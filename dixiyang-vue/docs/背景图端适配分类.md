# 背景图 / 封面图「端适配」分类（电脑端 vs 移动端）

> 版本：v1.1（追加功能落地） ｜ 日期：2026-10-16 ｜ 类型：🔍 资源盘点 + 裁剪数学分析（前端）+ ✅ 功能落地
> 一句话：背景是 `center/cover` 全视口铺满，**图片长宽比决定它属于桌面还是手机**——本页给出 22 张现有图片（上传背景 11 + 上传封面 4 + 内置背景 7）的逐张判定与选图规则；**v1.1 已把分类落成功能**（选择器按当前端排序 + 「电脑/手机」角标，见 §9）。

## 1. 需求（用户原话）

> 我希望分一下类，简单看一下上传的图像适合电脑端还是移动端的分类

## 2. 判定标准（裁剪数学，不是"看着像"）

**渲染方式**（`dixiyang-vue/Dixiyang-vue3/src/composables/useBackgroundConfig.ts:146`）：

```
background: linear-gradient(遮罩), url('...') center/cover no-repeat fixed;  /* #theme-bg: fixed; inset: 0 */
```

即图片等比放大到**铺满整个视口**，多余部分裁掉、四周不留白。

**两端视口形状**：桌面 ≈ 16:9（1.78，考虑浏览器 UI 实际约 2.0）；手机 ≈ 9:19.5（0.46）。

**可见比例公式**（A = 图片宽高比）：

| 场景 | 可见比例 |
|---|---|
| 桌面，A < 1.78 | 竖直只剩中间 **A/1.78** |
| 桌面，A ≥ 1.78 | 横向只剩中间 **1.78/A** |
| 手机，A ≥ 0.46 | 横向只剩中间 **0.46/A** |

**分辨率门槛**：手机 375 宽 @2x ≈ **750px** 起够；桌面 1920×1080 需 **≥1920px** 宽，不足会被放大发虚。

**分类表**：

| 宽高比 A | 桌面 | 手机 | 归类 |
|---|---|---|---|
| ≥ 1.78（16:9 及更宽） | 几乎不裁 | 只留中间 ≈1/4 | **桌面优先** |
| 1.6 ~ 1.78 | 上下微裁 | 中间 26~29% | **桌面优先** |
| 1.2 ~ 1.6 | 上下裁 10~25% | 中间 29~38% | **通用**（主体需居中） |
| 0.8 ~ 1.2（近方） | 上下裁 33~55% | 中间 38~58% | **通用偏手机** |
| ≤ 0.8（竖幅） | 上下裁掉 55%+ | 横向保留 58~100% | **移动优先** |

## 4. 选图规则（以后加图照这个来）

| 目标 | 推荐尺寸 | 备注 |
|---|---|---|
| **两端通用** | 3:2 ~ 16:10（A 1.5~1.6），长边 ≥1920 | 主体必须居中（两端都会裁上下/左右） |
| **只给手机** | 9:16 ~ 9:20（A 0.5~0.6），宽 ≥1080 | 竖构图人像/立绘最佳，手机几乎全见 |
| **只给桌面** | 16:9 及更宽（A ≥ 1.78），宽 ≥1920 | 横景/大场景最佳 |
| **小说封面** | 2:3 竖版（如 800×1200） | 方图可接受（裁左右 33%），横图别当封面 |

**两个易踩的坑**：
1. **"手机上够清"≠"桌面上够清"**：手机只需 750px 长边，桌面要 1920px；1200 宽的图在手机上很清晰，桌面全屏会发虚。
2. **主体靠边的图不能跨端用**：跨端裁剪只保留中心区域（横图给手机只留中间 1/4），主体偏左/偏右的图两端只能保一个（如内置 `1763874302372` 两个主体分居左右 → 手机上都不完整）。

## 9. 功能落地（v1.1：选择器分端排序 + 角标）

### 9.1 形态

- **单网格**（不新增标题行、不撑高，手机浮层仍可滚）：网格顺序 = **当前端对应组 → 通用 → 另一端**，组内保持原顺序（内置图在前、自定义图在后）；
- **角标**：只给明确适合某一端的图打「电脑」/「手机」小胶囊（卡片**左上**，右上已被自定义背景的删除按钮占用）；通用/尺寸未知不打标，靠 `title` 说明；
- 「不使用背景 / 上传背景」两张**功能卡仍固定钉在列表末尾**；
- **当前端判定 = 视口长宽比**（`innerHeight > innerWidth` 判为手机口径），监听 `resize`/`orientationchange` 实时重排——比 768 断点更贴合"图会被怎么裁"（桌面窄窗口同样是"手机形状"的裁剪）；
- 尺寸来源：**从已渲染缩略图的 `@load` 读 `naturalWidth/Height`**，零额外网络请求（内置图/服务端图都不重复下载）。

### 9.2 判定口径（常量集中在 `src/utils/bgFit.ts`）

| 常量 | 值 | 含义 |
|---|---|---|
| `BG_FIT_MOBILE_MAX_ASPECT` | 0.8 | 竖图宽高比上限（更竖才算手机） |
| `BG_FIT_MOBILE_MIN_LONG_SIDE` | 750 | 手机 375 宽 @2x 的清晰度门槛 |
| `BG_FIT_DESKTOP_MIN_ASPECT` | 1.6 | 横图宽高比下限（16:10） |
| `BG_FIT_DESKTOP_MIN_LONG_SIDE` | 1920 | 1080p 清晰度门槛；不到则**降级为「通用」**（桌面放大发虚） |

尺寸未知/非法 → `null`（按通用处理，不打角标）。
