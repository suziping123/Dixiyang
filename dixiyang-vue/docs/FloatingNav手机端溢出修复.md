# FloatingNav 手机端「设置」按钮溢出修复

> 版本：v1.0 ｜ 日期：2026-10-16 ｜ 类型：🐛 移动端 Bug 修复（前端）
> 关联：[背景图端适配分类](./背景图端适配分类.md)（同批验证）

## 1. 需求（用户原话）

> 还发现 floatingnav 在手机端 settings 按钮溢出了

即：FAB（悬浮球）展开后的**横条导航**里，末尾的「设置」按钮**挤出胶囊右缘**、压在悬浮球上/露在背景之外。

## 2. 根因（CDP 取证，非推断）

探针：headless Chrome（9222）→ 375/360/320 真机视口 → 展开悬浮球 → 量 `scrollWidth/clientWidth` 与首末条目相对胶囊的位移。

| 场景 | 胶囊 clientW | 内容 scrollW | 末条目右溢出 | 结论 |
|---|---|---|---|---|
| 375 + 5 项（普通用户） | 289 | 289 | −18（在内） | ✅ 恰好放得下 |
| **375 + 6 项（admin 多一个「管理后台」）** | 289 | **314** | **+34px** | ❌ 设置被挤出、压到球上（球 left=315 / 胶囊 right=307） |
| 360 + 6 项 | 274 | 314 | **+49px** | ❌ 更严重 |
| 320 + 5 项 | 234 | 262 | **+37px** | ❌ 旧机型即使用户也溢出 |

**一句话根因**：FAB 横条的条目是 **`flex-shrink: 0` 的固定 44px**，而容器只有 `max-width: calc(100vw - 82px)`（*只限容器、不限内容*）。条目数 6（admin）或视口 ≤360 时，内容比容器宽 → flex 行内条目**溢出到胶囊之外**（`overflow: visible`），末位「设置」正好落在悬浮球区域。

> 桌面 100px 竖栏不受影响：竖排不参与该宽度竞争；本 bug 仅 FAB 横条形态。

## 3. 方案

让条目宽度**按「条目数 + 视口宽」自适应收缩**，并给极窄屏一个换行兜底（保持胶囊观感与 44px 高度触控目标）：

```vue
<!-- template：把条目数注入 CSS 变量 -->
<nav class="floating-nav" :style="{ '--nav-count': navItems.length }" ... >
```

```css
/* FAB 横条：容器变量 */
.floating-nav { --nav-gap: 8px; --nav-pad: 10px; padding: 8px var(--nav-pad); gap: var(--nav-gap); }

/* 条目宽度 = 可用宽 / 条目数，clamp 到 [32px, 44px] */
.nav-item {
  width: clamp(
    32px,
    calc((100vw - 82px - env(safe-area-inset-right, 0px) - 2 * var(--nav-pad) - (var(--nav-count, 5) - 1) * var(--nav-gap)) / var(--nav-count, 5)),
    44px
  );
  height: 44px;   /* 高度保持 44px 触控目标 */
  flex-shrink: 0;
}

/* 极窄屏（≤344px）：单行放不下 → 3 列纵向面板（不缩到 32px 以下难看） */
@media (max-width: 344px) {
  .floating-nav {
    flex-wrap: wrap;
    justify-content: center;
    width: min(calc(100vw - 82px - env(safe-area-inset-right, 0px)), 156px);
    border-radius: 20px;
  }
}
```

**设计取舍与利弊**

| 方案 | 取舍 |
|---|---|
| ✅ **条目自适应收缩（已采用）** | 保持原胶囊形态与动效；375 下 6 项 = 38.8px、360 = 36.3px（图标 20px 仍清晰）；不溢出、不压球、无横向滚动 |
| ✅ **≤344px 换行成 3 列面板** | 旧机型（320）用 32px 宽条目会太挤 → 换成 3×2 面板，条目回到 44×44 触控目标，宽度 156px 绝不出屏 |
| ❌ 加 `overflow-x: auto` 让胶囊横滚 | 导航横滚反直觉（用户找不到末项），且会裁掉条目入场位移 |
| ❌ 缩小条目数（删「管理后台」入口） | 改产品信息架构，与本 bug 无关 |
| ❌ 只把 `max-width` 调大 | 治标：内容本身没变小，超窄屏照样溢出（320 实测已溢出） |

## 4. 改动文件

| 文件 | 改动 |
|---|---|
| `dixiyang-vue/Dixiyang-vue3/src/components/FloatingNav.vue` | ① `<nav>` 注入 `--nav-count`（= 条目数）；② FAB 横条提取 `--nav-gap/--nav-pad` 变量；③ `.nav-item` 宽度改 `clamp(32px, 可用宽/条目数, 44px)`；④ 新增 `@media (max-width: 344px)` 换行兜底 |

无逻辑/接口改动；桌面（>1024px 且非触屏）竖栏形态不受影响（实测条目仍为 44px）。

## 5. 验证（CDP，修复后）

| # | 用例 | 修复前 | 修复后 |
|---|---|---|---|
| 1 | 375 + 6 项（admin）：内容不溢出 | ❌ `314 > 289`、右溢出 +34px | ✅ `overflow=0`、末条目内侧 6px、条目宽 38.8px |
| 2 | 375：胶囊在视口内 + 页面无横向滚动 | — | ✅ `left=16 / right=307 ≤ 375`、`scrollWidth=375` |
| 3 | 375：与悬浮球不重叠 | ❌ 压球（溢出错位） | ✅ 间隙 8px |
| 4 | 360 + 6 项 | ❌ 右溢出 +49px | ✅ `overflow=0`、条目宽 36.3px、单行 |
| 5 | 320 + 6 项 | ❌ 溢出（单行放不下） | ✅ 自动换行 3 列（`rows=2`、胶囊 156×114）、`overflow=0`、不压球 |
| 6 | 375 + 5 项（普通用户）：未误伤 | ✅ 原样 | ✅ 条目仍 44px、`overflow=0` |
| 7 | 1440 桌面：回到左侧竖栏 | ✅ | ✅ 无 FAB、条目 44px |
| 8 | 控制台错误 | — | ✅ 0 |
| 9 | 375 / 320 截图肉眼复核 | — | ✅ 6 个图标全在胶囊内、「设置」不再压球；320 为 3×2 面板 |

**汇总：14/14 PASS**（判据用 `scrollWidth ≤ clientWidth` + 首末条目落在胶囊边框内 + 不压球 + 视口无横向滚动；首轮脚本因断言未计 1px 边框得出 `rightSpill=3` 的误报，已用修正判据复测为 0）。

## 6. 已知问题 / 副作用

1. **≤344px 的形态变化**：320 宽旧机型上胶囊变 3×2 圆角面板（非胶囊），这是刻意的兜底降级；360 及以上仍是单行胶囊。
2. **条目宽度下限 32px**：375 下 6 项为 38.8px、360 为 36.3px（宽高比略窄于 1:1，图标 20px 居中不裁），触控高度仍 44px。
3. **探针副作用**：验证时临时把 `localStorage.role` 置为 `admin` 以复现 6 项（admin）导航，**已复原为 `user`**；探针用测试账号 `admin123` 真实登录态，未写入后端数据；探针标签已关闭。
4. **未覆盖**：桌面竖栏在**极矮窗口**（高度 < 400px）下的纵向溢出（本次未报，未处理）。
