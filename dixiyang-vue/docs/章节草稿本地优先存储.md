# 章节草稿本地优先存储（Local First）

## 需求

小说章节编辑器采用「本地优先」策略：内容先落本地 IndexedDB，再异步同步云端。

- 断网 / 云端接口不可用时，用户编辑不丢失、不阻塞
- 编辑过程中 800ms 防抖自动本地保存，切章节 / 关页前立即落盘
- 本地草稿与云端版本（version + hash）关联，云端保存成功后清除脏标记

## 方案

### 1. `src/utils/draftDB.ts` — IndexedDB 封装（原生 API，零依赖）

| 项 | 值 |
|----|----|
| 数据库 | `dixiyang-drafts` |
| 版本 | `1` |
| store | `chapters`，`keyPath: 'chapterId'` |
| 索引 | `novelId`（`unique: false`，在 `onupgradeneeded` 创建） |

导出：

```ts
interface ChapterDraft { chapterId, novelId, title, content, updatedAt, serverVersion, serverHash, wordCount, isDirty }
openDraftDB(): Promise<IDBDatabase>          // 单例缓存（dbPromise）
putDraft(draft): Promise<void>               // upsert（put）
getDraft(chapterId): Promise<ChapterDraft | null>   // 永不 reject
deleteDraft(chapterId): Promise<void>
listDraftsByNovel(novelId): Promise<ChapterDraft[]> // index.getAll 走 novelId 索引
clearDirtyByChapter(chapterId): Promise<void>       // 同事务 get → put，isDirty=false
```

关键实现：

- **单例**：`dbPromise` 模块级缓存；`onversionchange` 时 `close()` 并置空，允许其他标签页升级后重开。
- **打开三态**：`onsuccess` / `onerror` / `onblocked` 用 `settled` 标志防重复回调；blocked 直接 reject（避免永久挂起）。
- **不支持 IDB 降级**：`indexedDB` 缺失或 open 失败 → `memoryMode = true`，全部操作转内存 `Map<number, ChapterDraft>`；同会话草稿仍可用，**编辑器绝不崩溃**。
- **错误策略**：读类失败静默返回 `null` / `[]`（`getDraft` 保证不抛）；写类失败上抛，由调用方决定（`useChapterDraft` 置 `saveState='error'`）。dev 环境才 `console.warn`。
- **事务完成以 `oncomplete` 为准**（`txDone`），保证真正落盘。

### 2. `src/composables/useChapterDraft.ts` — 草稿读写 + 防抖

```ts
type SaveLocalState = 'idle' | 'saving' | 'saved' | 'error'
interface DraftSaveInput { chapterId, novelId, title, content }  // server 字段由 composable 合并

useChapterDraft() => {
  saveState,                                                   // Ref<SaveLocalState>
  loadDraft(novelId, chapterId, serverContent, serverVersion, serverHash),
  scheduleSave(draft),                                         // 防抖 800ms
  flushSave(),                                                 // 立即落盘
  markSynced(chapterId, version, hash),                        // 云端保存成功后
  wordCount(content),
  dispose(),                                                   // 清定时器 + 尽力落盘
}
```

关键实现：

- **loadDraft 本地优先**：先 `await flushSave()`（把上一章节的 pending 落盘，避免被新章节上下文覆盖）→ 读本地；有则 `{ content: local.content, fromLocal: true, isDirty }`；无则用云端内容初始化本地记录（`isDirty: false`）并返回 `fromLocal: false`。
- **scheduleSave**：只接收 4 个业务字段，写入时由 `syncCtx`（当前章节的 serverVersion/serverHash）组装完整 `ChapterDraft`，`isDirty: true`、`wordCount` 实时计算；状态 `saving` → 写成功 `saved` / 失败 `error`（失败保留 pending，`flushSave` 可重试）。
- **flushSave**：清定时器后立即 `commitPending()`；页面关闭 / 切章节前调用。
- **markSynced**：更新 `syncCtx` + 读回草稿写 `serverVersion/serverHash/isDirty=false`。
- **dispose**：清定时器并 `void commitPending()` 尽力保存；`getCurrentScope()` 存在时自动注册 `onScopeDispose`，组件卸载无须手动调。
- **wordCount**：`content.replace(/\s+/g, '').length`（中文按字符，去全部空白）。

## 典型调用时序

```
进入章节: loadDraft(...)           → 本地有则用本地，无则初始化
编辑中:   scheduleSave({4字段})    → 800ms 防抖写 IDB，state: saving→saved
云端成功: markSynced(id, ver, hash)→ server 字段更新、isDirty=false
切章/关闭: await flushSave()       → 立即落盘
卸载:     dispose()（自动 onScopeDispose）→ 清定时器 + 尽力保存
```

## 已知问题 / 取舍

1. **本地优先不处理服务端冲突**：若本地 dirty 期间云端在别处被改，`loadDraft` 仍返回本地内容（按需求「优先本地」）；冲突检测需后端 `ConflictResult` 参与，另行接入。
2. **内存降级不跨刷新**：IDB 不可用时草稿仅存活于当前会话，刷新即失（可接受的降级）。
3. **`loadDraft` 初始化的 `title` 为 `''`**：签名不含 title，首次以云端内容建档时无标题，后续 `scheduleSave` 会带入真实标题。
4. `commitPending` 失败会把 pending 放回，等待下一次 `scheduleSave` / `flushSave` 重试，极端情况下（持续写失败）内存中的 pending 不会无限增长（单坑位）。

手工验收（浏览器 DevTools）：

1. Application → IndexedDB → `dixiyang-drafts/chapters` 可见记录，`novelId` 索引存在
2. 编辑正文停手 800ms 后记录 `updatedAt` 更新、`isDirty=true`
3. DevTools 设 Offline 后编辑：无报错，草稿照常写入（IDB 本地不依赖网络）
4. 切换章节 / 刷新页面：上一章未手动保存的内容仍在（`fromLocal=true`）
5. 控制台 `indexedDB.databases()` 或临时改名 DB 验证内存降级路径不抛错
