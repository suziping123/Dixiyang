# 404 页被背景图覆盖修复

- **需求**: 访问未匹配路由时，`NotFoundView`（404 页）应显示自带的亮纸底，而不是被全局背景图整层盖掉。
- **日期**: 2026-09-30

## 根因

背景图不是 body 背景，而是 `useBackgroundConfig.ts:135-147` 动态插入的 `#theme-bg`：
`position: fixed; inset: 0; z-index: 0`，插为 **body 首个子节点**（与 `#app` 平级）。

层叠顺序（同一 stacking context）：

| 元素 | 定位 | 绘制步骤 | DOM 序 |
|------|------|---------|--------|
| `.ld-404`（亮纸底+文字） | 非定位 static | 步骤 3（块背景）/ 5（行内） | `#app` 内，靠后 |
| `#theme-bg` | fixed + z-index:0 | 步骤 6（定位后代） | body 首子，靠前 |

→ 非定位内容先画、定位层后画，404 底色和文字整体被背景图压住。

其它页面正常是因为根容器都有 `position: relative`（z-index auto，同属步骤 6），DOM 序在 `#theme-bg` 之后：
`.ld-page`（landing-base.css:17）、`.engine-container`（HomeView）、`.auth-container`（LoginView）。
**全站唯独 `.ld-404` 没有 position/z-index。**

次要因素：404 页无 `.ld-page` 容器，`html:has(.ld-page)` 的亮纸底切换不生效，html/body 仍是暗色底。

## 方案

两处 CSS 改动，零 JS：

1. `.ld-404` 补 `position: relative` —— 升为定位元素，DOM 序在 `#theme-bg` 之后，亮纸底与文字画到背景图之上。
2. `html:has(.ld-page)` 的亮纸底规则扩展为同时匹配 `html:has(.ld-404)` —— html/body 同步翻成亮纸，消除暗底露边（含 overscroll 情况）。

## 改动文件

| 文件 | 改动 |
|------|------|
| `Dixiyang-vue3/src/styles/landing/landing-sections.css:701` | `.ld-404` 加 `position: relative` + 注释 |
| `Dixiyang-vue3/src/styles/landing/landing-base.css:7-17` | 亮纸底/`color-scheme`/滚动条规则选择器加 `html:has(.ld-404)` |

1. `npm run build-only` —— 通过（✓ built in 7.46s）。
2. 手动：`npm run dev` → 设置任一背景图 → 访问 `http://localhost:5173/不存在的路径` → 页面应为亮纸底 + 404 文案，不出现背景图。
3. 对比：落地页 `/`、`/home`、`/login` 表现不变。
