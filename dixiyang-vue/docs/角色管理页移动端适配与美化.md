# 角色管理页移动端适配与美化

> 版本：v1.0 ｜ 日期：2026-09-29 ｜ 断点：`≤1024` / `≤768` / `≤480`（沿用项目既有档位）
> 前置：[移动端响应式修复](./移动端响应式修复.md)（v1.0 已修居中、字号降档、弹窗 `width=min()`）
> 范围：**仅** `src/views/CharacterManagerView.vue` 的模板与样式，零 JS 逻辑/接口/路由改动

## 需求

1. 角色管理页移动端「太大了」——单列全宽巨卡（单卡 ≈266px），一屏只能看 1.5 个角色。
2. **不影响显示内容**：性别/年龄/「📋 有设定」标签、外貌或背景描述、编辑/删除按钮**一项不减**。
3. 整体美化，并与项目设计 token（圆角/语义色/动效时长）对齐。

## 现状根因

| # | 症状 | 根因 |
|---|------|------|
| 1 | 手机上卡片巨大 | `≤768` 只有 `grid-template-columns: 1fr`（单列全宽）+ `padding:16px`；头像 48px、描述 2 行、按钮整行 → 单卡 ≈266px |
| 2 | 缺超窄档 | 只有 `≤1024`、`≤768` 两档，320px 屏（SE）无任何专门处理 |
| 3 | 观感不统一 | 卡片圆角 16px，而 `main.css` 规定只有 `--radius-sm:8px` / `--radius-md:12px` 两档 |
| 4 | 硬编码色值 | `rgba(59,130,246,.2)`（蓝）、`#ef4444`（红）、`rgba(168,85,247,.2)`（紫）与 `--accent-soft/--danger-soft/--accent-purple` token 重复定义 |
| 5 | 手机上输入框会触发 iOS 聚焦缩放 | 全局 `html { font-size: calc(... × --viewport-font) }` 在 ≤768 为 0.8125、≤480 为 0.75 → 实际字号 ≈12px（<16px） |
| 6 | 触屏「点一下跳一下」 | `.character-card:hover { transform: translateY(-5px) }` 在触屏 sticky hover 下会持续生效 |
| 7 | 死元素 | 模板里的 `.bg-gradient-animation` 在本组件**无样式定义**（该规则只存在于 `HomeView.vue` 的 scoped 样式），属无效装饰 div |

## 方案（全部 CSS；模板仅 2 处小改）

### 一、移动端骨架：单列 → 双列自适应

```css
@media (max-width: 768px) {
  .character-grid {
    grid-template-columns: repeat(auto-fill, minmax(150px, 1fr));
    gap: 12px;
  }
}
```

关键点：用 `auto-fill` + `minmax(150px, 1fr)` **一次规则覆盖全部窄屏**——
375px 屏自动两列（每卡 ≈166px），320px 屏自动降单列，无需为 360px 再插一个断点。
平板档同步把 `minmax(280px)` 降到 `240px`（1024 屏原本会挤出 4 列窄卡）。

### 二、单卡瘦身（信息一项不减，266px → 约 205px，−23%）

| 元素 | 桌面 | ≤768 | 缩放 |
|------|------|------|------|
| `.glass-card` padding | `24px` | `12px 10px` | 内边距减半 |
| `.character-avatar` | 60×60 | 40×40 | −33% |
| `.avatar-text` | 1.5rem | 1rem | −33% |
| `.character-name` | 1.25rem | 0.95rem | −24% |
| `.info-tag` | 0.85rem / 12px 圆角 | 0.7rem / 999px 胶囊 | 更紧凑 |
| `.character-desc` | 0.9rem | 0.78rem + `min-height: 2.32em` | 固定两行，同排按钮对齐 |
| `.action-btn` | `8px 12px` / 0.9rem / 16px icon | `7px 4px` / 0.78rem / 14px icon | 按钮不再撑高卡片 |
| `.create-card` | `min-height: 280px` | `min-height: 0` + `padding:16px 10px` | 随行高对齐 |

### 三、移动端专属修复

- **触屏手感**：`.character-card:hover { transform: none }` + `:active { scale(0.985) }`，消除 sticky hover 位移。
- **输入框字号**：`.el-input__inner / .el-textarea__inner { font-size: 16px }`，**防 iOS 聚焦自动放大整页**。
- **长表单弹窗 → 底部抽屉**（仅 `.character-dialog:not(.delete-dialog)`）：
  `width:100% !important` + `margin: auto auto 0 !important`（抵消 EP 默认 `15vh` 顶边距）+ 上圆角 + `max-height:88vh` + `__body` 内部滚动 → 底部取消/保存常驻。
- **删除确认框**保持居中短弹窗（新增 `.delete-dialog` 类排除抽屉规则）。
- **≤480 超窄档**：`main-stage` 收到 `28px 12px 20px`、卡片间距 10px、`novel-cover-thumb` 40px、关掉 `.card-border-gradient`（148px 卡上 1px 渐变描边收益低于合成开销）。

### 四、美化（桌面 + 移动共用）

| 项 | 改动 |
|----|------|
| 圆角 | 卡片/描边统一 `var(--radius-md)`(12px)、按钮 `var(--radius-sm)`(8px)，落到全局两档规范 |
| 语义色 | `info-tag` → `--accent-soft/--accent-soft-strong`；`settings-tag` → `--accent-purple`；删除按钮 → `--danger-soft/--danger/--danger-border` |
| 动效 | 统一 `var(--dur)`/`var(--dur-fast)` + `var(--ease-out)`，替换各处 `all .3s ease` 与 `cubic-bezier(.34,1.56,.64,1)` |
| 头像 | 加 `inset 0 0 0 1px rgba(255,255,255,.16)` 内描边 + 底部微光，不再是实心圆 |
| 标签行 | `flex-wrap: wrap` + `tabular-nums`，三枚标签满屏时不挤压 |
| 名字 | `overflow-wrap: anywhere` + `line-height:1.3`，超长名不溢出 |
| 卡片入场 | `@keyframes cardIn`（上浮 10px 淡入）+ `animation-delay: calc(var(--i,0) * 40ms)`，**最多错峰 8 张**（内联 `--i` 只给卡片壳，靠继承下发，不落到表单控件） |
| 幽灵卡 | `.create-card` 改虚线描边，hover 转实线 + 加号图标旋转 90° |
| 悬停 | 卡片 `translateY(-4px)` + `var(--shadow-card)`；按钮按下 `scale(.97)`、图标 `scale(1.08)` |

## 已知问题

- **（v1.1/v1.2 已修复）** 初版给 `.character-card-wrapper` 加的 transform 入场动画、以及弹窗覆盖规则，均已在后续轮次处理；卡片"全透明"与弹窗"全黑"的**真正根因**是底板透明度过低（`--glass-bg` = 5% 白，`backdrop-filter` 不提供底色）与全局 `.el-dialog{…!important}`，详见 [卡片毛玻璃底板与弹窗配色修复](./卡片毛玻璃底板与弹窗配色修复.md)。
- **自动截图验证不可用**：命令行 `chrome --headless --screenshot` 在本机沙箱被拒（`mojo platform_channel: 拒绝访问`，命名管道策略限制，与代码无关），故本轮为**静态检查 + 人工 DevTools 验证**；后续如需自动截图需单独授权运行该命令。
- `.bg-gradient-animation` 仍是**无样式死元素**（本组件内无规则），本次未删 DOM（避免动模板结构），仅未对其做任何处理。
- `bgConfig = useBackgroundConfig()` 是**既有 eslint 违规**（`no-unused-vars`，`src/views/CharacterManagerView.vue:194`），属早前遗留，本次未清理（清理需动 JS）。
- 时间线页（`TimelineView.vue`）仍是 `grid-template-columns: 1fr` 单列卡片 + `max-width:1100px` 无居中容器，手机观感同样偏大，**本次未动**，建议按本方案同法处理。
- 320px 屏因 `minmax(150px,1fr)` 自动降单列（每卡 ≈238px），属预期行为而非缺陷。
