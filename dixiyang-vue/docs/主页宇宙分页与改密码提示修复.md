# 主页宇宙分页与改密码提示修复

- **日期**: 2026-10-07
- **需求**: ① 主页宇宙数量到 10 个后不再增加（第 11 个"消失"）；② 设置页改密码"有时能用有时不能"
- **环境**: Python 后端 `DixyangFast`（FastAPI，:8084）+ Vue3 前端（vite :5173 → 代理 /api → :8084）

## 根因

### 问题 1：主页 10 个上限（双重叠加）

| # | 位置 | 问题 |
|---|------|------|
| 1 | `HomeView.vue` fetchNovels | 硬编码 `{ page: 1, pageSize: 10 }`，**只拉第一页**，第 11 条起永远不可见 |
| 2 | 同上 | 参数名 `pageSize`（驼峰）与 FastAPI 路由 `page_size`（蛇形，`routers/novel.py:11`）不匹配 → **被框架忽略，恒用默认 10** |
| 3 | Hero/分节计数 | `novels.length`（=已加载数，封顶 10）当总数显示 → 宇宙数永远显示 10，创建后不涨 |

API 实证：
```
GET /novel/listall?page=1&pageSize=5  -> records=10 total=12  (参数被忽略)
GET /novel/listall?page=2&page_size=5 -> records=5  total=12  (参数生效)
```

### 问题 2：改密码按钮点击无反应（主根因）+ 报错文案被吞（次根因）

后端 `/user/password` **无问题**：用测试账号连续 6 次新旧密码往返修改全部成功（6/6），错密码/同密码均正确拒绝。

**主根因（用户反馈「点击压根没反应、没有任何提示」）**：

```html
<form class="pwd-form" @submit.prevent @keyup.enter="enterSubmit(changePassword, $event)">
  ...
  <button type="submit">修改密码</button>   <!-- 无 @click -->
```

- `@submit.prevent` **没有绑定任何表达式**（空处理器）→ 点击 `type="submit"` 按钮 → 触发 submit → 被 prevent 且无逻辑 → **`changePassword` 根本不会被调用**，连字段校验都不跑 → 零请求、零红字、零 toast
- 唯一能触发的路径是**末框回车**（keyup.enter → enterSubmit）→ 完美解释「有时能用有时不能」
- 对照正确写法：`CreateCard.vue:25` `@submit.prevent="submitForm"`（有处理器），故创建宇宙按钮正常

**次根因（回车路径触发后的报错文案误导）**：`errorText.ts` 关键词规则 `[/密码|password/i, '账号或密码不正确']` 把后端「当前密码不正确」「新密码不能与当前密码相同」全吞成登录页文案「账号或密码不正确」，用户在设置页看到莫名文案以为功能坏了。
（EXACT 精确匹配优先于 KEYWORDS，故补进精确表即可，不动关键词规则。）

## 修复方案

### 主页分页（HomeView.vue）
1. 参数改为 `page_size`（对齐 FastAPI 蛇形命名）
2. 分页状态：`page` / `total` / `loadingMore` / `hasMore`，新增「加载更多」胶囊按钮（`已加载 x / total`），追加模式追加记录
3. 所有总数展示（subtitle、Hero 宇宙大数字、分节计数徽章）`novels.length` → 后端 `total`（真实总数，创建后立即 +1）
4. 追加失败回退 `page`（防跳页）；追加模式不重播全列表入场动画，仅重启悬浮
5. 删除本地移除时同步 `total--`；`@create-success` 改箭头函数（防将来 emit 带参数污染 append 参数）

### 改密码（AccountSection.vue + errorText.ts）
1. **按钮脱离空 submit 路径**：`type="submit"` → `type="button"` + `@click="changePassword"`（点击直达提交逻辑；回车仍走 keyup.enter → enterSubmit 的跳框/末框提交约定，不受影响）
2. `changePassword` 开头加 `if (pwdLoading.value) return` 防重入（连点/回车双触发）
3. EXACT 精确表补 4 条改密码业务原文（`当前密码不正确` / `新密码不能与当前密码相同` / `新密码至少 6 位` / `参数不完整`→`请填写完整后再提交`），精确匹配优先 → 用户看到后端真实提示
4. 按钮文案「保存信息」→「修改密码」（消除歧义）

## 第二轮：删除×分页对齐与触底自动加载

用户反馈第一版「加载更多」逻辑不对：**删除多了之后点击没反应、不符合逻辑、各端无优化**。

### 新增根因

| # | 问题 | 机制 |
|---|------|------|
| 1 | 删除后点加载更多永远空转 | 删除只在本地 `filter + total--`（估算），服务端数据缩水但客户端 `page` 停在旧位置 → `offset` 超出服务端总数 → 返回**空页**；空页算"成功"不回退、`total` 不收敛 → 按钮还在、点击无效（例：10 条删 2 → `8/9` 按钮凭空出现 → page=2 offset=10 > 9 条 → 永远空） |
| 2 | 多页数据空洞 | 服务端删除后条目前移，客户端已加载集合 ≠ 服务端前 N 页 → 下一页 offset 跳过中间条目，**部分宇宙永远加载不到** |
| 3 | 各端零适配 | 无触底自动加载（移动端主流）、按钮触摸目标 <44px、追加失败静默无重试 |

### 方案（用户确认：触底自动+按钮双轨、删除后对齐重拉）

1. **`realignList()` 对齐重拉**（带 `withListLock` 列表互斥锁）：按已加载条数算 `pages = max(1, ceil(loaded/10))`，`Promise.all` 并行拉服务端第 1..pages 页**覆盖**本地 → 本地严格 = 服务端前 N 页，`page` 归位、`total` 取响应权威值 → `hasMore` 自然收敛（10 条删 2 → 按钮正确消失；20 条删 12 → 补位后可继续正确加载）
2. **删除改 async/await**：服务端删除成功才动本地，随后 `await realignList()`；请求失败列表不动
3. **空页兜底**：`fetchNovels` 返回本次写入条数，`loadMore` 发现追加 0 条但 `hasMore` 仍 true → 自动改走 `realignImpl()` 恢复一致（彻底杜绝"点了没反应"）
4. **触底自动加载**：网格底部 1px 哨兵 + `IntersectionObserver`（`rootMargin: 200px` 提前预载），`watch(hasMore)` 驱动挂/卸，`onBeforeUnmount` disconnect；与按钮共用 `loadingMore`/`hasMore` 守卫，且两者经 `withListLock` 互斥
5. **失败可见**：追加连续失败 → `loadError` → 按钮变警示色「加载失败，点击重试」
6. **移动端**（≤768px）：按钮 `min-height: 44px`（触摸目标）、字号 0.9rem、间距收紧

## 已知问题

- **角色/节点 Hero 汇总**（`charTotal`/`nodeTotal`）只覆盖**已加载**的宇宙，加载更多后数字增长——如需全量需后端加聚合接口，暂不杜撰（沿用 design-slop A8 原则）。
- **登录风控**：10 分钟内成功登录 ≥3 次会锁密码登录（`auth_service.py` `RISK_LOGIN_LIMIT`，提示「登录过于频繁，请使用邮箱验证码登录」），10 分钟后自动恢复——测试时注意。
- **测试账号残留**：验证过程注册了 `codex_pwd_t1`、`codex_pg_t2`（密码均 `Test123456`，无删除用户接口），可忽略或后续清理。
- **单点登录踢号**：后端每次登录轮换 `session_id`（`auth_deps.py:30`），另一设备/浏览器登录会把当前 token 顶掉 → 401 → 前端跳登录页。多端同时使用时"改密码突然跳登录"属此设计，非 bug。
- **账号 111 不存在于 py 后端 DB**（登录报「用户名不存在」），用户实际使用账号待确认。

手工清单：

2. 列表超过 10 个 → 底部出现「加载更多（10 / N）」，点击追加且不丢已加载
