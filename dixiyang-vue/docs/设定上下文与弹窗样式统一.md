# 设定上下文与弹窗样式统一

- **日期**: 2026-10-07
- **状态**: 已完成
- **涉及模块**: 小说编辑页设定上下文面板、全局 ElMessageBox、小说编辑页 5 处弹窗改用 el-dialog

## 需求

用户反馈（`/novel-editor/:id` 页面）：

1. **设定上下文字体大、风格不符**：面板标题字号远大于周围面板，整体与侧栏风格不一致。
2. **启用开关改形态**：「已启用/未启用」文字不要常驻按钮内，改用**颜色 + 按钮**表达状态，最多 hover 时显示当前状态。
3. **message-box 不像其他页面**：新建卷/新建章节/删除确认等所有 `ElMessageBox` 弹窗仍是原生观感，且**标题看不清（颜色对比度太低）**；参照时间线页 `.btn-icon` 的样式统一。

## 方案

### 1. 设定上下文面板（`AIContextPanel.vue`）

| 问题 | 根因 | 修法 |
|------|------|------|
| 标题 30px 过大 | `.ctx-head .panel-title` 只设了 `margin` 未设字号 → 落到全局 `main.css` 的 `h3 { font-size: 1.875rem }`；`ChapterSidebar` 的 `.panel-title`（0.78rem）是 scoped 样式，跨不到本组件 | 补齐同款标题样式：`0.78rem / 700 / letter-spacing 1px / var(--text-secondary)` |
| 风格不符 | `.ctx-panel` 是**卡中卡**（外层「AI 补全」panel 已有卡片底，内层再套一层 `background + border`） | 去掉卡片底，改虚线顶部分隔 + 间距，融入外层平铺 section |
| 启用开关 | pill 内常驻文字「已启用/未启用」 | 改 **26px 纯色状态钮**（`radius 8`，对齐 `.btn-icon` 几何）：关=玻璃灰底+暗点，开=主色亮底+发光蓝点；状态文字仅在 `title`（hover）与 `aria-label`（读屏）显示 |

### 2. 全局 ElMessageBox（`main.css`，全站生效）

- **标题对比度根因**：`.el-message-box` 底色是 `--surface-glass` = `rgba(255,255,255,0.05)` 半透明玻璃，在编辑页亮背景上糊成一片亮，白字标题（#eeeeee）对比度崩掉。`el-dialog` 早已改用不透明 `--surface-dialog: #222530`（同文件注释记录过该教训），message-box 却没跟上。
  - **修**：底色改 `var(--surface-dialog)`（#222530，白字对比度 15.3，不受背后页面明暗影响）。
- **按钮对齐时间线页 `.btn-icon` 视觉语言**（玻璃底 + 1px 玻璃边 + `radius 8` + hover 变主色）：
  - 取消钮：`--glass-bg` 底 + `--surface-glass-border` 边，hover 变主色边/字；
  - 主确认钮：由原 20% 半透明蓝改 **accent 实底白字**（深色弹窗上更清晰），hover 提亮；
  - **危险语义激活**：原 `.el-message-box.is-danger` 规则是**死规则**（EP 不会给盒子加 `is-danger` 类，已核实 EP 源码），从未生效。改用 `:has(.el-message-box__status.is-warning|is-error)` 关联状态图标 → 警告/错误弹窗的确认钮显示危险红（对齐 `.btn-icon.btn-danger`）；`confirmDelete` 与各页删除确认均传 `type: 'warning'`，正确命中。
  - 抵消 EP 相邻按钮 `margin-left`（容器已用 flex `gap` 控距）。
- **EP 导入顺序**：`main.ts` 中 `element-plus/dist/index.css` 在 `main.css` **之后**导入，同特异性后到者赢 → 颜色类规则一律 `!important`（项目既有惯例）。

### 影响面（全站可见）

所有 `ElMessageBox`（`confirm.ts`、各页新建/删除/离开确认）统一：半透明雾底 → 实底 #222530 深板，与 `el-dialog` 观感一致；确认按钮蓝实底、危险确认红字。属于「复用统一」方向的预期变化。

### 3. 小说编辑页 5 处 ElMessageBox 改用全局 el-dialog 模板

用户追问「el-dialog / character-dialog 不是已有模板，为什么不用」→ 核实：项目里**写好的是全局样式**（`html .el-dialog`，main.css:404，一次定义全站生效 + ≤768px 自动底部抽屉），`character-dialog` 是角色页 scoped 页面级样式，**没有现成的确认/输入弹窗组件**。当初用 `ElMessageBox` 是命令式一行最省事，且三态离开确认（`distinguishCancelAndClose`）只有它有。

**方案**：新建 Promise 化弹窗宿主组件，5 处调用换实现、调用风格保持 `await`，彻底复用全局 el-dialog：

| 原调用（ElMessageBox） | 新实现（DialogHost） |
|---|---|
| `prompt('卷名称', '新建卷')` ×2 | `dialogs.prompt({ title, message, defaultValue })` → `Promise<string \| null>`（取消/ESC=null，顺带修掉原取消时 Promise 未捕获 rejection） |
| `confirm(..., { type: 'warning' })` ×2 | `dialogs.confirm({ title, message, danger: true })` → `Promise<boolean>`，确认钮 `type="danger"`（与角色/时间线页删除确认一致） |
| `confirm(..., { distinguishCancelAndClose })` 路由离开 | `dialogs.confirmLeave(msg)` → `Promise<'save' \| 'leave' \| 'cancel'>`，三按钮：保存到云端 / 继续离开 / 取消(X、ESC) |

**收益**：样式自动吃 `html .el-dialog` 全局模板；移动端自动获得底部抽屉响应式（ElMessageBox 无此能力，一直居中小窗）；与时间线/角色页写法统一；ESC/X 关闭经 `@close` 兜底 resolve，不再产生 unhandled rejection。
**保留**：`main.css` 的 message-box 补丁不回退——`confirm.ts` 与其余页面仍用 `ElMessageBox`。

## 已知问题

- `:has()` 需现代浏览器（Chrome 105+ / Safari 15.4+）；不支持时危险确认钮降级为普通蓝色主钮（渐进增强）。
- message-box 是全站样式，其他页面（登录、设置、角色删除等）的弹窗外观同步变化。
- 仓库既有报错与本次无关：type-check 9 处、lint 8 处（清单见 `小说编辑器Tab禁用与段落视觉间距.md`）。

2. 面板无嵌套卡片框，虚线分隔融入侧栏；chips/全选清空正常。

6. 有未上传修改时离开：三按钮弹窗，保存到云端=保存后离开、继续离开=直接走、取消/ESC=留在页面。
