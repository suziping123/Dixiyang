# 表单内联校验与错误文案统一

> 版本：v1.1 ｜ 日期：2026-09-29 ｜ 范围：登录/注册、设置-账户、RAG 聊天、确认弹窗

## 需求

1. `AccountSection.vue` / `useAuth.ts` 像登录页那样**实时显示改错了哪个字段**（内联红字），而不是一闪而过的全局 toast。
2. 抽象**警告的通用模板**（字段级内联错误），替代散落的 `ElMessage.warning`。
3. **屏蔽后端原始错误**：不要让用户看到返回的报错信息（尤其 RAG 气泡）。
4. **美化"退出警告"那种确认弹窗**（`confirmDelete` / `ElMessageBox`）。

## 根因

| 症状 | 根因 |
|------|------|
| AccountSection 无实时定位 | 用原生 `input` + `SettingRow`，**未接 `el-form/rules`**，校验只在提交时跑，只能吐全局 toast |
| 登录页"半残" | `useAuth.rules` 只定义 `username/email/password`，**缺 `nickname`/`code`** → 这两个字段从不校验；且从不调 `el-form.validate()`，提交仍靠 18 处 `ElMessage.warning` 兜底 → `rules` 与手动校验**两套冗余** |
| 后端原文上屏 | ① `http.ts` 拦截器透传 `res.msg` → 各处 `ElMessage.error(apiRes.msg)`；② `useChatStream.ts:244/366` 直接 `抱歉，请求失败：${error.message}` 拼进聊天气泡 |
| 无通用警告模板 | 全项目无 `el-alert` / 自定义 Alert，37 处 `ElMessage.warning/error` 全是同一个 toast |
| "error 页面" | 全项目只有 `NotFoundView`（404 路由兜底），**无通用错误页** |

## 方案

### 一、新增 3 个文件（通用模板）

**1. `src/components/ui/FieldError.vue`** — 内联字段错误组件
```vue
<FieldError :message="errors.username" />
```
- `role="alert"` + `aria-live="polite"`（读屏播报）
- 文案为空不渲染、不占位；`<Transition>` 滑入/淡出，`prefers-reduced-motion` 下降级
- 红字 `--danger`、字号 `0.8125rem`（与 `SettingRow.desc` 同号）

**2. `src/composables/useFormValidation.ts`** — 轻量校验引擎
```ts
interface FieldRule { required?; pattern?; min?; message?; validator?(value, form) }
useFormValidation(rules, form) → { errors, validateField, validateAll, clearError, clearAll }
```
- `validateField(k)` 绑 `@blur`（单字段）；`validateAll(keys?)` 绑提交（可只查指定字段）
- `validator(value, form)` 拿到**整个 form** → 密码确认等跨字段规则在此实现
- 纯 `validator` 规则可省 `message`（错误由返回值给出，内置规则兜底 `'输入有误'`）

**3. `src/utils/errorText.ts`** — 错误文案映射
```ts
friendlyError(raw?, fallback = '操作失败，请稍后再试'): string
```
- 精确表 → 关键词表 → 兜底；**原始 `raw` 只进 `console.error`，永不上屏**

### 二、修改 7 个文件

| 文件 | 改动 |
|------|------|
| `LoginView.vue` | **拆 `el-form :rules` / `el-form-item` / `label-position`**，改原生 `<form class="auth-form">` + `.field` 容器；保留 `el-input`（prefix-icon）、`email-with-code`、GSAP、`enterSubmit`；每字段 `@blur` + `<FieldError>` |
| `useAuth.ts` | `rules` → `FieldRule` 格式，**补 `nickname`/`code` 缺失规则**；登录/注册各一个校验实例；**删 18 处 `ElMessage.warning`**；按 `loginMode` 只查当前模式字段；`error(apiRes.msg)` → `friendlyError()`；返回 `loginErrors/registerErrors/validateLoginField/...` |
| `AccountSection.vue` | 5 输入框接 `FieldError`（昵称/邮箱取 `useUser` 的 errors，密码三项用本地实例）；`changePassword` 3 处 warning → 内联（含 `confirm` 跨字段 validator）；error → `friendlyError()` |
| `useUser.ts` | `validateForm` 的 2 处 warning → `useFormValidation` 并**返回 `errors/validateAccountField/validateAccountAll`**；error → `friendlyError()`；删除从未被消费的 `rules`；**v1.1：`snapshot` 脏值检测**（未改动则不发请求/不弹提示，成功才更新快照） |
| `useChatStream.ts` | `:244`/`:366` 气泡 → `friendlyError(error.message, …)`，原始错误仅 `console.error` |
| `confirm.ts` | `confirmDelete(message, title = '确认操作')` —— 去掉硬编码标题 `'警告'`；危险场景（登出）显式传 `'警告'`；`autofocus: false` 约定不变 |
| `main.css` | 新增语义色 token `--warning/--warning-soft/--warning-border`；`.el-message-box` 从 1 行背景覆盖 → 全套（圆角 `--radius-md`、标题/内容/分隔线、双按钮玻璃样式、危险态 `.is-danger`） |

### 三、明确不动
- `CharacterManagerView` / `TimelineView` 的 `ElMessage.warning` —— 不在三文件范围，列为后续
- 全部 `ElMessage.success` —— 非警告
- `enterSubmit` 回车约定、GSAP 入场动画、验证码倒计时逻辑、`email-with-code` 布局 —— 零改动

### 四、脏值检测（v1.1 补丁：点一下输入框就弹「更新成功」）

**问题**：`AccountSection` 昵称/邮箱是「blur 即保存」的既有设计，但 `saveAccountInfo()` **没有脏值检测**——点一下输入框、什么都没改、失焦 → 校验通过 → 照样 `POST /user/update` + 弹「更新成功」。密码表单有「保存信息」按钮、昵称/邮箱没有，用户自然觉得"我没按保存啊"。

**方案**（`src/composables/useUser.ts`）：

```ts
const snapshot = { nickname: accountForm.nickname, email: accountForm.email }

// fetchUserInfo 成功 → snapshot = 后端值（「已保存」基准）
// saveAccountInfo：校验通过后 ↓
if (accountForm.nickname === snapshot.nickname && accountForm.email === snapshot.email) return  // 未改：静默
// 请求成功 → snapshot = 新值（成功才更新）
```

| 场景 | 行为 |
|------|------|
| 点输入框不改内容 → blur | 校验通过 → **无变化 → 不发接口、不弹提示** |
| 改了值 → blur | 发 `POST /user/update` → 弹「更新成功」→ 更新快照 |
| 后端返回失败 | 快照**不**更新 → 下次失焦自动重试 |

「昵称与邮箱会立即保存」的既有设计与 `SettingsSection` 描述保持不变，只是**不再空转请求**。

## 已知问题

- `type-check` 存在**既有**错误（`localImages.ts`、`storyMappings.ts`、`RagAssistantView.vue` references readonly、`TimelineView.vue`），与本次改动无关；本次涉及的 8 个文件零类型错误。
- `lint` 基线由 11 个既有错误降至 **8 个**（改造顺带消除 3 个），零新增。
- `CharacterManagerView`（"请输入角色名称"）、`TimelineView` 仍用 `ElMessage.warning`，未迁。
- 无通用错误页（仅 404）；如需"专门的 error 页面"属新需求，本次未做。
- `confirmDelete` 的危险态样式依赖 EP 在 `type: 'error'` 时加的 `.is-danger`；`type: 'warning'` 走 `--warning` 图标色。

## 验证方式

1. `npm run build-only` 通过（1986 模块）。
2. `npm run lint`：8 个错误全为既有文件，无一涉及本次改动。
3. `npm run type-check`：本次改动文件零错误。
4. `npm run dev` 手工回归：
   - **密码登录**：空提交 → 用户名/密码下方红字（非 toast）；blur 即校验；填对后红字消失
   - **验证码登录**：切换登录方式 → 旧错误清空；发码倒计时 60s 正常；空邮箱/错格式 → 内联红字
   - **注册**：昵称、验证码字段**首次有校验**；密码 <6 位内联提示；发码 → 倒计时 → 提交
   - **面板切换**：登录↔注册不残留上一面板错误
   - **回车提交**：非末框跳下一框、末框提交，行为不变
   - **移动端 ≤768px**：单面板静态布局、`panel-switch` 显示、FieldError 不破版
   - **设置-账户**：昵称/邮箱 blur 内联校验；**不改内容失焦 → Network 无 `/user/update` 请求、不弹提示**（脏值检测）；改内容失焦 → 请求 +「更新成功」；改密码三项（含"两次不一致"跨字段）内联提示
   - **后端错误**：故意输错密码 → 显示友好文案，`console` 才有原始 msg
   - **RAG**：断网/后端报错 → 气泡显示友好文案，不含后端原文
   - **确认弹窗**：登出弹窗玻璃化、圆角、双按钮分层，标题为「警告」；普通删除为「确认操作」
