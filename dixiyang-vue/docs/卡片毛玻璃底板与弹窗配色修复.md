# 卡片毛玻璃底板与弹窗配色修复（角色卡 / 时间线卡 / 角色弹窗）

> 版本：v2.0 ｜ 日期：2026-09-29
> 前置：[角色管理页移动端适配与美化](./角色管理页移动端适配与美化.md)、[毛玻璃与弹窗配色修复](./毛玻璃与弹窗配色修复.md)
> 本轮改用**真实浏览器探针（Chrome CDP + 像素测量）**取证，纠正了前两轮的两处错误判断

## 需求（用户反馈）

1. **角色卡片还是全透明**，毛玻璃质感没有。
2. **时间线的卡片配色也全是透明的**。
3. **el-dialog 还是全黑**，看不清。

## 取证方法与关键事实

用 CDP 驱动真实 Chrome（`scripts/_probe-render.mjs`，假 JWT 写入 localStorage 通过路由守卫），读取计算样式 + 截图做像素级对比：

| 探针结论 | 实测值 | 含义 |
|---------|-------|------|
| 角色卡计算样式 | `background: rgba(255,255,255,0.05)`、`backdrop-filter: blur(20px)` | **底板只有 5% 白**，等于一层看不见的薄膜 |
| 放大卡区域内相邻像素平均梯度（锐度） | 基线 `5.922` vs `backdrop-filter:none` **`5.922`** | 两者**逐像素相同**，`backdrop-filter` 在该页面未参与合成 |
| 整页 A/B 截图字节数 | `blur(20px)` 与 `none` 两张图**字节完全相同**（1672925） | 铁证：模糊没有生效 |
| 切换 `will-change: auto` / `transform: none` / `position: static` / `overflow: visible` | 锐度全部 `5.922` 不变 | **与动画、transform、will-change 全部无关** |
| 弹窗计算样式 | `background: rgb(13,13,15)`（不透明）、`matches('.el-dialog.character-dialog') = true` | 我的规则匹配上了，但**没赢** |
| `#theme-bg` 定位 | `position: fixed; z-index: 0; background-attachment: ... fixed`，是 `body` 的子节点、与 `#app` 平级 | 卡片祖先链上不绘制任何背景 |

## 两个真正的根因

### 1. 卡片透明：底板透明度过低 + `backdrop-filter` 不提供底色

`backdrop-filter` 的作用是**模糊元素背后的内容**，它**不提供任何底色**。卡片底板一直是 `--glass-bg` = `rgba(255,255,255,.05)`（全项目 `main.css` 里的 `.glass-card` 定义），所以：

- 背景图**清晰地**穿过卡片 → 视觉上就是"全透明"；
- 即使 `backdrop-filter` 起作用，效果也仅是"背后内容变模糊"，卡片本身依然是那张背景图，没有"卡"的边界感。

> 上一轮我判断"祖先 transform 生成 backdrop root 导致失效"——**方向错了**。本轮 A/B 已证明 `will-change`/`transform`/`position`/`overflow` 四种切换对结果**零影响**。那一轮唯一的有效改动是"关键帧去掉 transform"（顺手减少了一个潜在风险），但它不是本问题的主因。

### 2. 弹窗全黑：`!important` 优先于任何非 `!important` 声明，与选择器特异性无关

`main.css`：

```css
.el-dialog { background: var(--surface-page) !important; backdrop-filter: blur(20px) !important; }
```

而上一轮我写的是 `.el-dialog.character-dialog { background: var(--surface-panel); … }`（**没有 `!important`**）。CSS 级联规则：**`!important` 声明永远优先于普通声明，比较特异性只在同一层级内进行**。所以全局那条不透明的 `#0d0d0f` 一直赢。

> 上一轮我的结论"复合选择器 0-2-0 压过 0-1-0"也是错的——那只在双方都没有 `!important` 时成立。

## 方案

### 一、新增"强衬底" token（`src/assets/main.css`）

```css
--surface-panel-strong: rgba(16,18,26,0.52);
--glass-bg-strong: var(--surface-panel-strong);
```

取值依据（探针实测卡片区域）：

| 候选底板 | 平均亮度 | 正文(白字)对比度 | 背景明暗摆幅 |
|---------|---------|----------------|------------|
| 原 `rgba(255,255,255,.05)` | 0.0117 | 17.01 | **0.0346**（背景图亮部透出来，花） |
| `rgba(255,255,255,.16)` | 0.0368 | 12.09 | 0.0538（发灰、不像玻璃） |
| **`rgba(16,18,26,.52)`（选用）** | 0.0055 | **18.92** | **0.0154**（摆幅比原来小一半，平顺） |

即：**白字对比度 18.9（优秀档 ≥7）+ 明暗摆幅最小**，任何背景下都读得清、且读作"玻璃卡"。

### 二、全局 `.glass-card` 用新底板（`main.css`）

```css
.glass-card {
  background: var(--glass-bg-strong);   /* 原 var(--glass-bg) = 5% 白 */
  backdrop-filter: blur(16px);
  -webkit-backdrop-filter: blur(16px);
  …
  /* 同时移除 will-change: transform, backdrop-filter（无必要，且模糊/合成路径更简单） */
}
```

**影响面（已核实）**：全局 `.glass-card` 只被 **时间线 `.node-card`** 与 **角色页两类卡**使用；`HomeView.vue:601` 和 `CreateCard.vue:213` 各自定义了 scoped `.glass-card` 并继续用 `--glass-bg`，**不受影响**。`.glass-sm/.glass-lg/.glass-xl`（工具栏/图例等）未改动。

### 三、角色卡底板用 `!important` 压过同名全局规则（`CharacterManagerView.vue`）

```css
.glass-card {
  background: var(--glass-bg-strong) !important;  /* 压过 main.css 的同名 .glass-card */
  backdrop-filter: blur(20px); -webkit-backdrop-filter: blur(20px);
  …
}
```

### 四、弹窗每条声明都加 `!important`（`CharacterManagerView.vue` 非 scoped 块）

> **（已升级）** 这一半后来改为全局方案：面板样式移入 `main.css` 的 `.el-dialog`，面板色去黑为 `#222530`，
> 组件内不再需要 `!important`。详见 [弹窗面板全局化与去黑](./弹窗面板全局化与去黑.md)（索引 8.11）。
> 以下为当时方案，仅作历史记录。

```css
.el-dialog.character-dialog {
  background: var(--surface-panel-strong) !important;   /* 原来漏了 !important，一直输给全局 */
  backdrop-filter: blur(20px) !important;
  -webkit-backdrop-filter: blur(20px) !important;
  border: 1px solid var(--glass-border) !important;
  border-radius: var(--radius-md) !important;
  box-shadow: var(--shadow-card) !important;
  padding: 17px;                                        /* 补回 1px 边框占掉的内容盒 */
}
```

移动端抽屉规则同步补 `!important`（`max-height` / `border-radius`）。

## 已知问题

- **headless Chrome 下 `backdrop-filter` 未参与合成**：本机 CDP 实测 `blur(20px)` 与 `none` 截图逐字节相同，且改 `#theme-bg` 的 `background-attachment`、给卡片加 `position: relative` 都无法使其生效。`#theme-bg`（`position:fixed` + `background-attachment:fixed`）与 `#app` 是 `body` 下的兄弟节点，卡片祖先链不绘制背景——这是 Chrome 背景附着/合成路径的已知脆弱点。因此本次修复**不依赖 `backdrop-filter`**：底板自身足够不透明，"看起来是玻璃卡"的效果在模糊无效时依然成立；模糊生效时观感只会更好。
- 该结论只针对角色页/时间线；其它页面若也依赖 `backdrop-filter` 的"模糊背后"效果，需要各自复核（本次未动）。
- `--surface-panel-strong` 刻意保持"深色带一点冷调"，不是纯灰——纯灰会让卡片在背景图上发白、发脏。
- 弹窗改玻璃面板后，`.el-overlay` 的暗色遮罩仍在其后，观感为"暗景中一块稍亮的玻璃面板"，与设置页面板（`--surface-panel`）同族。
