# 更换邮箱验证码流程

> 版本：v1.0 ｜ 日期：2026-09-29 ｜ 范围：前端 `useUser`/`AccountSection` + 后端 `DixyangFast /user/update`
> 后端接口细则见 `DixyangFast/docs/用户与配置接口文档.md` §2

## 需求

1. 改邮箱**不该那么容易**：`sXXXXXXXX@outlook.co` 这类地址过去失焦即写库成功（后端零校验）。
2. 要求走**邮箱验证码**：把验证码发到**新邮箱**，收到码才允许更换。
3. 顺带解决上一版脏值检测的盲区 —— 脏值检测只防「没改也发」，防不了「乱改也成」。

## 根因

| 环节 | 问题 |
|------|------|
| 前端 | `useUser.saveAccountInfo` 把 `{ nickname, email }` 一起提交，email 走 `@blur` 即保存；正则 `\. [a-zA-Z]{2,}` 允许 `.co` |
| 后端 | `routers/user.py::update_user` **零校验**直接 `user.email = body["email"]`（不验格式/唯一性/验证码） |
| 能力闲置 | 邮件验证码基础设施**早已存在**（`email_service.send_verification_code`、`EmailVerificationCode` 模型、60s 限流/5min 过期/一次性），但 `send_code` 的 purpose 白名单只有 `("LOGIN","REGISTER")`，从未接到改邮箱上 |

## 方案

### 一、后端 `DixyangFast`（3 文件）

1. `services/auth_service.py`
   - `send_code` purpose 白名单 → `("LOGIN","REGISTER","CHG_EMAIL")`（限流/过期/一次性逻辑**原样复用，零新增**）
   - 新增模块级 `verify_change_email_code(db, email, code) -> str | None`：查未过期未使用的 `purpose=CHG_EMAIL` 记录 → 比码 → `used=True`；返回 `None` 表示通过，否则返回用户可读错误
   - ⚠️ purpose 用 **`CHG_EMAIL`（9 字符）** 而非 `CHANGE_EMAIL`（12）—— 兼容现有 `email_verification_code.purpose VARCHAR(10)`，**无需改表迁移**
2. `routers/user.py::update_user` — 三段式：**先全部校验、后统一落库**
   - nickname：strip 后 1–20 字符
   - email：与库里相同 → 视为未改、免验证码；**变了** → ① 缺 code 报「更换邮箱需要验证码」② `verify_change_email_code` ③ 唯一性（排除自身）「该邮箱已被其他账号使用」
   - 全通过才 `db.commit()`（要么全改要么全不改）
3. `schemas/auth.py`：`SendCodeDTO.purpose` 注释补 `CHG_EMAIL`

### 二、前端（2 文件）

**`src/composables/useUser.ts`**
- `saveAccountInfo` **只提交 `{ nickname }`**，脏值检测只比对昵称（昵称失焦即存的既有体验不变）
- 新增独立表单 `emailForm { newEmail, code }` + `emailV` 校验实例
- 新增 `sendChangeEmailCode()`（`POST /auth/send-code { purpose:'CHG_EMAIL' }` + 60s 倒计时，与 `useAuth` 同款写法但不跨 composable 耦合）
- 新增 `changeEmail()` → `POST /user/update { email, code }` → 成功更新 `accountForm`/`snapshot`/Pinia 并清空草稿；失败走 `friendlyError`
- 新增 `cancelChangeEmail()` 清空草稿与错误；`onBeforeUnmount` 清倒计时定时器

**`src/components/settings/AccountSection.vue`**
- 邮箱行**不再是可编辑输入框**，改为只读展示 + 「更换邮箱」按钮
- 展开面板：`新邮箱`（blur 校验格式）→ `发送验证码`（60s 倒计时）→ `6 位验证码` → `确认更换`（成功后自动收起）/ 收起（清空草稿）
- `onAccountBlur` 拆为 `onNicknameBlur`（仅昵称路径）
- `SettingsSection` description 同步改写

### 交互

```
邮箱  [ sxxx@outlook.com  ]  [更换邮箱]
       └ 展开：
         [ 输入新邮箱            ]  blur 校验格式
         [ 6 位验证码 ] [发送验证码]   ← 60s 倒计时，码发到【新邮箱】
         [        确认更换        ]   ← 成功 → 收起 + 「邮箱已更换」
```

## 已知问题

- 「与当前邮箱相同」仅在**发码**时拦截（`sendChangeEmailCode`），提交路径靠后端 `email == 当前值 → 免码通过` 兜底，二者行为一致。
- 验证码校验失败**不消耗**该码（`used=True` 未 commit），可重试；换邮箱则须重新发码（码绑定邮箱）。
- 前端正则仍允许 `.co` 等合法 TLD —— 这是对的，**真正的门槛是收得到验证码**。
- 需要 SMTP 环境变量（`SMTP_HOST/PORT/USERNAME/PASSWORD`，`config.py`），缺失时 `send_code` 返回「验证码邮件发送失败」。

## 验证方式

1. 后端：`& .venv\Scripts\python.exe -m compileall -q src\dixiyang\routers\user.py src\dixiyang\services\auth_service.py`（已通过）。
2. 前端：`npm run build-only` / `npm run lint`（基线 8）/ `npm run type-check`（本文件相关 0 错）。
3. 手工（需起 8084 + SMTP）：
   - 设置-账户：点「更换邮箱」→ 输入新邮箱 → 发码 → 60s 倒计时，**新邮箱收到 6 位码**
   - 只填邮箱不填码点确认 → 「更换邮箱需要验证码」
   - 填错码/等 5 分钟过期 → 对应错误文案，**不写库**
   - 正确码 → 「邮箱已更换」，面板收起，`GET /user/info` 返回新邮箱
   - 同一码二次使用 → 「请先获取验证码」（已 `used`）
   - 填**别人已占用**的邮箱 + 有效码 → 「该邮箱已被其他账号使用」
   - 昵称失焦照旧：不改不发请求，改了直接存（**不弹码**）
