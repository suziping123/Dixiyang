# 移动端浮动导航防遮挡（悬浮球化）

> 版本：v1.2 ｜ 2026-10-10（v1.1：2026-09-29）
> 后续修复与视觉美化见：[悬浮球美化与适配修复](./悬浮球美化与适配修复.md)（修复巨型胶囊/横条压球两处回归）
> v1.2：宽屏桌面左侧 100px 隐形热区穿透修复（挡点击/误触），见文末章节

## 需求

移动端（触屏设备）下，FloatingNav 以**左下角常驻横条**形式展示（3 个 38px 按钮约 150×54px、`position: fixed`、`z-index: 100`），会盖住页面左下角的交互元素——典型如 RAG 助手页（`RagAssistantView.vue`）的「历史」「上下文」按钮、输入框左端等，导致无法点击。

## 根因（两轮定位）

1. **触屏常驻横条遮挡**：`(hover: none), (pointer: coarse)` 下整条常驻，面积大。
2. **桌面窄视口 hover 热区遮挡**（第一轮漏掉的真凶）：桌面模式下 `.nav-wrapper` 是**左侧 100px 宽、全高、透明、z-index:100** 的热区，鼠标进入即弹竖条、且拦截该区域点击。窄视口（≤768px）下 RAG 页按钮 x≈31px 起，**整个落在 100px 热区内** → 桌面缩窗测试时按钮完全点不到（这也是"第一轮修复无效"的原因——触屏媒体查询在桌面窗口不触发）。

## 方案

把 FAB（悬浮球）模式的触发条件从"仅触屏"扩展为"**触屏 或 视口 ≤1024px**"（与 RAG 抽屉断点一致）：

- 平时左下角只显示一个 46×46 圆形悬浮球（菜单图标），常驻遮挡面积从 ~150×54 缩到 46×46。
- 点击悬浮球 → 在其右侧滑出导航横条，同时出现**全屏透明遮罩**（拦截误触页面）。
- 以下任一操作收起：点击遮罩 / 再点悬浮球 / 选中导航项 / 路由切换（含浏览器返回）。
- 视口 **>1024px 且非触屏**才走桌面 hover 竖条模式（`isFab` 守卫，触屏合成 mouseenter 不影响展开状态）。
- RAG 页「历史/上下文」按钮**居中**（≤768px 时 `chat-header` 改 `align-items: center`），远离左缘，避开悬浮球与热区。

检测逻辑（JS 与 CSS 媒体查询保持同一条件）：

```ts
const touchMedia = window.matchMedia('(hover: none), (pointer: coarse)')
const compactMedia = window.matchMedia('(max-width: 1024px)')
const isFab = ref(touchMedia.matches || compactMedia.matches)
// matchMedia change 监听，视口跨断点时实时切换
```

```css
@media (hover: none), (pointer: coarse), (max-width: 1024px) { /* FAB 样式 */ }
```

层级结构（wrapper `z-index: 100` 形成局部层叠上下文）：

```
nav-wrapper (fixed, z-index 100)
├── nav-backdrop  (fixed inset 0, z-index 1)  ← 展开时盖住页面、可点收起
├── nav-fab       (relative,   z-index 2)      ← 悬浮球，始终可点
└── floating-nav  (fixed,      z-index 2)      ← 展开横条，收起时 opacity 0 + pointer-events none
```

## v1.2 变更：宽屏桌面左侧热区穿透（根治挡点击 + 收窄误触）

### 需求

用户反馈「FloatingNav 的范围太大了」（2026-10-10，宽屏桌面场景）。第一轮（本文档 v1.0）只把 **≤1024px** 切成 FAB 规避了 100px 热区，**>1024px 桌面 hover 模式**下 `.nav-wrapper` 仍是左侧 **100px 宽 × 全屏高、z-index:100、无 `pointer-events` 控制**的隐形区域：

1. **挡点击**：页面左侧 100px 内的按钮/链接事件被该区域拦截（下面的「已知问题」中 session-panel 左缘重叠即此症状）；
2. **易误触**：鼠标扫过左缘任意位置（整条 100px 全高）即弹出导航面板。

### 方案（3 行 CSS，仅动桌面模式，FAB/移动端零改动）

```css
.nav-wrapper   { pointer-events: none; }  /* 整条穿透：不再拦截页面左侧点击（FAB 模式早有此处理，桌面模式漏了） */
.nav-trigger   { width: 16px;             /* 30→16：唯一 hover 入口，收窄误触面 */
                 pointer-events: auto; }  /* 穿透后由它接管 hover（mouseenter 由命中子元素沿祖先链分发到 wrapper） */
.floating-nav  { pointer-events: auto; }  /* 展开面板单独恢复可点；收起态在屏幕外 hit test 不命中，无副作用 */
```

关键点：

- **mouseenter 沿祖先链分发**：wrapper 自身 `pointer-events:none` 不成为命中目标，但指针进入 trigger（wrapper 后代）时 wrapper 的 mouseenter 照常触发 → 面板照常弹出；
- **无缝衔接**：trigger 右缘 16px = 展开面板 `left:16px`，从 trigger 水平右移直接进面板，不丢 hover；离开 trigger 又不在面板高度 → 立即收起（期望行为：不想用导航时一甩就掉）；
- **FAB 覆写不受影响**：FAB media query 内 `.nav-wrapper { pointer-events:none }`（同值）、`.nav-trigger { display:none }`、`.floating-nav` 收起 `none`/展开 `auto` 均源顺序靠后，覆盖基础规则。

### 改动文件

| 文件 | 改动 |
|------|------|
| `src/components/FloatingNav.vue` | `.nav-wrapper` 加 `pointer-events:none`；`.nav-trigger` `30px→16px` + `pointer-events:auto`；`.floating-nav` 加 `pointer-events:auto`（均附注释） |
