# 登录页背景视频资源修复

> 最后更新: 2026-09-28
> 范围: 前端 `dixiyang-vue/Dixiyang-vue3`

## 一、问题

Vite dev server 报错：

```
Failed to resolve import "/videos/卡比.mp4" from "src/views/LoginView.vue". Does the file exist?
```

**根因**：
1. `LoginView.vue:4` 用根绝对路径 `/videos/卡比.mp4`，Vue SFC 的 `transformAssetUrls` 会把 `<source src>` 编译成 ESM `import`，Vite 按项目根 `Dixiyang-vue3/videos/` 解析 → 该目录不存在。
2. 源视频实际只残留在构建产物 `dist/videos/卡比.mp4`（`src/videos/` 已被删除）。
3. 根 `.gitignore:132` 有 `*.mp4`，视频不入库，换机器/CI 必然缺文件。

## 二、方案

| 项 | 处理 |
|----|------|
| 资源位置 | 复制 `dist/videos/卡比.mp4` → `src/assets/videos/卡比.mp4`（项目已有该资源目录规范） |
| 引用方式 | `/videos/卡比.mp4` → `@/assets/videos/卡比.mp4`（走 `vite.config.ts` 的 `@ → ./src` alias） |
| 打包行为 | `vite build` 自动带 hash 打进 `dist/assets/卡比-*.mp4`，dev/prod 一致 |

**改用 `@/assets/...` 的理由**：`/` 开头路径只能命中 `public/`，而模板中的 asset URL 会被编译为 import，`public` 内容不应被 import；`src/assets` + alias 是 Vite 官方推荐做法，且 `src/assets/videos/` 已存在。

## 三、改动文件

- `Dixiyang-vue3/src/views/LoginView.vue` — `<source src>` 路径改为 `@/assets/videos/卡比.mp4`
- `Dixiyang-vue3/src/assets/videos/卡比.mp4` — 新增（从 `dist/videos/` 复制，34MB）

## 四、验证方式

```powershell
# 1. dev server 转换成功（200，import 解析到 /src/assets/videos/）
#    GET http://localhost:5173/src/views/LoginView.vue
#    期望: import _imports_0 from "/src/assets/videos/卡比.mp4?import";

# 2. 生产构建成功且视频入包
cd Dixiyang-vue3
npm run build-only     # ✓ built，dist/assets/卡比-DGAgbYBS.mp4 34,011 kB
```

## 五、已知问题

1. **`*.mp4` 被根 `.gitignore:132` 忽略** → 视频不提交，他人克隆后登录页视频 404（不阻断功能）。如需入库，加例外：`!dixiyang-vue/Dixiyang-vue3/src/assets/videos/*.mp4`。
2. **`npm run build` 的 `type-check` 阶段有既有 TS 错误**（`localImages.ts`、`storyMappings.ts`、`RagAssistantView.vue`、`TimelineView.vue`，均与本次改动无关），故验证用 `npm run build-only`。修复这些类型错误为独立任务。
3. **视频 34MB 进主 bundle 产物**，登录页加载偏重；可后续换更小素材或做懒加载。

## 六、排查提示

- 新增 `<video>/<img>` 资源时：放 `src/assets/` 并用 `@/assets/...` 引用；`public/` 只放 favicon、无需打包的静态件。
- `dist/` 是可清理产物，**不可**作为资源来源长期依赖。
