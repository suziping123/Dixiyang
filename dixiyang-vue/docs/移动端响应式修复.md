# 移动端响应式修复（主页 / 角色管理 / 页面头部）

> 版本：v1.0 ｜ 日期：2026-09-29 ｜ 断点：`≤1024px`、`≤768px`
> 前置：[悬浮球美化与适配修复](./悬浮球美化与适配修复.md)（导航已改右侧悬浮球）

## 需求

1. **角色管理**移动端：卡片太大、字太大、整体不居中。
2. **主页**移动端：字体太大、比例失衡，挤压其他按钮（卡片底部三枚操作按钮）。
3. 断点 375px（常见手机宽）与 768px（平板竖屏）两档都要能看能点。

## 根因

| # | 症状 | 根因 | 位置 |
|---|------|------|------|
| 1 | 角色管理内容**偏左不居中** | `margin-left: 80px/70px` 是**旧左侧竖条导航的残留**；导航早已改成右侧悬浮球，这块留白纯属把内容往左推 | `CharacterManagerView.vue` 媒体查询 |
| 2 | 角色卡片太大 | `padding:24px` + 60px 头像 + `min-height:280px` + `1fr` 全宽，移动端无降档 | 同上 |
| 3 | 字太大 | `section-title 1.5rem`、`character-name 1.25rem`、`avatar-text 1.5rem` **零缩放** | 同上 |
| 4 | 弹窗按钮被挤出屏 | `el-dialog width="650px"` / `"400px"` **硬编码**，375px 屏直接超宽 | 同上 |
| 5 | 主页卡片按钮被挤 | 手机上是**双列小卡（约 160px 宽）**，却用 `.card-content { padding: 28px }` + 桌面字号（`novel-title 1.6rem` 等）→ 内容溢出，底部 `.action-btn-sm` 三枚按钮被压 | `HomeView.vue` |
| 6 | 主页顶栏挤压 | `.logo-wrapper { min-width: 300px }` + `logo-text 3.5rem` 手机上不降（仅降到 2rem） | 同上 |
| 7 | 各子页顶栏同样爆 | **`NovelPageHeader` 一个媒体查询都没有**（3.5rem 标题 + 300px 最小宽），角色管理/时间线/小说编辑共用 | `NovelPageHeader.vue` |
| 8 | 死代码 | 媒体查询里的 `.floating-nav` / `.nav-item` —— `FloatingNav` 是子组件，父组件 scoped 够不到 | `CharacterManagerView.vue` |

## 方案（全部为 CSS 响应式，无 JS 改动）

### 一、`CharacterManagerView.vue`

```css
@media (max-width: 1024px) {
  .main-stage { margin-left: 0; }            /* 删旧左侧导航留白 → 恢复居中 */
}
@media (max-width: 768px) {
  .main-stage { padding: 40px 16px; margin-left: 0; }
  .section-title { font-size: 1.15rem; }
  .glass-card { padding: 16px; }
  .character-avatar { width: 48px; height: 48px; }
  .avatar-text { font-size: 1.1rem; }
  .character-name { font-size: 1.05rem; }
  .character-desc { font-size: 0.85rem; }
  .action-btn { padding: 7px 10px; font-size: 0.85rem; }
  .create-card { min-height: 200px; }
  /* 弹窗：两列改单列 + 内部滚动，底部按钮始终可见 */
  .character-dialog :deep(.el-col) { flex: 0 0 100%; max-width: 100%; }
  .character-dialog :deep(.el-dialog) { max-height: 86vh; display: flex; flex-direction: column; }
  .character-dialog :deep(.el-dialog__body) { overflow-y: auto; }
}
```

弹窗宽度走 **prop 而非 CSS**（`:deep()` 受 teleport/class 落点影响，不可靠）：
```vue
<el-dialog width="min(650px, 92vw)" ...>   <!-- 原 650px -->
<el-dialog width="min(400px, 92vw)" ...>   <!-- 原 400px -->
```

同时删除媒体查询中失效的 `.floating-nav` / `.nav-item` 规则（死代码）。

### 二、`HomeView.vue`（768 块增强）

- 顶栏：`.logo-wrapper { min-width: 0 }`、`.logo-img { max-height/min-width: 56px }`、`logo-text 2→1.6rem`、`glow-line 150→90px`、`.section-title 1.4→1.05rem`
- **双列小卡降档**（核心）：`.card-content 28→14px`、`novel-title 1.6→1.1rem`、`description 0.9→0.8rem`、`.pen-name 0.7rem`、`.novel-id` 隐藏、`.card-stats`/`.stat` 缩 padding 与字号、`.card-actions gap 8→6`、`.action-btn-sm padding 8→5`
- `flex: 1` 的 `.description` 会自动吸收剩余高度，卡片比例 `aspect-ratio: 2/3` 在双列下（≈160×240）保持不变

### 三、`NovelPageHeader.vue`（新增响应式，此前为零）

```css
@media (max-width: 1024px) { .logo-text { font-size: 2.5rem; } }
@media (max-width: 768px) {
  .stage-header { margin-bottom: 32px; }
  .logo-wrapper { min-width: 0; }
  .logo-text { font-size: 1.6rem; letter-spacing: -1px; }
  .glow-line { width: 90px; }
  .subtitle-row { flex-wrap: wrap; gap: 10px; }
  .subtitle { font-size: 1rem; }
  .novel-cover-thumb { width: 44px; height: 44px; }
}
```

## 已知问题

- 角色卡片 `1fr` 单列全宽在 768 屏仍较宽（有 `padding:16px` 缓解）；如需更紧凑可再加 `max-width`。
- `.character-dialog` 若 EP 版本把 `class` 落到 `.el-dialog` 自身而非 overlay，`:deep()` 系规则会失效 —— 本次已实测背景样式生效（说明 class 在 overlay），后续升级 EP 需回归。
- 其余页面（时间线、RAG、设置）的移动端未在本次范围；时间线 `.legend-fixed` 已确认在右下角，与右侧悬浮球**不同高**（球在垂直中部），不冲突。
- `TimelineView`/`RagAssistantView` 各自的窄屏样式未动。

## 验证方式

1. `npm run build-only` 通过（9.94s）；`npm run lint` 8 errors = 基线（零新增）；`npm run type-check` 本次改动文件 0 错。
2. `npm run dev` + DevTools 375×667 / 768×1024：
   - **角色管理**：内容水平居中（不再整体左偏）、卡片内边距与字号明显降档、创建按钮占满行宽
   - 角色弹窗：宽 `92vw` 不超屏，两列变单列，**表单超高时 body 内滚动，底部取消/保存始终可见**
   - **主页**：顶栏不换行爆版；双列小卡内标题/描述不溢出，底部三枚操作按钮完整可点
   - 各子页（角色/时间线/小说编辑）顶栏 `DIXIYANG ENGINE` 缩到 1.6rem，封面缩略图 44px
3. 宽屏（>1024px）回归：三处页面桌面样式与改动前一致（新增规则全部包在媒体查询内）。
