# 弹窗面板全局化与去黑

> 版本：v1.0 ｜ 日期：2026-09-29
> 前置：[卡片毛玻璃底板与弹窗配色修复](./卡片毛玻璃底板与弹窗配色修复.md)（弹窗那一半由本文升级为全局方案）
> 用户原话：「就是现在的全黑风格不太满意……不能全黑，也不能看不清楚内容，也就是说太黑了都不行」
> 诉求：「直接改这个 el-dialog，全局改，直接用，直接复用」

## 需求

1. 弹窗面板**不能是"一块全黑"**（原来是不透明 `#0d0d0f`，在亮页面上像黑洞）。
2. **内容必须看得清**，不能为了不黑而把字糊掉。
3. 不再逐页写弹窗样式：**改全局 `.el-dialog`，全站复用**，包括此前只吃默认黑底的 `CharacterSettingsDialog.vue`（AI 设定助手）。

## 标定过程（真实 Chrome + 像素取样）

用 `scripts/_probe-dialog-tone2.mjs` 造一块 `.el-dialog` 面板，逐候选改底色后读回**实际渲染像素**，再算白字 WCAG 对比度（合格 4.5 / 优秀 7）：

| 候选 | 面板实测 RGB | 相对亮度 L | 白字对比度 | 结论 |
|------|-------------|-----------|-----------|------|
| 原 `--surface-page` `#0d0d0f` | `13,13,15` | 0.0032 | ≈19 | 全黑，用户不接受 ❌ |
| 上一轮 `--surface-panel-strong` `rgba(16,18,26,.52)` | `16,18,26`（不透明时） | 0.0062 | 18.69 | 仍偏黑 |
| `rgba(25,28,38,1)` | `25,28,38` | 0.0118 | 17.00 | 稍好 |
| **`#222530` = `rgb(34,37,48)`** | **`34,37,48`** | **0.0188** | **15.27** | **✅ 选定** |
| `rgba(44,48,60,1)` | `44,48,60` | 0.0298 | 13.17 | 开始发灰、缺少质感 |
| 半透明冷白玻璃 28–46% | `142,132,161`~`170,163,184` | 0.26~0.39 | **2.38~3.37** | 亮衬底上糊成一片白，白字**不合格** ❌ |

**关键结论**：玻璃面板要"不黑且可读"，必须**不透明**——半透明方案在亮背景页面（如登录页衬底 L≈0.19）上会整体发白，对比度掉到 2.4~3.4。所以去黑靠**把面板本身颜色调亮一档**（`#0d0d0f` → `#222530`），而不是降不透明度。

## 另有一处必须知道的坑：EP 的样式在 main.css 之后导入

`src/main.ts` 的导入顺序是：

```ts
import './assets/main.css'      // 我的全局样式（前）
…
import 'element-plus/dist/index.css'   // EP 基础样式（后）
```

同特异性选择器相遇时**后导入者胜**，与"只在 main.css 里写就行"的直觉相反。实测两次踩到：

1. `.el-dialog { padding: 17px }` 被 EP 的 `.el-dialog { padding: var(--el-dialog-padding-primary) }` 覆盖；
2. 更严重：`.el-dialog__title { color: var(--text-primary) }` 被 EP 的深色 `color: var(--el-text-color-primary)` **覆盖成 `rgb(48,49,51)`**，在深色面板上几乎看不见（首轮实测就是这个值）。

**处置**：凡与 EP 撞名的属性一律用 `html` 前缀提升特异性（`html .el-dialog`、`html .el-dialog__title`、…），**不引入 `!important`**——保持样式表干净、可覆盖。

## 方案

### 一、`src/assets/main.css`

新增面板 token（与既有 `--surface-panel` / `--surface-panel-strong` 并列）：

```css
--surface-dialog: #222530;   /* 弹窗面板专用：比 --surface-panel 亮一档，避免"一块全黑" */
```

**替换**原先那条单行规则 `.el-dialog { background: var(--surface-page) !important; backdrop-filter: blur(20px) !important; }` 为一套全局面板样式：

```css
html .el-dialog {
  background: var(--surface-dialog);
  -webkit-backdrop-filter: blur(20px); backdrop-filter: blur(20px);
  border: 1px solid var(--glass-border);
  border-radius: var(--radius-md);
  box-shadow: var(--shadow-card);
  color: var(--text-primary);
  padding: 17px;                       /* EP 默认 16px + 1px 边框回填 */
}
html .el-dialog__header { padding-bottom: 14px; border-bottom: 1px solid var(--border-color); }
html .el-dialog__footer { padding-top: 14px; border-top: 1px solid var(--border-color); }
html .el-dialog__title { color: var(--text-primary); }          /* 关键：压过 EP 的深色标题 */
html .el-dialog .el-form-item__label { color: var(--text-primary); }
html .el-dialog .el-input__wrapper,
html .el-dialog .el-textarea__inner,
html .el-dialog .el-select__wrapper,
html .el-dialog .el-input-number__wrapper { background: var(--surface-input); border-color: var(--glass-border); color: var(--text-primary); box-shadow: none; }
html .el-dialog .el-input__inner,
html .el-dialog .el-textarea__inner,
html .el-dialog .el-select__placeholder { color: var(--text-primary); }
/* 聚焦 / hover / placeholder / 下拉项 …（同前缀） */
```

移动端全站弹窗统一贴底抽屉：

```css
@media (max-width: 768px) {
  html .el-dialog {
    width: 100% !important;              /* 压过各弹窗固定 width（420/480/800/850px） */
    max-width: 100vw;
    max-height: 88vh !important;
    margin: auto auto 0 !important;      /* 抵消 EP 默认 margin: 15vh auto 50px，贴底 */
    border-radius: var(--radius-md) var(--radius-md) 0 0;
    display: flex; flex-direction: column;
  }
  .el-dialog__body { overflow-y: auto; -webkit-overflow-scrolling: touch; padding: 0 14px; }
  .el-dialog__footer { padding-bottom: calc(14px + env(safe-area-inset-bottom, 0px)); }
  .el-dialog .el-input__inner, .el-dialog .el-textarea__inner { font-size: 16px; }  /* 防 iOS 聚焦放大 */
}
```

逃生口（当前无弹窗使用）：`html .el-dialog.dialog-plain { background: var(--surface-page); }`

### 二、`src/views/CharacterManagerView.vue`

删除文件末尾整个非 scoped `<style>` 块（原为压过旧全局规则而写的面板 + 表单项 + 抽屉，约 120 行，含大量 `!important`），只保留本页专属覆写：

```css
@media (max-width: 768px) {
  .el-dialog .el-col { flex: 0 0 100%; max-width: 100%; }  /* 性别/年龄两列改单列 */
}
```

模板不动（`class="character-dialog"` 与 `delete-dialog` 保留作语义标记）。文件由 1104 行降到 983 行。

## 已知问题

- **`el-message-box`（确认/警告框）仍是原来的玻璃样式**，未纳入本轮；它已有专门美化（`main.css` 的 `.el-message-box` 一节），观感与弹窗面板不同源，若需统一可后续处理。
- 面板为不透明色 → `backdrop-filter` 在它身上**不产生可见效果**（保留仅为与全站玻璃语言一致及未来降透明度时可用）。这是刻意的：不透明才不受页面明暗影响。
- 之前几轮我判断错过的两个坑现已记入本文档：① `!important` 优先于任何普通声明、与特异性无关；② EP 样式后导入，同特异性时 EP 赢，必须用 `html` 前缀提升特异性。
- 探针脚本 `scripts/_probe-dialog-final.mjs`（面板实测）与 `scripts/_probe-render.mjs`（计算样式/父链）保留可复现；其余临时诊断脚本已清理。

## 验证方式

1. `npm run build-only` ✅ 7.22s；产物 CSS 断言（已核对）：
   - `--surface-dialog: #222530`；
   - `html .el-dialog{background:var(--surface-dialog);…padding:17px}`（`html` 前缀）与 `html .el-dialog__title{color:var(--text-primary)}`；
   - 移动端 `html .el-dialog{width:100%!important;margin:auto auto 0!important;…}`；
   - `.el-dialog{…surface-page…}` 匹配数 **0**（旧的不透明黑规则已消失）；
   - 组件内 `.el-dialog.character-dialog` 匹配数 **0**（重复定义已清）。
2. **真实浏览器实测**（`scripts/_probe-dialog-final.mjs`，只给 `class="el-dialog"`、不写任何内联样式）：
   - 面板渲染像素 = `rgb(34,37,48)`、L = 0.0188、白字对比度 **15.27**；
   - 标题色 = `rgb(255,255,255)`（修复前是 `rgb(48,49,51)`，几乎不可见）；
   - 整屏图 `.probe/final_dialog.png` 人眼确认：深色玻璃面板 + 浅色文字 + 可辨边框。
3. 静态检查：`vue-tsc` 改动文件 0 错；`oxlint` 8 errors、`eslint` 21 errors = 既有基线，零新增。
4. 人工目视（`http://localhost:5173`，**硬刷新**）：上表 8 个弹窗逐个确认"不黑、看得清"；375px 视口确认全部为贴底抽屉、底部按钮常驻、聚焦输入框不缩放。
