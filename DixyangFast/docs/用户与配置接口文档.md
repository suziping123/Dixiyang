# DixyangFast 用户与配置接口文档

> 路由：`src/dixiyang/routers/user.py`、`src/dixiyang/routers/user_config.py`
> 鉴权：`/user/**` 需 `Authorization: Bearer <token>`（`get_current_user_id`）；`/userConfig/**` 按现有配置放行
> 响应：统一 `Result { code, msg, data }`；**HTTP 状态恒为 200，业务码在 body**（成功 200 / 失败 500，缺/坏 token 为 HTTP 401）——前端拦截器仅在 401 时跳登录，业务码由调用方判断（如 `assertApiResponse`）

## 用户模块（prefix `/user`）

### 1. GET /user/info
返回 `{ userId, username, nickname, email }`。

### 2. POST /user/update（2026-09-29 改：换邮箱需验证码）
body：`{ nickname?, email?, code? }` —— 非 null 字段才覆盖；**全部校验通过才落库**（要么全改、要么全不改）。

| 字段 | 规则 | 错误提示 |
|------|------|---------|
| `nickname` | strip 后 1–20 字符 | 昵称需为 1-20 个字符 |
| `email` = 当前值 | 无需验证码，直接通过（**脏值**：与库里相同即视为未改） | — |
| `email` ≠ 当前值 | 必须携带 `code`（`purpose=CHG_EMAIL` 邮箱验证码） | 更换邮箱需要验证码 / 请先获取验证码 / 验证码已过期，请重新获取 / 验证码错误 |
| `email` 已被他人占用 | `AppUser.email` 唯一（排除自身） | 该邮箱已被其他账号使用 |

**换邮箱流程**：
```
POST /auth/send-code  { email: 新邮箱, purpose: "CHG_EMAIL" }   → 60s 限流，5 分钟有效，一次性
POST /user/update     { email: 新邮箱, code: "123456" }         → 通过后写库并把该码 used=True
```

- 校验实现：`services/auth_service.py::verify_change_email_code()`；purpose 白名单 `("LOGIN","REGISTER","CHG_EMAIL")`（`CHG_EMAIL` 9 字符，兼容 `email_verification_code.purpose VARCHAR(10)`，**无需改表**）。
- **只改昵称不要传 `email`**（前端 `saveAccountInfo` 仅提交 `{ nickname }`）。
- 对应前端 `useUser.ts::changeEmail()` / `AccountSection.vue` 更换邮箱面板。

### 3. POST /user/password（2026-09-28 新增）
body：`{ oldPassword, newPassword }`

| 校验 | 错误提示 |
|------|---------|
| 两项缺一 | 参数不完整 |
| `len(newPassword) < 6` | 新密码至少 6 位 |
| 新旧密码相同 | 新密码不能与当前密码相同 |
| 用户不存在 | 用户不存在 |
| bcrypt 旧密码不匹配 | 当前密码不正确 |

- 成功：`_hash_pw(newPassword)` 覆盖后 `db.commit()`，返回「密码已修改」。
- 对应前端 `AccountSection.vue` → `POST /user/password`。

### 4. GET/POST /user/bg-config
旧版 `app_user.bg_config` JSON 字段（已被 `/userConfig/background` 取代，保留兼容）。

## 用户配置模块（prefix `/userConfig`）

见 Java 侧同名端点说明（行为对齐）：

| 端点 | 说明 |
|------|------|
| GET `/userConfig/background?userId=` | 返回 `UserConfig`（不存在自动创建） |
| POST `/userConfig/background` | `backgroundId` 非 null 才覆盖（**空串=清除**），`customBgs` 存 `storage/user/customBgs/{userId}.json` |
| GET `/userConfig/fontColors?userId=` | 读 `storage/user/fontColors/{userId}.json`（`__file__:` 引用兼容旧 DB 值） |
| POST `/userConfig/fontColors` | body `{ userId, colors }`，写 JSON 文件并更新 `font_colors_json` 引用 |

## 邮件验证码发送（2026-09-28 修复）

- `services/email_service.py`：按端口择协议——465 用 `SMTP_SSL`（隐式 SSL）；587/25 用 `SMTP` + `ehlo` + `starttls`。混用（465 上 `starttls`）会报 `Connection unexpectedly closed`。SMTP 配置缺失时打日志并返回 False。
- `services/auth_service.send_code()`：邮件发送失败时**删除本次验证码记录**（否则 60s 限流把用户锁死）并返回 `Result.error("验证码邮件发送失败，请稍后重试")`；此前后端忽略发送结果、假成功。
- 配置项（`.env`）：`SMTP_HOST`（默认 `smtp.qq.com`）、`SMTP_PORT`（默认 587）、`SMTP_USERNAME`、`SMTP_PASSWORD`（QQ 邮箱需用授权码而非登录密码）。

SMTP 连通性（不打印凭据）：

```powershell
# 465/587 均尝试连接+登录，输出 LOGIN: OK 即通
.\.venv\Scripts\python.exe -c "import sys; sys.path.insert(0,'src'); from dixiyang import config; import smtplib; s=smtplib.SMTP_SSL(config.SMTP_HOST,465,timeout=15); s.ehlo(); s.login(config.SMTP_USERNAME,config.SMTP_PASSWORD); print('LOGIN: OK'); s.quit()"
```
