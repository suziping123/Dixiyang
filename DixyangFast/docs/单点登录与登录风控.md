# Python 端：单点登录与登录风控

> 最后更新: 2026-10-06
> 总方案见根目录 [docs/单点登录与登录风控.md](../../docs/单点登录与登录风控.md)

## 需求

同一账号仅一台设备在线（顶号踢出）；10 分钟内登录 3 次后密码登录强制邮箱验证码（邮箱验证码设施本端原本已有）。

## 实现要点

1. **模型**：`models/user.py` 增加 `session_id/login_count/login_window_start/require_code`。
2. **签发**：`utils/jwt.py` 的 `create_access_token(user_id, session_id)` 增加 `sid` claim。
3. **登录**：`services/auth_service.py`
   - `login()`：密码通过 → 检查 `require_code`（拒绝文案「登录过于频繁，请使用邮箱验证码登录」）→ 生成 `uuid4().hex` 覆盖 `session_id` → `_record_login()` 窗口计数 → commit → 签发。
   - `login_by_code()`：验证码通过 → 顶号 + `require_code=False` + 重置窗口 → 签发。
   - 常量：`RISK_WINDOW_MINUTES=10`、`RISK_LOGIN_LIMIT=3`；时间统一 `_now_utc_naive()`（**UTC 字面值**，与 Java 共表可比）。
4. **校验**：`utils/auth_deps.py` 的 `get_current_user_id` 注入 `db: Session = Depends(get_db)`：
   - 无 `sid` claim → 401「登录已失效，请重新登录」
   - `sid != user.session_id` → 401「账号已在其他设备登录」
   - 58 处调用方均为 `Depends(get_current_user_id)`，FastAPI 自动注入 DB，**调用方零改动**。

## 已知问题

- JWT 密钥取 `.env` 的 `SECRET_KEY/JWT_SECRET_KEY`，与 Java 硬编码密钥不一致时切换后端会全员重登（见总文档「已知问题 1」）。
- `send_code` 的 `purpose` 白名单为 `LOGIN/REGISTER/CHG_EMAIL`；SMTP 未配置时返回真实失败，不会假成功。
