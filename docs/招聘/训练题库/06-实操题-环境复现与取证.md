# 实操题 · 环境复现与取证（12 题）

> **对应能力**：E1 环境、E3 取证、E5 标注
> **建议用时**：3-4 小时（可分两次）｜ **满分**：120（每题 10）
> **规则**：必须真实启动/请求/看日志；每題提交"命令 + 证据 + 结论"；禁止只贴代码。

> 安全边界：路径穿越/越权只在本地测试库、`/tmp` 沙箱做；不要删除真实用户数据；不要读取根 `.env`；截图打码 token/密码。
>
> 命令依赖：示例用 `jq` 取字段；没有 `jq` 时用 `python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["token"])'`。登录示例走 5173 代理；前端未起时把 host 换成 `localhost:8084`。

## P2. 造 11 本小说，复现 B1 分页漂移（L2）★

**目标**：用真实 API 造 11 本小说，证明前端发 `pageSize=100` 时只回 10 本；修复后回 11 本。

**步骤**：

```bash
TOKEN=$(curl -s -X POST http://localhost:8084/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin123","password":"123456"}' | jq -r '.data.token')

for i in $(seq 1 11); do
  curl -s -X POST http://localhost:8084/api/novel/create \
    -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
    -d "{\"title\":\"E2E分页-$i\",\"description\":\"paging\"}" >/dev/null
done

# 关键对比
curl -s -H "Authorization: Bearer $TOKEN" \
  'http://localhost:8084/api/novel/listall?page=1&pageSize=100' | jq '.data.records | length'
curl -s -H "Authorization: Bearer $TOKEN" \
  'http://localhost:8084/api/novel/listall?page=1&page_size=100' | jq '.data.records | length'
```

**预期**：前者 10，后者 11（或更多）；前端 Network 里是 `pageSize=100`。

**修复验证**：把前端改成 `page_size` 后，Network 的 query 变更；页面显示 11 本；Java 分支仍用 `pageSize`（不要盲改）。

**证据**：两条 curl 输出、Network 截图、修复前后对比。

**评分**：造数 2；两条对比 3；定位 2；修复+回归 3。

**陷阱**：只造 10 本，看不出问题；只改后端默认值为 11，掩盖契约漂移。

## P3. 让知识库页真实 500，观察静默失败（L2）★

**目标**：让前端调用的 8084 `/api/rag/documents` 真实返回业务 500，观察页面是否提示、是否保留旧数据。

> 关键事实：8084 的 `rag.py` 用 **嵌入式 Chroma**（`persist_directory`），不是 8000 的 Chroma Server；停 8000 不会让 `/api/rag/documents` 失败。8085 才通过 HTTP 连 8000。不要用错故障点。

**步骤（推荐，可回滚）**：

```bash
# 1) 用一个"不是目录"的路径让嵌入式 Chroma 初始化失败
touch /tmp/chroma-broken
# 2) 停掉你自己的 8084 测试进程（先确认 PID，别杀别人）
lsof -iTCP:8084 -sTCP:LISTEN -P -n
kill <确认过的PID>
# 3) 用坏路径重启（仍在 8084，前端代理无需改）
CHROMA_PERSIST_DIR=/tmp/chroma-broken ./start_backend.sh
# 4) 登录后请求，观察业务 500
curl -s -H "Authorization: Bearer $TOKEN" \
  http://localhost:8084/api/rag/documents | head -c 300
# 5) 测完恢复：kill 当前进程，正常 ./start_backend.sh；删除 /tmp/chroma-broken
```

**预期（修复前）**：HTTP 200 + `code:500 + data:null`；页面空白/旧数据；Console 只有 `加载文档失败`；无用户提示。

**修复后**：出现明确错误提示、表格清空、提供重试；恢复正常后端后重试成功。

**证据**：Network 响应体、Console、截图、恢复后 count。

**评分**：制造 500 3；观察 2；证据 2；修复/回归 3。

**注意**：不要删/改真实 `storage/vectordb_4060`；`/tmp/chroma-broken` 测完删除；若启动脚本强制覆盖环境变量，改用 `env CHROMA_PERSIST_DIR=...` 或临时改 `.env.example` 之外的启动参数（不要改真实 `.env`）。

## P4. 复现 SSE 取消：前端停、后端是否停（L3）★

**目标**：发一个长回答，1s 后取消，证明后端是否继续生成/落盘。

**步骤（浏览器）**：

1. 打开 DevTools Network，发"写 800 字"。
2. 首 token 后点停止。
3. 看 Network：请求是否 `canceled`；看 Console。
4. 看后端日志：abort 后是否还有 token。
5. 看链文件：`storage/chat/{userId}/{sessionId}/*.json` 的 assistant 内容长度。

**步骤（curl）**：

```bash
curl -N --max-time 3 -X POST http://localhost:8084/api/chat/stream \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"message":"写 800 字","sessionId":"<uuid>","useRag":false}' | head -c 500
```

**判定**：

- 前端停、后端 1s 内无新 token、链只存已流出部分 → 通过。
- 后端继续打 token 8s、链存完整回答 → 复现 E3，记 P1。

**证据**：HAR（aborted）、后端日志时间线、链文件内容、前端最后一段文本。

**评分**：复现 3；证据链 3；判定 2；修复建议 2。

## P10. Docker 部署验证 RAG 缺失（L2）

**目标**：用 `docker compose up` 起栈，证明 RAG 8085/Chroma 8000 不在 compose 内，主后端访问 `host.docker.internal:8085` 的行为。

**步骤**：

```bash
docker compose config | grep -E '8084|8085|8000|host.docker.internal'
docker compose up -d
docker compose ps
curl -s http://localhost:8084/api/rag/stats
docker compose exec backend sh -c 'curl -s --max-time 3 http://host.docker.internal:8085/api/rag/health || echo FAIL'
```

**预期**：compose 只有 MySQL/Redis/backend/frontend；8085 不在 `ps`；`/api/rag/stats` 可能 `connected:false`/空；容器内访问 8085 失败（若宿主机没起）。

**证据**：compose config、ps、curl、容器内失败输出。

**评分**：配置 3；运行 2；证据 3；修复 2。
