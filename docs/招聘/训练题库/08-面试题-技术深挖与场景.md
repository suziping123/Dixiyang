# 面试题 · 技术深挖与场景（30 题）

> **对应能力**：E2/E4/E6/E7
> **建议用时**：60 分钟 ｜ **满分**：100
> **规则**：先给结论，再给证据/例子；不会的题要说"我会怎么验证"，不要编。

# 一、技术深挖（20 题，每题 3 分）

## T1. `ref` 与 `reactive` 怎么选？

**答案要点**：

- `ref` 可包任意类型，模板自动解包，适合原始值/替换整个对象；`reactive` 只适合对象/数组，解构/替换会丢响应性。
- `reactive` 深层代理；`shallowRef/shallowReactive` 用于大对象/第三方实例（ECharts、编辑器）。
- 项目里 `messages`、`currentContent` 用 `ref`；Pinia setup store 用 `ref`。
- 常见坑：`reactive` 解构 `const { x } = state` 失去响应；`ref` 在 JS 里要 `.value`。

**追问**：`ref` 包对象和 `reactive` 有性能差异吗？→ 有代理层级/解包开销，但通常不是瓶颈；大对象用 `shallowRef`。

---

## T2. 为什么 Pinia setup store 里用 `ref` 而不是 `reactive`？

**答案要点**：

- setup store 本质是组合式函数，`ref` 可直接返回并被 Pinia 解包；`reactive` 无法整体替换。
- 便于 `storeToRefs` 解构；SSR/测试更简单。
- 项目 `stickyStore`、`userStore` 都用 `ref` + 函数。

**追问**：`storeToRefs` 和直接解构有什么区别？→ `storeToRefs` 保留响应性；直接解构拿到的是值。

---

## T3. 路由守卫怎么做登录拦截与回跳？

**答案要点**：

- `beforeEach` 校验 token（本地解 `exp` + 后端 401 兜底）。
- 未登录 `next({ path:'/login', query:{ redirect: to.fullPath } })`。
- 登录成功后只允许站内路径回跳，防开放重定向。
- 项目现状：只跳 `/login`、登录硬编码 `/home`，丢失深链（B16）。

**追问**：只在前端解 JWT 验过期安全吗？→ 不安全，只是 UX；后端必须验签。

---

## T4. axios 拦截器怎么处理业务码？

**答案要点**：

- 传输层 2xx ≠ 业务成功；项目后端用 `{code,msg,data}`。
- 401 统一清登录态跳登录；其他业务码应 `reject` 或强制调用方检查。
- 项目现状：`code=500` 也 resolve，导致 B2/B9 静默失败。
- 更好的做法：`request<T>()` 包装，统一检查 code；或拦截器 reject + 全局错误提示，但要评估调用方。

**追问**：为什么不能所有错误都 `reject`？→ 有些调用方需要业务错误数据（冲突提示、表单校验）；要区分"可恢复业务错误"和"系统错误"。

---

## T5. SSE 协议要点与解析坑

**答案要点**：

- `text/event-stream`；事件以空行分隔；`data:` 可多行；`id/event/retry` 字段。
- 解析要处理 `\r\n`、尾缓冲、`done` 后取消 reader、`TextDecoder` flush。
- 项目两份重复解析，`done` 不 break、尾行丢弃（B15）。
- 断线重连：`Last-Event-ID`/客户端重试；项目未实现。

**追问**：SSE 和 WebSocket 怎么选？→ 单向服务器推送用 SSE（简单、HTTP 兼容）；双向/二进制用 WebSocket。

---

## T6. `AbortController` 能解决所有竞态吗？

**答案要点**：

- 只取消"当前请求"，不能阻止已排队的回调/旧 Promise 写状态。
- 要配合请求序号/会话 ID 校验；abort 的 catch 也可能写新状态（B3）。
- 组件卸载/切会话要 abort + 清理 timer/reader。
- 服务端要检测断开并取消上游，否则"前端停、后端继续"（E3）。

**追问**：abort 后 `fetch` 的 Promise 会怎样？→ reject `AbortError`；要区分"用户取消"和"网络错误"。

---

## T7. `v-for` 一个字符串会发生什么？

**答案要点**：

- Vue 把字符串当可迭代，逐字符渲染；`"江末,林晚"` 变成 5 个标签（B5）。
- 后端 JSON 字符串字段要先 `JSON.parse`；模板只处理数组。
- `:key` 用稳定 ID，不要用 index/字符。

**追问**：为什么筛选逻辑是对的、显示是错的？→ 筛选用了 `parseJsonField`，模板没用；典型"数据层修了展示层漏了"。

---

## T8. `v-html` 一定 XSS 吗？

**答案要点**：

- 不一定；关键看是否经过可信 sanitizer（项目 DOMPurify）与配置。
- `marked` 产出 HTML → `DOMPurify.sanitize`；`ADD_TAGS/ADD_ATTR` 只放行必要项。
- 剩余风险：链接 `target/rel`、图片隐私、sanitizer 版本/配置被改。
- 验证：注入 `<img onerror>`、`javascript:`、`<script>`，断言被剥离。

**追问**：`DOMPurify` 能防所有 XSS 吗？→ 不能；DOM clobbering、mXSS、配置错误仍可能；要持续更新+测试。

---

## T9. ECharts 在 Vue 中怎么正确销毁？

**答案要点**：

- `onMounted` init；`onBeforeUnmount` `dispose()`；`ResizeObserver.disconnect()`。
- `keep-alive` 用 `onActivated/onDeactivated`；窗口 resize 用 ResizeObserver 更稳。
- 同一 DOM 重复 init 会警告；用 `getInstanceByDom` 判断。
- 项目 `EChart.vue` 已正确 dispose（B13 是误判题）。

**追问**：只 `chart.dispose()` 不 disconnect observer 会怎样？→ observer 仍持有 DOM/回调，可能泄漏/报错。

---

## T10. FastAPI 依赖注入与 Pydantic alias

**答案要点**：

- `Depends` 可复用 DB session/当前用户/服务；`yield` 依赖做清理。
- Pydantic v2 `Field(alias="novelId")` + `populate_by_name=True` 支持驼峰入参。
- Query 参数用函数签名名（`page_size`），不会自动识别 `pageSize`（B1/C15）。
-  response model 可统一输出，但项目多用 `Result` 字典。

**追问**：`alias` 能同时接受驼峰和下划线吗？→ 可以配 `AliasChoices`/validator；但要明确契约，不要长期双轨。

---

## T11. SQLAlchemy Session 生命周期与事务

**答案要点**：

- 每请求一个 session，`try/finally close`；不要跨线程/长期持有。
- `commit` 后对象过期，需 `refresh`；异常 `rollback`。
- 项目 `get_db` 依赖；部分 service 自己 `SessionLocal()`（摘要线程）要确保关闭。
- N+1：列表里逐条 count/查询；用聚合/批量查询。

**追问**：`create_all` 能代替迁移吗？→ 不能；只建缺失表，不改列/索引；项目手工补列就是补丁。

---

## T12. 401 与 403 的区别？项目怎么处理？

**答案要点**：

- 401 未认证/凭证失效；403 已认证但无权限。
- 前端用户端只对 401 清登录；后台把 403 也当失效（B10，误踢）。
- 后端应统一错误码；JWT 过期/被顶号返回 401，权限不足 403。
- 不要用 200+code 混淆传输层与业务层。

**追问**：被顶号应该 401 还是 403？→ 401（当前凭证不再有效），并给明确 message。

---

## T13. 什么是 IDOR？项目里怎么发生？

**答案要点**：

- Insecure Direct Object Reference：用客户端提供的对象 ID 直接访问，未校验归属。
- 项目：`/userConfig?userId=`、角色/时间线/故事节点无鉴权、Java `userId=1L` 默认值。
- 修复：从 token 取 userId；Service 校验资源归属；管理员走独立权限。
- 测试：A token 访问 B 资源，断言 403。

**追问**：把 ID 换成 UUID 能防 IDOR 吗？→ 只能增加枚举难度，不能替代授权校验。

---

## T14. 路径穿越怎么防？

**答案要点**：

- 不信任 `sessionId`/文件名；白名单正则 + `Path.resolve()` + `is_relative_to(base)`。
- `os.path.join(base, "/abs")` 会逃逸；`..` 也会。
- 上传文件名用服务端生成（UUID），不用客户端原名。
- 项目 `/chat/regenerate` 未校验 `session_id`（C4）。

**追问**：只把 `..` 替换掉够吗？→ 不够；编码/符号链接/绝对路径都可能绕过；用解析后包含关系判断。

---

## T15. 文件型存储怎么保证并发安全？

**答案要点**：

- 进程内锁（按 key）+ 跨进程文件锁/分布式锁；锁范围覆盖读-改-写。
- 临时文件 + `os.replace`/`Files.move(ATOMIC_MOVE)` 原子写。
- 链式结构：先写新节点，再原子更新 tail.next；DB 最后更新。
- 读侧处理半截/损坏 JSON（重试/隔离）。
- 项目 Python 无锁，Java 锁只覆盖 append（C5）。

**追问**：`synchronized` 能跨 JVM 吗？→ 不能；多实例要用外部锁。

---

## T16. 缓存与 DB 双写怎么选一致性？

**答案要点**：

- 没有完美方案；明确"至少一次/至多一次"。
- 先 DB 后删缓存（Cache Aside）常见；删除失败要重试/延迟双删。
- 计数类：Redis 增量 + 幂等批次回写；先 commit 再删 Redis 防丢，但可能重复。
- 项目 `flush_views` 先 `take` 后 commit，失败丢增量（C18）。
- 监控对账：缓存 pending vs DB。

**追问**：为什么不能强一致？→ 跨系统事务成本高；多数场景用最终一致 + 对账。

---

## T17. 描述 RAG 全链路与常见失败点

**答案要点**：

- 离线：加载 → 清洗 → 切分 → embedding → 写入 Chroma → 状态文件。
- 在线：query embedding → 向量召回 topK×4 → rerank → 拼 prompt → LLM → 引用。
- 失败点：切分过大/过小、embedding 模型不一致、collection/路径错、rerank 404、score 语义、上下文超长、引用不对齐。
- 项目：三套 Chroma 路径、rerank 端点写错、`score=1-distance` 可能为负。

**追问**：召回和精排的取舍？→ 召回重覆盖（topK 大），精排重准确（cross-encoder），再截断给 LLM。

---

## T18. Chroma 的 distance/score 怎么解释？

**答案要点**：

- cosine space 下 distance 通常 `1 - cosine_similarity`，范围 [0,2]；`score=1-distance` 是相似度，可能为负。
- 不是概率，不能直接当百分比；前端显示要标注"相似度"并 clamp/归一。
- 不同距离度量（l2/ip/cosine）语义不同；collection 创建时要固定。
- 项目 `1.0 - _score` 直接展示，易误导。

**追问**：为什么两条文档 score 0.8 不代表"80% 相关"？→ 只是相对排序信号；没有校准。

---

## T19. Java `SseEmitter` 的生命周期怎么管？

**答案要点**：

- 设置超时；注册 `onTimeout/onCompletion/onError`；客户端断开要取消上游。
- 不要每请求 `newSingleThreadExecutor`；用共享池/WebFlux。
- `latch.await()` 要超时；`send` 失败不要吞。
- 项目 Java 版每请求建池、无超时、`sendEvent` 吞异常（C12）。

**追问**：`SseEmitter.complete()` 后还能 send 吗？→ 不能；会抛异常；要幂等清理。

---

## T20. Spring Security `permitAll` 的风险

**答案要点**：

- `permitAll` 跳过认证，Controller 可能拿到 null userId；若再有默认值 `1L`，匿名可冒充用户 1（C10）。
- 只放行真正公开路径；业务路径 `authenticated()`；方法级 `@PreAuthorize` 做权限。
- JWT filter 要处理无效 token；不要让异常变成 500。
- 测试：无 token/过期/越权三类。

**追问**：`permitAll` 后 CSRF 还需要吗？→ 看是否用 cookie/session；JWT header 模式下 CSRF 风险低，但不要盲目关。

# 二、场景排障（6 题，每题 5 分）

## S1. 页面空白，Console 无报错，怎么查？

**答案要点**：

1. Network：请求有没有发？状态码/响应体 `code`？
2. 业务 500 被 resolve？调用方没检查（B2）。
3. DOM：是空态、v-if 隐藏、还是 CSS 覆盖？
4. 数据：接口返回空数组 vs 字段名不匹配（records/data）。
5. 路由/权限：是否被守卫重定向。
6. 证据：HAR + 截图 + 后端日志。

**评分**：分层 3；证据 1；能提到业务码 1。

---

## S2. 流式回答重复/丢字，怎么定位？

**答案要点**：

- 丢字：SSE 尾缓冲未 flush、`\r\n`、多行 data、`done` 提前 break。
- 重复：前端双写（流式 + batchSave）、重连重放、后端重复落盘。
- 对账：前端最后文本 vs 链文件 content；Network 原始帧。
- 项目：前端已取消 batchSave；两份解析器不一致（B15）。
- 修复：抽公共解析器 + 尾缓冲 + 去重 + 单写入点。

**评分**：丢字 2；重复 2；对账 1。

---

## S3. 上传提示成功，刷新后没有，怎么查？

**答案要点**：

- Network 有没有上传请求？HAR。
- 后端有没有收到/落库？日志 + DB/Chroma count。
- 成功提示是否硬编码/`setTimeout`（E2）。
- 前端是否上传后没刷新/刷新错页。
- 权限/租户：是否传到别人库。
- 结论：假交互 P0 / 刷新 bug P1 / 后端缺失 P1。

**评分**：请求 1.5；落库 1.5；假交互 1；结论 1。

---

## S4. 切到 Java 后端后历史消息全空，怎么查？

**答案要点**：

- DB `head_path` 是 `__file__:...`，Java 不识别（C14）。
- 链 `next` 全路径 vs 纯文件名（C11）。
- Java 是否读对 storage 根目录/工作目录。
- 日志：`readFile` 是否报不存在；`getSessionMessages` 返回空。
- 修复：StorageService 解析 + next 归一 + 跨后端契约测试。

**评分**：`__file__` 2；next 2；验证 1。

---

## S5. 评测集分数突然下降 10 分，怎么排查？

**答案要点**：

- 先分层：哪些任务/标签下降；是否集中在某后端/浏览器/模型版本。
- 环境：依赖/lockfile、DB seed、RAG 索引、端口。
- 评测器：prompt/judge 版本、隐藏测试变更、随机种子。
- Agent：模型/提示词/工具版本。
- 数据：评测集泄漏/污染/难度变化。
- 方法：固定一组 golden 重跑；A/B 对比；查 trace。

**评分**：分层 2；环境 1；评测器 1；数据 1。

---

## S6. Agent 说修好了，但 CI 失败，怎么处理？

**答案要点**：

- 复跑 CI，保存日志；区分环境差异/真实失败。
- 看 diff：是否改测试/硬编码/只改 UI。
- 本地隐藏测试 vs CI 差异（Node/Python 版本、依赖）。
- 结论：Agent 过度声称（overclaim）；按 E7 反馈，要求证据。
- 评分：结果 0；过程分按定位/验证给部分。

**评分**：复现 2；diff 审查 2；结论 1。

# 三、行为与协作（4 题，每题 5 分）

## B1. 你判 P0，研发说"这是设计"，怎么办？

**答案要点**：

- 先对齐定义：P0 的标准是数据/安全/造假，不是"我觉得"。
- 拿证据：请求/日志/DB/用户影响；给最小复现。
- 区分"设计取舍"与"实现 bug"；如果是设计，要求文档写明并评估风险。
- 找第三方（产品/安全）仲裁；记录结论。
- 不情绪化，不对人。

**评分**：标准 2；证据 2；协作 1。

---

## B2. 时间紧、任务多，怎么排优先级？

**答案要点**：

- 按 P0（安全/数据/造假）→ P1（核心功能）→ P2（体验）。
- 先做"能阻塞评测结论"的：环境、真实链路、关键 badcase。
- 并行：自动化/脚本化重复工作；模板化报告。
- 明确交付边界：哪些没做、为什么、下次何时。
- 不偷偷降级/省略证据。

**评分**：优先级 2；并行 1；边界 1；诚信 1。

---

## B3. 标注规范有歧义，你和同事标得不一样，怎么办？

**答案要点**：

- 先查手册/历史案例；没有就提出来。
- 双评抽样，算一致率/κ；找分歧点。
- 更新规范 + 加正反例；统一培训。
- 无法达成 → 第三人仲裁，记录理由。
- 不擅自改别人的标；保留版本。

**评分**：查规范 1；双评 1；更新 1；仲裁 1；版本 1。

---

## B4. 你发现同事/Agent 在评测中造假，怎么办？

**答案要点**：

- 先固定证据（HAR/日志/diff/截图），不传播未证实结论。
- 按流程上报；区分"失误"与"故意"。
- 保护数据/回滚影响；通知相关方。
- 复盘：流程漏洞（测试只读、隐藏用例、双人复核）。
- 不公开羞辱；对事不对人。

**评分**：证据 2；上报 1；止损 1；复盘 1。
