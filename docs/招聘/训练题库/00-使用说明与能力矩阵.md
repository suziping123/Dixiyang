## 一、这套题为什么以 Dixiyang 为载体

这个项目恰好覆盖目标岗位的完整工作流：

| 岗位真实动作 | 项目中的对应物 |
|---|---|
| 搭前端工程环境、跑模型产物 | Vue3 + Vite + Node 20/22；`npm run dev/build/type-check` |
| 读源码判断实现真假 | `useChatStream`、`RagKnowledgeView`、`http` 拦截器、demo 适配器 |
| 识别假交互/占位/硬编码 | `setTimeout` 假加载、TODO 死按钮、前端 push 固定数据 |
| 复现并记录 badcase | `pageSize` 分页漂移、业务 500 静默、SSE 取消、rerank 404 |
| 写 Rubric / Prompt | 知识库上传任务、流式对话任务、安全修复任务 |
| 看 Agent 轨迹 | LangChain 工具循环、SSE 事件、工具调用与引用回推 |
| Git/终端/依赖/日志 | 双后端、端口、uv/uvicorn、Maven、Docker、MySQL/Redis |
| 用数据说话 | Redis JMeter P95 4.9-5.0×、吞吐 +71%、命中 99.99% |

> **重要基线（以当前 README/脚本为准）**：
> Python 主后端 **8084**；独立 RAG 服务 **8085**；ChromaDB **8000**；Vue dev **5173**；Java 备用后端与 Python 同占 **8084**，二选一。

## 四、难度分级

| 级别 | 定义 | 典型题 |
|---|---|---|
| **L1 基础** | 有明确标准答案，考记忆/基本操作/单点识别 | 端口命令、`isComposing`、`logout` 清空、403 误登出 |
| **L2 常见** | 需要读 2-3 个文件、理解一个机制 | 分页漂移、业务码 500、乐观更新、Java `next` 指针 |
| **L3 复杂** | 跨前后端/跨进程、并发时序、需要设计 | 会话切换竞态、SSE 生命周期、链文件并发、Rubric 设计 |
| **L4 易误判** | 看起来是 bug 其实是设计/安全；或看起来安全其实有洞 | demo mock、`v-html` 已消毒、ECharts 已释放、`log.error("{}",e)` 不是编译错 |

> 训练要求：L1/L2 必须全对；L3 至少能写出"根因 + 影响 + 修复 + 验证"四段；L4 必须能说清"为什么不是/为什么是"。

## 五、30 天训练计划（每天 2 小时）

| 周 | 重点 | 任务 |
|---|---|---|
| 第 1 周 | 工程基础 + 前端 L1/L2 | A 全卷 + B1-B9；每天用 DevTools 抓 1 个请求 |
| 第 2 周 | 前端 L3 + 后端 L1/L2 | B10-B18 + C1-C9；补写 3 个最小复现 |
| 第 3 周 | 后端 L3 + RAG + 评测设计 | C10-C18 + D1-D4；写 2 份 Rubric |
| 第 4 周 | 标注 + Agent + 模拟考 | E1-E8 + 07 专项 + 09 模拟卷；复盘错题 |

**每天固定动作**：

1. 10 min 看昨天的错题（只写"错在哪、正确结论、证据"）。
2. 60 min 做新题（先不看答案，限时）。
3. 30 min 对照答案，补 `file:line` 或命令。
4. 20 min 把当天最有价值的一条写成 badcase JSON。

## 七、每道题的固定答题模板

### 7.1 代码审查题（B/C 卷）

```text
【现象】用户看到什么/接口返回什么
【定位】file:line + 关键代码
【根因】机制层面的原因（不是现象复述）
【影响】谁会受影响、什么条件下触发、数据/安全后果
【修复】最小改动 + 长期治理（两层）
【验证】造什么数据、看什么证据、断言什么
```

### 7.2 Rubric 设计题（D 卷）

```text
【任务目标】一句话
【可观测行为】用户/接口/数据层能看到的
【判定证据】截图/HAR/日志/DB 查询
【分级】0/1/2 或 pass/fail
【一票否决】造假/越权/数据损坏
【通过线】总分 + 核心维度下限
```

### 7.3 badcase 题（E 卷）

```text
【标题】一句话现象
【前置】账号/数据/构建模式
【步骤】最小复现 3-6 步
【期望 vs 实际】
【证据】截图 + HAR/日志/计数
【根因】机制
【级别】P0/P1/P2 + 理由
【标签】假交互/硬编码/...
【修复建议】
```

## 八、评分口径（训练自评）

| 等级 | 标准 |
|---|---|
| 优秀（85+） | 能给出跨层根因、最小修复、可执行回归测试；能指出题目陷阱/误判 |
| 合格（70-84） | 定位准确、修复方向对、验证步骤可执行；偶有边界遗漏 |
| 待补（60-69） | 能看出表面问题，但根因/影响/验证缺一项 |
| 不合格（<60） | 只描述现象、只改 UI、无证据、把 mock 当 bug |

**自评必须写证据**：没有 `file:line`、命令、截图/HAR、日志的答案，按 0 分。

## 九、必须记住的 12 个"项目事实"

1. 前端 Node 要求 `^20.19.0 || >=22.12.0`；`build = run-p type-check build-only`，`dist` 存在 ≠ 类型检查通过。
2. Python 主后端 8084；RAG 服务 8085；Chroma 8000；Vue 5173；Java 备用同 8084。
3. 测试账号 `admin123 / 123456`；禁伪造 token；10 分钟 3 次密码登录触发验证码；单点登录顶号。
4. `http.ts` 对业务码 500 **resolve**，调用方必须自查 `code`；只有 401 会统一跳登录。
5. FastAPI 查询参数是 `page_size`，Java 是 `pageSize`；`pageSize` 在 Python 被忽略，回落默认 10/20。
6. Python 聊天链路在流结束/取消时落盘；前端明确不再 `batchSave`。Java 版 `/chat/stream` 不落盘。
7. 链文件 `next` 存**纯文件名**，读取要基于当前文件父目录解析；Java 版当完整路径用。
8. RAG 精排真实端点是 `/api/rag/rerank`；`knowledge_search_tool` 调 `/api/rerank`，**静默 404 回退**。
9. `score = 1 - cosine_distance` 是相似度，不是概率/百分比；可能为负。
10. `VITE_DEMO=1` 是**有意的展示 mock**；真实交付里出现 mock 才是 P0。
11. `v-html` 经过 `DOMPurify.sanitize`；ECharts 卸载会 `dispose()`；这两个是"看起来危险但其实正确"的误判题。
12. 文档会漂移：以 `README`、`start_backend.sh`、`vite.config.ts`、运行时日志为准。

## 十、使用建议

- **不要背答案**：每题先自己在仓库里找证据，再对照。
- **不要只读代码**：B/C 卷至少挑 6 题真实启动/抓包/改代码验证。
- **不要跳过误判题**：真实评测工作中，"把设计当 bug"比"漏 bug"更常见。
- **每 10 题做一次复盘**：把错题归因为"不知道/没看全/不会验证/表达不清"四类。
- **模拟考必须计时**：评测岗的核心不是"会不会"，而是"在限定时间内稳定产出可复核结论"。
