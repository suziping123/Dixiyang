# Coding Agent / WebDev 评测岗 · 学习资料总目录与知识地图

> **版本**：v1.0 ｜ **适用岗位**：AI 大模型训练-代码类（Coding Agent / WebDev 评测与轨迹标注）
> **项目载体**：Dixiyang（Vue3 + FastAPI + MySQL/Redis + 可选 Chroma RAG；Java Spring Boot 为同端口备用）
> **资料定位**：这是题库的**知识母集**，不是题目答案汇编，也不是考点清单。
> **代码基准**：当前仓库 commit；项目事实以 `README.md`、启动脚本、`vite.config.ts`、`docker-compose.yml` 和运行结果为准。

## 一、这份资料要解决什么问题

评测岗每天面对的不是"背八股"，而是下面这些判断：

1. 这个页面/接口是**真的实现了**，还是模型用 mock、硬编码、假 loading 糊出来的？
2. Agent 说"修好了"，是**最终输出对了**、**代码改对了**、**工具用对了**，还是只是在当前环境偶然通过？
3. 一条 badcase 的根因在**需求理解、代码定位、修改、验证、环境、工具**哪一层？
4. 怎样把"感觉不对"变成**别人能复现、能双评、能回归**的 Rubric 与证据链？
5. 怎样设计任务、Harness、隐藏测试和反作弊，让分数**可复现、公平、不可刷**？
6. 面对研发/标注同事/面试官，怎样用**原理 + 项目证据 + 取舍**讲清楚？

因此资料按"知识体系 → 工程实践 → 评测方法 → 项目事实 → 表达与反例"组织，而不是按题库顺序组织。

## 二、范围边界

### 2.1 必须覆盖

- 软件工程、编程语言、Web、HTTP/API、数据库、测试调试、安全与性能的基础。
- Vue3/TypeScript/Vite/Pinia/Router/Axios 的前端体系。
- Python/FastAPI/Pydantic/SQLAlchemy/MySQL/Redis 的后端体系。
- LLM、Embedding、向量检索、Reranker、RAG 全链路与评估。
- Coding Agent 的任务执行、工具调用、轨迹、Harness、Rubric、badcase、指标、沙箱。
- Dixiyang 项目的真实架构、数据流、关键实现、已知问题与文档差异。
- 面试表达、概念对照、常见错误、进阶追问。

### 2.2 只做岗位相关延伸

以下内容**不作为主线**，只在被问到时按"扩展知识"解释，避免无限扩张：

- 大模型预训练/微调数学、分布式训练、GPU 算子优化；
- Kubernetes、服务网格、分布式共识、复杂微服务治理；
- 浏览器内核/渲染引擎源码、图形学；
- Spring 全家桶的深水区（本项目 Java 是备用实现，重点在跨后端契约与安全对比）；
- 与评测无关的 UI 视觉设计理论。

### 2.3 三种"不能混"

| 不能混 | 说明 |
|---|---|
| 岗位通用知识 ≠ 项目事实 | 通用原理可以迁移；项目结论必须有代码/文档/运行依据 |
| 项目已实现 ≠ 文档宣称 | 文档会漂移，以运行时与脚本为准；冲突要记录 |
| 题库覆盖 ≠ 知识边界 | 题库没考的知识，仍可能是岗位合理追问 |

每个重要知识点尽量按以下顺序展开：

```text
是什么 → 为什么 → 怎么工作 → 代码/流程 → 项目哪里用
```
