一、项目背景与目标

DIXIYANG 是面向小说/网文创作者的 AI 写作辅助系统。创作者在长篇写作中普遍面临角色设定遗忘、前后情节矛盾、资料检索困难等问题，本项目目标是把创作者的本地资料（电子书、设定文档）构建为私有知识库，让 AI 在对话创作时能实时检索引用，并提供角色、时间线、故事节点等结构化管理能力。项目由我独立完成需求分析、系统设计、前后端开发、RAG 检索流水线搭建与 Linux 环境部署上线，线上地址 https://XXX.com。

二、总体架构

系统分为四层：

1. 前端层：Vue 3 + TypeScript + Vite + Pinia + Element Plus + Tailwind CSS，负责小说管理、角色/时间线维护、AI 对话、知识库可视化。
2. 业务后端层：Python FastAPI（端口 8084），SQLAlchemy ORM + MySQL 8.0，JWT 认证、邮箱验证码登录、11 个路由模块、15 个服务模块。
3. RAG 服务层：独立 Embedding/Reranker 服务（端口 8085，bge-m3 + bge-reranker）+ ChromaDB 向量库（端口 8000，11 万+ 向量），通过 HTTP 供业务后端调用。
4. LLM 接入层：LangChain + DeepSeek 模型，支持流式输出、Agent 工具调用、五种对话模式。

三、核心功能与实现要点

1. AI 流式对话（SSE）
   后端 POST /api/chat/stream 返回 text/event-stream，async generator 逐 token 推送；状态机实时切分 thinking 与 content 标签，前端 fetch + ReadableStream 解析渲染；AbortController 实现前后端联动取消，出错时兜底落盘已生成内容。

2. Agent 工具循环
   流式收集 tool_calls，最多 5 轮循环：知识检索 knowledge_search（RAG）、角色/时间线/故事节点查询、save_to_knowledge 知识写回；检索结果以 rag_references 结构化事件推给前端展示引用来源。

3. RAG 检索流水线
   离线：rag-shared 库完成文档加载（md/pdf/epub/csv 等）→ 切分（chunk 600、overlap 120）→ bge-m3 批量向量化 → 写入 ChromaDB；mtime + hash 增量更新避免重复计算；YAML 配置支持 GPU（RTX4060 FP16）与 CPU 双硬件环境。
   在线：召回 topK×4 → bge-reranker 精排取 topK，当前库内 111,509 条向量、26 本语料、7 万余 chunks。
   检索失败时自动降级：Embedding 服务不可用则本地回退，聊天不中断。

4. 冷热分离存储（数据库 + 链式 JSON）
   MySQL 只存 __file__ 路径引用，长对话以 next 指针链式 JSON 文件存储；截断采用 tmp + rename 原子写保证一致性；历史超过 12 条时后台线程生成滚动摘要控制 prompt 长度；封面/背景 MD5 秒传去重。

5. 编辑纠错学习
   用户编辑 AI 回答后，链内替换消息并记录 edits.json，异步 LLM 提取 keyPoint/errorType 修正要点，后续对话自动注入 system prompt，使模型逐步适应用户偏好；重新生成接口截断链文件后重新流式生成。

6. 周边功能
   小说/角色/时间线/故事节点 CRUD（角色支持 AI 从对话提取设定）、AI 自动生成会话标题、五种对话模式（创作/讨论/分析/头脑风暴/提问）、三套主题与个性化背景字体配置、知识库可视化页（统计/浏览/语义搜索）。

四、数据库设计

MySQL 8.0（utf8mb4），核心表：app_user、novel、novel_character、timeline（parent_id 自关联层级）、story_node（vector_id 关联向量库）、novel_relation、chat_session（仅存会话索引与链头路径）、email_verification_code 等。实战运用多表外键连接、分组统计、唯一约束防重（uk_user_title、uk_novel_name），并完成日常备份恢复操作。

五、部署与运维

1. Linux 环境独立完成全链路部署：MySQL（Docker 容器）→ FastAPI 8084 → ChromaDB 8000 + Embedding 8085 → Nginx/前端静态资源，最终以 HTTPS 暴露。
2. 编写跨发行版启动脚本 start_rag.sh：自动检测 CPU/线程绑定（OMP/MKL/TORCH 环境变量）、服务健康检查重试、HNSW 参数在线调优（ef_search=25），兼容 Ubuntu/CentOS/Arch。
3. 网络排障：ping/curl/telnet 验证连通性，端口与防火墙策略核对，模拟客户现场环境完成调试；向量库与模型约 10G 通过 U 盘/scp 跨机迁移（附《Linux迁移指南》）。
4. 文档标准化交付：《系统总览》《RAG架构规划》《RAG离线构建流程》《功能完成状态》《Linux迁移指南》《Docker安装指南》等，可复用于实验室开放基金项目交付流程。
