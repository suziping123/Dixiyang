DIXIYANG 小说写作 RAG 辅助系统 —— 项目介绍（求职用）

一、项目概述

DIXIYANG 是一套独立设计、开发并完成部署的全栈 AI 小说写作辅助系统，面向网文/小说创作者，提供角色与时间线管理、AI 流式对话创作、基于 RAG 的知识库检索等能力。项目由我一人完成从架构设计、前后端开发、RAG 检索流水线搭建到 Linux 环境落地部署的全流程，线上部署于 https://XXX.com。

二、技术架构

前端：Vue 3（TypeScript + Vite + Pinia + Element Plus + Tailwind CSS），SSE 流式渲染、Markdown 安全渲染、主题与个性化配置。
后端：Python FastAPI + SQLAlchemy + LangChain（对接 DeepSeek），提供 JWT 认证、邮箱验证码登录、小说/角色/时间线 CRUD、SSE 流式聊天接口。
RAG：ChromaDB 向量库 + bge-m3 Embedding（1024 维）+ bge-reranker 精排，本地部署 11 万+ 条向量，支撑"召回 ×4 → 精排取 TopK"的两级检索。
数据库：MySQL 8.0，多表外键关联（用户/小说/角色/时间线/会话索引），日常增删改查、多表连接与分组统计、备份恢复均独立完成。
部署：Linux（Ubuntu/CentOS/Arch 兼容的 Shell 部署脚本），Docker 部署 MySQL 等中间件，健康检查、端口探测与网络连通性调试（ping/curl/telnet）保障服务可用。

三、核心设计亮点

1. 冷热分离存储：数据库只存 __file__ 路径引用，长对话/大文本以 next 指针链式 JSON 落盘文件系统，写入采用 tmp + rename 原子操作，会话截断、消息编辑不损坏数据；配合历史滚动摘要控制 prompt 长度。
2. 真流式 SSE：后端 async generator 逐 token 推送，状态机实时切分 thinking/content 标签，前端 fetch + ReadableStream 解析并支持 AbortController 前后端联动取消。
3. Agent 工具循环：LLM 流式收集 tool_calls（最多 5 轮），工具涵盖角色/时间线查询、RAG 知识检索、知识写回，检索引用结构化回推前端展示。
4. RAG 离线流水线：文档切分（chunk 600/overlap 120）→ 批量向量化 → mtime+hash 增量更新，支持 GPU/CPU 双硬件配置 YAML，跨机器向量库迁移。
5. 编辑纠错学习：用户修改 AI 回答后，异步用 LLM 提取修正要点（keyPoint/errorType）存入 edits.json，后续对话自动注入，实现模型对用户偏好的持续适应。
