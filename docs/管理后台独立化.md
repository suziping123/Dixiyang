# 管理后台独立化（admin.html 独立入口 + 三层隔离）

> 版本：v2.1 ｜ 日期：2026-10-18（v2.0 / v2.1 为同日第二、三轮）｜ 分支：`feat/admin-console`
>
> 一句话：管理后台从用户端 SPA 中**彻底分出**为独立入口 `admin.html`（独立登录页/独立壳/独立会话），并顺手修复 FloatingNav"几乎全局呼出"与双实例挂载问题。
>
> **v2.0（同日第二轮）**：按用户反馈"风格没对齐我的风格 / 文档没看 / 不像真实后台（缺浏览器式多页签）"——控制台**接入用户端设计系统**（背景图层 + 玻璃 + token）、新增**浏览器式多页签**、落地**内容管理**（广场帖子下架/恢复/硬删除/评论治理 + 灵感墙便签管理）。详见 §12。
>
> **v2.1（同日第三轮）**：按用户反馈"admin 的移动端适配不太行，可以复用 floatingnav，注册的东西要变一下"——**FloatingNav 组件注册项化**（不传=用户端默认 5 主页，向后兼容），控制台窄屏/触屏**侧栏撤下、导航交给悬浮球**（注册=控制台页面表 + 返回用户端 + 退出登录）。详见 §13。

## 1. 需求（用户原话与拆解）

> "我觉得应该让管理员和普通用户不能共用东西……管理员用户不能用普通用户的方式访问后台，现在就是集成在里面的，而且现在的 FloatingNav 也很不对，因为几乎是全局呼出了。"

拆解为两条硬需求 + 一条授权：

1. **后台与用户端隔离**：管理后台不得作为普通用户 SPA 内的一个路由（改本地存储即入）；管理入口不得出现在用户端任何导航中。
2. **FloatingNav 收敛**：导航只应在少数主页出现（现状：App.vue 全局挂 + 8 个视图各自又挂 = 双实例 + 登录/落地/404 等页面也在呼出）。
3. 授权：在做好版本管理的前提下，允许顺便治理存量混乱（重复挂载、死代码等）。

事实核对（改造前）：

- 后台是 SPA 内 `/admin` 懒加载路由，守卫仅查 `localStorage.role`（前端判断）；
- `require_admin` 接受**任何**带 `role=admin` 的用户端 token——"共用"的口子就在这；
- 单点登录为**按账号单会话**（`session_id` 覆盖式），若后台登录复用同机制，**登后台会顶掉用户端**；
- `hideNav` 路由 meta 是死代码（无人读取）；FloatingNav 双实例（App.vue + 8 视图）。

## 2. 决策清单（访谈定案）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 隔离程度 | 彻底独立：后台不嵌在用户端 SPA |
| 2 | 技术形态 | Vite 多入口：`index.html`（用户端）+ `admin.html`（控制台），独立登录页/独立壳/独立样式 |
| 3 | 后端归属 | 后台 API 继续在 Python 侧（DixyangFast，8084） |
| 4 | 账号与会话 | 同一 `app_user` 表（`role=admin` 放行）+ 独立端点 `/api/admin/auth/login` + **独立会话空间** `admin_session_id`：登后台不顶用户端，双端可同时在线（"管理员也可以登录正常账号"） |
| 5 | FloatingNav 范围 | 仅 5 个主页显示（首页/灵感墙/RAG 助手/广场/设置），其余页面一律隐藏 |
| 6 | 功能范围 | 一期：3 个既有功能（仪表盘/用户列表/改角色）原样搬迁 + 隔离；内容管理做二期规划（见 §10）。**v2.0 已把内容管理落地（见 §12）** |
| 7 | 版本管理 | 改造前先提交 WIP 基线快照（本地不 push）→ 开分支 `feat/admin-console` 小步提交 |
| 8 | 演示站 | 保留后台展示：`admin.html` 进演示构建，走演示登录页链接进入（"独立入口"本身成为展示点） |

## 3. 方案总览（三层隔离）

```
                        同一域名
   ┌─────────────────────┴───────────────────────┐
   │ /index.html（用户端 SPA）      /admin.html（管理控制台）│
   │  token / session_id           admin_token / admin_session_id │
   │  守卫: 用户端会话             守卫: 后台会话               │
   └─────────────┬───────────────────────┬───────┘
                 │ /api/**（用户端 token） │ /api/admin/**（后台 token）
                 ▼                        ▼
        ┌──────────────── FastAPI :8084 ────────────────┐
        │ get_current_user_id            require_admin     │
        │ 拒绝 scope=admin               仅收 scope=admin  │
        │ 比对 session_id                比对 admin_session_id │
        │                                + role 实时校验     │
        └──────────────────────────────────────────────────┘
```

- **入口隔离**：`admin.html` 独立 HTML/独立入口 TS/独立路由/独立样式，用户端产物中删除 `/admin` 路由与全部后台代码。
- **会话隔离**：两套 JWT（`scope: user|admin`）+ 两个会话字段（`session_id` / `admin_session_id`），互不顶号、互不通兑。
- **接口隔离**：`require_admin` 只认后台 scope 的 token——**用户端 token 打不开后台接口**（核心断言）。

## 4. 后端改动（DixyangFast）

| 文件 | 改动 |
|------|------|
| `models/user.py` | `AppUser` 新增 `admin_session_id: str | None`（后台独立会话号） |
| `utils/jwt.py` | `create_access_token(user_id, session_id, scope="user")` 新增 `scope` claim |
| `utils/auth_deps.py` | ① `get_current_user_id` / `get_optional_user_id` 显式拒绝 `scope=admin`（403 / None）；② **`require_admin` 重写**：仅 `scope=admin` + `sid==admin_session_id` + `role==admin`（实时）三项全过才放行 |
| `services/auth_service.py` | 新增 `admin_login()`：账号密码 → `role=admin` 才放行 → 复用登录风控计数 → 写 `admin_session_id` → 签发 `scope=admin` token |
| `routers/admin.py` | 拆出无鉴权 `auth_router`（`POST /api/admin/auth/login`）；管理端点保留 router 级 `require_admin` |
| `main.py` | 启动 ALTER 补列 `admin_session_id`；挂载 `admin.auth_router` |

**风控**：后台登录复用用户端"10 分钟 3 次密码登录"计数（避免后台成为绕过口子）；被锁时提示"请先在用户端用邮箱验证码登录一次后再试"（一期后台不做发码通道，见 §9）。

```

src/admin/
├── main.ts                     # 独立壳：设计系统（main.css）+ EP dark css-vars + console.css；背景层初始化；演示模式挂载前 await 装 mock
├── App.vue                     # 仅 RouterView

├── utils/theme.ts              # 背景层：同源 localStorage → #theme-bg（固定照片层 + 叠色，只读不回写）
├── utils/session.ts            # admin_token / admin_username / admin_nickname 独立键

├── api/admin.ts                # login / stats / users / role / posts / sticky（仅后台 token 可用）
└── views/

    ├── LayoutView.vue          # 侧栏（玻璃）+ 多页签条 + keep-alive 内容区（≤768 侧栏转顶栏）
```

要点：

- **hash 路由**：GitHub Pages 无 rewrite，`admin.html#/users` 深链零配置；`noindex` 防收录。
- **独立 token 键**（`admin_token`）：同浏览器双端并存；401/403 只清后台会话，绝不联动用户端。
- **设计系统对齐（v2.0）**：直接引入用户端 `main.css`（token/玻璃/全局弹窗/表单规范），`console.css` 只承载控制台壳与页面共用件；背景层复用 `#theme-bg` 机制。视觉与多页签细节见 §12。
- **移动端导航（v2.1）**：触屏 / ≤1024px 时侧栏撤下，导航交给**复用组件** `components/FloatingNav.vue`（经 `items` prop 注册控制台页面表），内容区右侧避让悬浮球。见 §13。

## 9. 已知问题与限制

1. **风控共用**：后台登录计入用户端同一风控窗口；被锁后需到用户端做一次邮箱验证码登录解锁（后台一期无发码通道）——提示文案已引导。
2. **`/admin` 短链行为分环境**：Vite dev/preview 会把无扩展名路径回退到 `admin.html`（等价改道控制台登录页）；GitHub Pages 无该回退（落用户端 404）。**规范入口一律 `admin.html`**。
3. ~~控制台样式独立~~（**v2.0 已解决**：控制台直接引入用户端 `main.css` 设计系统，`console.css` 只承载控制台壳与页面共用件，见 §12.2）。
4. **控制台为 hash 路由**：URL 形态 `admin.html#/users`（静态托管零配置的代价）。
5. **自我降权即刻踢出**：管理员在用户管理里取消自己的 admin 会当场被踢出控制台（role 实时校验）。
6. 用户端 `localStorage.role` 仍在写入但已无读取点（见 §6 注）。
7. 控制台移动端为顶栏化基础适配（列表可横滚），未做逐项精修。

## 10. 二期规划：内容管理（~~本期只规划不实施~~ → **v2.0 已实施 M2.1/M2.2，见 §12**）

> **v2.0 进度**：M2.1（帖子列表 + 下架/恢复 + **硬删除** + **评论治理**）与 M2.2（灵感墙便签管理）已落地，接口契约见 [DixyangFast/docs/管理后台内容管理接口.md](../../DixyangFast/docs/管理后台内容管理接口.md) 与本文 §12.4；**M2.3 审计日志、M2.4 举报处理仍未做**。以下为原始规划（保留供演进参考）。

**目标**：广场（idea）与灵感墙（sticky）的日常运营能力，复用控制台壳与 `require_admin` 体系。

**页面与功能**

- 内容管理-广场：列表（分区筛选/关键词搜索/状态筛选）、详情预览、**下架/恢复**、删除（连带评论/图片/附件回收）。
- 内容管理-灵感墙：便签列表（用户/关键词）、删除。
- （P2）举报处理：举报列表 → 跳转帖子详情 → 与上架/下架打通。

**API 草案**（全部走既有 `require_admin`，即后台 token）

| 端点 | 说明 |
|------|------|
| `GET /api/admin/posts?page&pageSize&category&status&keyword` | 帖子列表（含作者/状态/计数/时间） |
| `PUT /api/admin/posts/{id}/status` `{status: published\|removed}` | 平台下架/恢复 |
| `DELETE /api/admin/posts/{id}` | 硬删除（复用 `idea_service` 既有删除与附件清理逻辑） |
| `GET /api/admin/sticky?page&pageSize&userId&keyword` | 便签列表 |
| `DELETE /api/admin/sticky/{id}` | 便签删除 |
| （P2）`GET/PUT /api/admin/reports...` | 举报处理 |

**数据与规则**

- `idea_post.status` 已存在 `published/removed` 状态机（作者侧已有 remove/restore）；管理侧建议新增标记 `admin_removed=1`，**平台下架后作者不可自行恢复**（这正是 `Redis与管理后台策划.md` §风险 提示过的"绕过"风险）。
- 审计日志（P1）：新表 `admin_audit_log(operator_id, action, target_type, target_id, detail, create_time)`，所有管理写操作落一条。
- 权限模型暂不细分：凡 `role=admin` 全权；后续如需"审核员/超管"再拆。

**里程碑**：~~M2.1 帖子列表+下架/恢复~~（✅ v2.0，含硬删除/评论）→ ~~M2.2 灵感墙~~（✅ v2.0）→ M2.3 审计日志 → M2.4 举报处理。

**风险**：与作者侧状态机耦合（需明确"平台操作 > 作者操作"的优先级）；删除的物理回收与 `sticky_cleanup` 类定时任务协同；移动端不做精修（沿用策划结论）。

## 12. v2.0：风格对齐 + 多页签 + 内容管理（实施记录）

### 12.1 需求（用户三条反馈）

1. **"风格也没有对齐我的风格，文档也没有看"**——控制台此前是自造的一套 `--c-*` 皮肤，没用上项目的设计规范文档（卡片毛玻璃、弹窗面板、Home 去 AI 味、设置页 token 等）。
2. **"也不是实际的"**——经确认：功能太单薄不像真系统，**内容管理要现在落地**（常规运营档）。
3. **"虽然是后台，但是没有模仿浏览器的分页打开之类的东西"**——缺多页签交互。

### 12.2 风格对齐（按设计规范落地）

- **设计系统直引**：console 入口导入用户端 `main.css`（token / 玻璃 / 全局弹窗 / 原生表格头 cyan 等全站规范），`console.css` 只留控制台壳与页面共用件；`admin.html` 挂 `dark theme-dark`。原自造 `--c-*` 变量已全部删除。
- **背景层**：复用 `#theme-bg` 机制（固定照片层 + 叠色 0.15）——读同源 localStorage（`dixiyang_theme_config`）：用户端选过的背景优先；自定义背景用 URL 直接可用；无缓存则内置默认「大草原-天空-宁静」。只读不回写、不请求服务端（与后台会话隔离原则一致）。
- **玻璃语言**：侧栏（`--surface-panel` + blur16）、页签条、卡片（`--glass-bg-strong` + blur16 + `--radius-md`）；大数字锚点（仪表盘统计卡 `clamp(1.9rem,3.4vw,2.6rem)` + 计数动画）、发丝线横规 + 计数徽章、语义化 hover。
- **去 AI 味**：登录页原紫蓝径向光删除；色板收敛蓝/青/中性（对齐 Home 轮设计闸门）。
- **动效（克制）**：卡片错峰入场（`rise-in`，`prefers-reduced-motion` 直接落终态）、页签内容切换 fade/slide、统计数字短计数动画。
- 表格头青色（`th { color: var(--accent-cyan) }`）来自 main.css 全局规范——控制台自动继承，属"对齐"而非新增。

### 12.3 浏览器式多页签（约定 + 实现）

**交互约定**：

- 点侧栏菜单 → 顶部开签 / 激活已开签；**仪表盘为固定首签，不可关闭**（无关闭钮）。
- 关闭当前签 → 激活**右邻**（无则左邻）；关闭非当前签仅移除。
- **刷新保持**：页签列表持久化于 sessionStorage（会话级）。
- **每签独立状态**：keep-alive 缓存筛选/翻页/输入等页面状态；**关签即丢缓存**；刷新后页面内状态重置（keep-alive 为内存缓存，与浏览器刷新行为一致）。
- 签条为浏览器式（圆顶角、激活签与内容相连、图标 + 标题 + 关闭钮），玻璃材质。

**实现**：`menu.ts`（菜单/页签单一注册表）+ `composables/useAdminTabs.ts`（模块级状态 + 持久化 + 邻签逻辑 + `keepNames` 清单）+ `LayoutView` 的 `<keep-alive :include="keepNames">`。

### 12.4 内容管理（常规运营档）

| 页面 | 能力 |
|------|------|
| 广场管理 | 筛选（状态/分区/关键词）+ 表格（作者/分区/状态标签/互动计数/时间）+ 详情弹窗（正文/配图/附件/评论列表）+ 下架/恢复 + 硬删除 |
| 灵感墙管理 | 筛选（用户名/昵称关键词、完成态）+ 列表（内容/用户/颜色/完成态/池中）+ 查看弹窗 + 删除 |

**规则与级联**：

- **平台下架**：`idea_post.admin_removed=1`（启动 ALTER 补列）；**作者侧 restore 被拦截**（"该内容已被平台下架"）；管理端恢复清 0；作者侧下架/恢复原行为不受影响。
- **硬删除级联**：评论/点赞/收藏/标签行 + 正文/附件文件（`delete_community_json`）+ 本地上传配图文件（仅 `/api/uploads/idea-images/`，防路径穿越）；二次确认（含标题、明示不可恢复）。
- **评论治理**：删除回写 `comment_count` 与热度；灵感墙删除连带正文文件（`delete_json`）。

**接口契约**：[DixyangFast/docs/管理后台内容管理接口.md](../../DixyangFast/docs/管理后台内容管理接口.md)（8 个端点，全部走 `require_admin`）。

## 13. v2.1：管理后台移动端 —— 复用 FloatingNav（悬浮球导航）

### 13.1 需求（用户反馈）

> "admin 的移动端适配不太行，我觉得可以单独试着复用 floatingnav，但是上面注册的东西要变一下"

### 13.2 问题（改造前取证 @375px）

侧栏在 ≤768px 折成顶栏后**塞不下**：4 个菜单项 + 返回用户端 + 退出登录挤在一行，截图中顶栏仅"仪表盘"一项可见（其余被挤出视口），换页导航实际瘫痪。

### 13.3 方案：FloatingNav 注册项化（组件复用，用户端零改动）

- **组件侧**（`src/components/FloatingNav.vue` + 新增 `FloatingNav.types.ts`）：新增 `items` prop（`FloatingNavItem`：`icon/label/path/href/danger/key`）
  - **不传 = 用户端默认 5 主页**（App.vue 未改动，注册项行为不变）
  - 扩展点：`href` 整页跳转（跨入口）、`danger` 危险样式、`key` + `select` 事件（无 path/href 条目交父级）、`navLabel` 无障碍标签
- **控制台侧**：
  - `admin/menu.ts` 新增 `ADMIN_NAV_ITEMS`：4 个控制台页面（`path`）+ **返回用户端**（`href: './index.html'` 整页跳转）+ **退出登录**（`danger` 危险色，无 path → 经 `select` 由 LayoutView 清会话回 `#/login`）
  - `LayoutView` 挂载判定与组件 FAB 模式**同一条件**（触屏 或 ≤1024px）——桌面宽屏不挂载（侧栏即导航，避免出现第二套左缘热区导航）
  - `console.css`：FAB 条件下侧栏 `display: none`（顶栏方案废弃）；内容区 `padding-right: 64px` 避让悬浮球（14 边距 + 46 球 + 4 缓冲，与用户端页面同规，内容右界恒在球左缘之内）；页签关闭钮触控命中区放大到约 32px（视觉不变）
