# 单点登录（顶号踢出）与登录风控

> 最后更新: 2026-10-06
> 范围: `dixiyang-engine`（Java）+ `DixyangFast`（Python）+ `dixiyang-vue/Dixiyang-vue3`
> 关联: [登录鉴权与表单回车](./登录鉴权与表单回车.md)

## 一、需求

1. **单点登录（顶号）**：同一账号多处登录时，**后登录的设备顶掉先登录的**；被踢设备下一次请求收到 401，前端自动清登录态并跳登录页、提示「账号已在其他设备登录」。
2. **登录风控**：短时间内多次被踢（即短时间频繁登录顶号）后，**密码登录必须改用邮箱验证码登录**；验证码登录成功后解除限制。

## 二、方案

### 核心机制：`app_user.session_id` 单会话号

```
登录成功 → 生成 UUID session_id → 覆盖写入 app_user.session_id（旧会话即失效）
         → 将 session_id 作为 sid claim 塞进 JWT 签发

每次请求 → 过滤器/依赖解出 sid → 与 app_user.session_id 比对
         → 不相等 → 401 踢出；旧 token 无 sid → 兼容放行至自然过期（不强制重登）
```

- 会话号存 **MySQL**（持久，后端重启不丢、所有设备不重登）。
- 双后端共用同一张表，切换 8084 后端不影响会话连续性（除 JWT 密钥差异，见「已知问题 1」）。
- 被踢时机为**下次请求时**（非即时推送），空闲设备在下一次任意请求时登出。

### 风控规则

| 项 | 值 |
|----|----|
| 统计窗口 | 10 分钟（`login_window_start` + `login_count`） |
| 触发阈值 | 窗口内成功登录 **3 次**（即已顶掉 2 台设备） |
| 触发后果 | `require_code=1`，之后密码登录返回「登录过于频繁，请使用邮箱验证码登录」 |
| 解除方式 | 邮箱验证码登录成功 → `require_code=0` 并重置窗口 |
| 风控时在线设备 | 不受影响，继续在线 |
| 时间基准 | 两端统一写 **UTC 字面值**（保证共表可比） |

前端收到该错误后**自动把登录方式切换到验证码模式**（`loginMode='code'`）。

## 六、已知问题

0. **旧 token 兼容（2026-10-06 回归修复）**：初版规则"无 sid 的 token 一律 401"在后端 `reload=True` 热加载后，把所有 SSO 上线前签发的登录态打回，表现为聊天页报「抱歉，请求失败，请稍后再试」（401 文案经 `friendlyError` 映射不到 → fallback）。已改为**兼容放行**：`sid` 存在才比对顶号；旧 token 有效至自然过期，用户无需强制重登。顶号功能不受影响（带 sid 的新 token 照常比对）。双后端（`auth_deps.py` / `JwtAuthenticationFilter.java`）同规则。
1. **双后端 JWT 密钥不一致**：Java 硬编码于 `JwtUtils.java:13`，Python 取 `.env` 的 `SECRET_KEY/JWT_SECRET_KEY`。切换 8084 后端时整批 token 签名校验失败 → 全员重登（现象类似被踢，实为既有问题，本次未动 `.env`，待另行统一）。
2. **空闲设备非即时下线**：被踢端需下一次请求才跳登录页（本次选定的时机策略）。
3. **Java 注册不校验验证码**：前端注册已传 `code`，Java `register` 未消费（既有行为，未在本次范围）；Python 端带码注册逻辑不受影响。
4. **业务路径大量 `permitAll`**：未携带 `Authorization` 的请求仍放行；前端全量带 token，故顶号有效，但严格鉴权属后续安全加固项。
5. **SMTP 未配置时**：`send-code` 返回「验证码邮件发送失败」或限流提示，不会假成功（Java 先发信后落库，失败不留记录）。

## 七、手动验收清单

1. 两个浏览器（含无痕）登录同一账号 → 后者登录 → 前者任意操作 → 自动跳登录页并提示「账号已在其他设备登录」。
2. 连续第 3 次登录后再用密码登录 → 自动切到验证码登录模式并提示。
3. 收到验证码邮件（需 `.env` 配置 `SMTP_USERNAME/SMTP_PASSWORD`）→ 验证码登录成功、恢复正常密码登录。
4. 被踢期间正在聊天的 SSE 流：下一次发送消息时跳登录页。
