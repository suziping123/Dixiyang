# 开发环境与测试账号（本地验证统一入口）

> 版本：v1.0 ｜ 日期：2026-10-16 ｜ 用途：给"需要登录才能验证"的前端/接口工作**统一一个真实登录入口**，禁止再伪造 token

## 1. 测试账号

| 项 | 值 |
|---|---|
| 用户名 | `admin123` |
| 密码 | `123456` |
| userId | `4`（本地 dev 库，`role=user`） |
| 用途 | 本地/CDP 探针、UI 验收、接口回归——**一律走真实登录拿真 token** |

> 该账号是**测试专用**：单点登录会"后登录顶掉先登录"，所以**探针只能用它**，不要拿自己或他人正在使用的账号做自动化登录。

## 2. 取 token（真实登录，任选其一）

**A. 命令行**（前端 5173 通过 Vite 代理到主后端 8084；也可直连 `localhost:8084`）：

```bash
curl -s -X POST http://localhost:5173/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin123","password":"123456"}'
# → {"code":200,"msg":"操作成功","data":{"token":"eyJ...","user":{...}}}
```

**B. 探针脚本内**（CDP：页面同源 fetch，最省事）：

```js
// 在 localhost:5173 页面上下文里执行，走真实登录接口（不伪造）
const res = await fetch('/api/auth/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ username: 'admin123', password: '123456' }),
})
const { data } = await res.json()   // data.token / data.user
```

## 3. 写入本地登录态（复刻 `UserStore.setLoginInfo`）

前端只认这 6 个键（`dixiyang-vue/Dixiyang-vue3/src/stores/UserStore.ts`）：

```js
localStorage.setItem('token', data.token)
localStorage.setItem('username', data.user.username)
localStorage.setItem('userId', String(data.user.userId))
localStorage.setItem('nickname', data.user.nickname)
localStorage.setItem('email', data.user.email || '')
localStorage.setItem('role', data.user.role || 'user')
// 然后 location.reload() → 守卫放行/static、loadFromServer() 拉真实背景与自定义背景
```

## 4. 注意事项（踩过的坑）

1. **禁止伪造 token**（如 `demo.<base64>.demo` 之类"本地可校验"的假 JWT）：守卫能骗过，但任何一次接口 401 都会触发拦截器 `clearAuth()` → 掉登录页，并且**探针会把假数据写进 localStorage 缓存**（`dixiyang_custom_bgs` / `dixiyang_theme_config`），污染后续肉眼验收。真伪 token 的正确姿势见 §2。
2. **登录风控**：10 分钟内同账号**第 3 次**密码登录起会被要求邮箱验证码 → 探针尽量**一次登录、多次复用 token**（token 有效期 7 天）。
3. **探针要拦接口时**用 `Fetch` 域拦截 `*://localhost:5173/api/*`（**别用 `*/api/*`**，会误伤 `/src/api/*.ts` 模块请求导致白屏），并且**先确认不需要真实数据**再拦。
4. 本地 `#app` 空白且无报错时，先查 Chrome 缓存：`Network.setCacheDisabled(true)`（本机出现过 `ERR_CACHE_READ_FAILURE`，新建标签必开）。
