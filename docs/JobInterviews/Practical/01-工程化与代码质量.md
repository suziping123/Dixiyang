## 1. TypeScript 严格类型治理：把 9 个存量错误清零

- **知识点**：`vue-tsc` 全量类型检查、`noUncheckedIndexedAccess`（索引取值返回 `T | undefined`）、`DeepReadonly` 与 mutable prop 的协变问题。
- **项目实战**：`npm run build`（= type-check + build-only）因 9 个存量错误长期失败，团队被迫用 `build-only` 绕过——**绕过路径常态化后，新增的真类型错误也会被静默放行到产物**。一轮治理清零：`??` 收敛索引 undefined、去掉多余 `Record` 标注改字面量推断、数组 prop 放宽 `readonly T[]`（组件内只读）。
- **面试话术**："我判断类型错误不能只看'能不能跑'——绕过一旦成为习惯，闸门就形同虚设。所以先把存量 9 错清零恢复 `npm run build` 绿灯，再谈新增代码的约束。"
- **真实改法示例**（9 错中的 3 类）：

```ts
// ① noUncheckedIndexedAccess：索引取值是 T | undefined → 用 ?? 收敛
const prev = { ...notes.value[idx]! }        // 改前：直接解包（TS 报 undefined）

// ② 多余的宽泛标注反而制造错误：storyMappings 标了 Record<...> 后赋值处处报错
//    改后：删标注，让 TS 从字面量推断（推断类型更精确）

// ③ DeepReadonly 与 mutable prop 冲突：组件只读数组 prop → 放宽为 readonly T[]
props: { msgs: readonly string[] }           // 改前：string[] 传 DeepReadonly 报错
```
来源：[前端type-check存量错误清零](../../前端type-check存量错误清零.md)

**分析**：三个例子的共性是——**不是把类型断言 `as any` 糊过去，而是找到"类型声明比实际使用更宽/更窄"的根因**：该收敛的收敛（`??`）、该删的删（多余标注）、该放宽的放宽（只读协变）。面试官追问"为什么不 suppress"时，这就是答案。

## 2. 构建双闸与脚本分层

- **知识点**：`build = run-p type-check + build-only` 的设计——开发期可用 `build-only` 快速出包，CI/交付必须走全闸。

```json
// package.json（真实）
"build":      "run-p type-check \"build-only {@}\" --",  // 全闸：类型 + 产物
"build-only": "vite build",                               // 仅产物（应急/迭代）
"type-check": "vue-tsc --build"
```
**分析**：关键在**两条命令都保留**——只留 `build-only` 等于拆掉闸门，只留 `build` 又会在存量未清时逼人绕过。分层让"快"和"严"各有其位，CI 永远走严的那条。

- **面试话术**："速度和安全分开两条命令，而不是把检查删掉。"

## 3. Lint 体系与基线对比法

- **知识点**：ESLint + oxlint 双 linter、Prettier；**存量项目改代码时用"与 HEAD 基线对比零引入"**，而不是要求全局 0 错（避免被历史问题卡死）。
- **面试话术**："存量项目的 lint 治理要区分'我引入的'和'历史遗留的'，用 diff 基线保证每轮改动零引入，遗留的单独排期。"

## 4. 文档驱动开发（每任务一文档）

- **知识点**：项目铁律——**无文档视为任务未完成**；每篇 MD 固定记录「需求 / 方案 / 改动文件 / 已知问题 / 验证方式」五段；`docs/README.md` 索引同步登记。
- **面试话术**："文档不是写完补，而是和代码同 PR 交付；'已知问题'一节强制诚实记录未解决项，交接成本大幅下降。"
- 🔗 [docs/README.md](../../README.md)（60+ 篇文档的索引与版本变更记录就是证据）

## 5. Git Hooks 管理特殊文件

- **知识点**：`git config core.hooksPath .githooks` —— 用 pre-merge/pre-pull hook 保护**被移出版本库但本地必须保留**的文件（本项目技能库），防止 `git pull` 直接删掉协作方本地文件；配恢复脚本兜底。
- **面试话术**："版本库边界之外的本地资产，要靠 hooks 做防删保护 + 一键恢复双保险，这是协作工程里很容易被忽略的一环。"
