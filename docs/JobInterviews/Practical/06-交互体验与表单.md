## 1. 表单回车提交的全局约定

- **知识点**：统一 `@keyup.enter="enterSubmit(提交函数, $event)"`（必须传 `$event`）——**非末框跳下一框、末框才提交**；textarea/按钮/下拉不触发；危险删除弹窗 `autofocus:false` **禁止回车确认**（防误删）。
- **面试话术**："回车提交看似一行代码，关键是边界：密码框回车登录、删除确认回车会误删——这类行为要全局统一约定而不是每个表单各写各的。"
- **关键代码**（`src/utils/enterSubmit.ts` 真实节选——核心是"数焦点"）：

```ts
export function enterSubmit(fn: () => unknown, e?: Event) {
  const run = (ev: Event) => {
    const el = ev.target as HTMLElement | null;
    // ① textarea/select/按钮/下拉：不接管（回车交给自身语义）
    if (el.tagName === 'TEXTAREA' || el.tagName === 'SELECT') return;
    if (el.closest('button, a, .el-select, [role="button"], [role="combobox"]')) return;

    const root = el.closest('form, .el-form, .creating-card, ...');
    if (root) {
      const fields = collectFields(root);        // ② 收集容器内可见可聚焦控件
      const idx = fields.indexOf(current);
      if (idx > -1 && idx < fields.length - 1) { // ③ 还有下一框 → 跳焦点并全选
        ev.preventDefault?.();
        fields[idx + 1]?.focus();
        (fields[idx + 1] as HTMLInputElement).select?.();   // 便于直接覆盖
        return;
      }
    }
    return fn();                                  // ④ 已是末框 → 才提交
  };
  if (e) return run(e);   // 模板传 $event：立即执行
  return run;             // 未传：返回处理器（兼容两种用法）
}
```

**分析**：
- **为什么必须传 `$event`**——不传就返回包装函数，模板上等于"每次渲染新建处理器"且拿不到事件，回车永远直接提交（这是项目里踩过的真实 bug）；
- `collectFields` 的过滤条件（`:not([disabled])`、排除 button/combobox、`display:none` 过滤）才是"可见可聚焦"的完整定义——**跳转逻辑的正确性全在这份过滤里**；
- `select()` 全选是体验细节：跳到下一框直接打字即可覆盖默认值。

## 3. 拖拽与点击的事件冲突（⭐ 经典手感坑）

三个连环 bug，全部实战修过：
1. **拖拽松手浏览器补发 `click`** → 误触"完成态划掉" → 修：`suppressClick` 标记（拖拽分支置位、click 消费后复位、`setTimeout(0)` 兜底防残留吞掉下次合法点击）；
2. **`moved` 标志不重置** → 拖过一次后每次单击都走"保存位置 + 命中检测"，便签悬在素材池口**单击即误投喂** → 修：`pointerdown` 开头重置；
3. **拖拽命中检测**：便签悬浮在光标下，`elementFromPoint` 永远命中自己 → 先临时 `pointer-events: none` 再取命中点。
- **面试话术**："鼠标事件序列（down/move/up/click）在'自定义拖拽'下会出补发和误判，我的处理是**显式状态机**：moved、suppressClick、dragging 三个信号各管各的。"
- **关键代码**（`src/components/sticky/StickyNote.vue` 真实节选，三个信号协同）：

```ts
let moved = false;          // 信号1：本次 pointer 序列是否真的发生了位移
let suppressClick = false;  // 信号2：拖拽结束，抑制浏览器补发的 click

function onPointerDown(e: PointerEvent) {
  if ((e.target as HTMLElement).closest('button, textarea, input, a')) return; // 按钮不进拖拽
  moved = false;   // ① 每次按下重置：否则拖过一次后单击永远走拖拽分支（误 PUT/误投喂）
  dragging.value = true;
  window.addEventListener('pointerup', onPointerUp, { once: true }); // ② once 防泄漏
}

function onPointerUp() {
  if (!moved) return;            // 没位移 = 普通点击 → 不抑制，让 click 正常工作
  suppressClick = true;          // ③ 位移过 → 补发的 click 一律作废
  setTimeout(() => { suppressClick = false; }, 0); // ④ 兜底：click 落别处被 .stop 吞掉时，标记不能残留
  ...
}

function toggleDone() {
  if (suppressClick) { suppressClick = false; return; }  // ⑤ 消费即复位
  ...
}
```

**分析**（为什么 `setTimeout(0)` 是必需的）：click 事件在当前宏任务内同步派发 → `suppressClick` 会被 ⑤ 消费复位；但若补发的 click 落在带 `.stop` 的按钮上被吞掉，标记就**永远残留**，下一次用户合法点击被误杀。`setTimeout(0)` 排到下一宏任务清零——**任何"一次性标记"都要有失效兜底**，否则竞态下变成偶发吞点击的幽灵 bug。

## 4. 完成态交互：从"点正文划掉"到勾选圆钮

- **知识点**：原交互"点整段文字=完成"隐晦且误伤（想选中复制却勾了完成）→ 改**显性勾选钮**：灰空心圈 → 黑底白勾（由灰变黑）+ `aria-pressed` 无障碍；正文 `cursor: pointer→text` 回归阅读语义；空操作给 `ElMessage` 反馈。
- **面试话术**："交互改版的判断依据是**操作目标的语义**——文字区的语义是阅读和选中，'完成'应该有自己的控件。"
- **关键代码**（`StickyNote.vue` 真实节选）：

```html
<!-- 模板：显性勾选钮；正文不再挂 @click -->
<button class="done-mark" :class="{ on: note.done }"
        :aria-pressed="note.done"                       <!-- 无障碍状态 -->
        :title="note.done ? '标记为未完成' : '标记为完成'"
        @click.stop="toggleDone">                       <!-- .stop：不冒泡触发置顶 -->
  <svg viewBox="0 0 24 24" ...><polyline points="20 6 9 17 4 12"/></svg>
</button>
<div class="content" :class="{ done: note.done }">{{ note.content }}</div>  <!-- 仅阅读 -->
```
```css
/* 由灰变黑：空心灰圈 → 黑底白勾，未完成 hover 浅显勾提示可点 */
.done-mark    { border: 2px solid rgba(58,49,38,.35); background: rgba(255,255,255,.4); border-radius: 50%; }
.done-mark svg{ opacity: 0; transform: scale(.6); }
.done-mark:hover svg { opacity: .35; transform: scale(1); }   /* 反馈：这里能点 */
.done-mark.on { background: #17171c; border-color: #17171c; color: #fff; }
.done-mark.on svg { opacity: 1; transform: scale(1); }
.content { cursor: text; padding-right: 26px; }               /* 文字回归选中语义 + 让位圆钮 */
```

**分析**（改版里容易被追问的三点）：
1. **为什么按钮不引发拖拽**——根元素 `pointerdown` 处理器已有 `closest('button')` 排除，`<button>` 语义天然继承这条防护，不用额外判；
2. **`cursor: text` + `padding-right`** 不能忘——去掉点击后若留着 `cursor:pointer`，用户会以为文字还能点；不留 padding，圆钮盖住首行末尾字；
3. **反馈链完整**：未完成 hover 有浅勾（可发现性）→ 点击变黑底白勾（状态确定性）→ 空便签点击给 `ElMessage`（无效操作有解释）。
