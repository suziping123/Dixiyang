## 1. 断点体系与移动弹窗（贴底抽屉）

- **知识点**：统一断点 `768`（项目另有 1024/480 档）；移动端弹窗不自设宽高，复用全局 `html .el-dialog` 贴底抽屉规则（宽 100%、`margin: auto auto 0`、body 滚动）——**新弹窗自设尺寸会被全局 `!important` 压掉**，直接复用。
- **面试话术**："弹窗移动端形态走全局一条规则，而不是每个弹窗重写一遍 media query——组件多了才明白收口的价值。"

## 2. 浮动导航避让（悬浮球 FAB）——"精算避让"反例

- **知识点**：FAB 悬浮球在右侧，页面应 `padding-right: 64px` 精算避让（14 边距 + 46 球 + 4 缓冲）。**盲目避让 88px** 会把 375 视口内容压到 273px → 双列 grid 放不下退化单列 → 用户观感"完全没适配"。
- **配套坑**：宽屏下 `.nav-wrapper` 100px×全高隐形热区**挡页面点击** → `pointer-events: none` 穿透 + `.nav-trigger` 接管 hover。
- **面试话术**："适配不是'加了 padding 就叫适配'，要拿 375 视口算实际可用宽度，验证布局是否还成立。"
- **关键代码**（`src/views/AdminView.vue` 真实，精算避让正例）：

```css
/* FAB 悬浮球在右侧占 74px（球 46 + 右缘 14 + 缓冲）→ 避让 64px 与内容右界刚好不重叠 */
@media (max-width: 768px) {
  .admin-page { padding: 18px 16px 60px; padding-right: 64px; }
}
```

**分析**（算账式适配，面试现场可直接算给他看）：375 视口 − 左 16 − 避让 64 = **295px 可用**，双列 `minmax(140px,1fr)` → 列宽 140.5px ✓ 成立；若照搬错误的 88px → 可用 271px → 双列放不下退化单列，观感"完全没适配"。**结论：避让值来自球的几何尺寸，不是拍脑袋。**

## 3. 横向溢出防呆（横滑组设计）

- **知识点**：筛选行/chips 组必须**收在块级容器内 `overflow-x: auto`**，滚动下沉到组自身（组 100% 宽不撑文档）；**禁止整行 `flex-shrink: 0` + `nowrap` 长组**——实测把 375 视口撑到 572、整页横向滚动。行内分组：chips 组与排序组各占一行（`flex-wrap: wrap`）。
- **面试话术**："横向滚动的正确姿势是'局部滚动容器'，让长内容在容器内滚，而不是让整页跟着滚——判定标准是 `documentElement.scrollWidth === 视口宽`。"
- **关键代码**（`src/views/IdeaLibraryView.vue` 真实，注释就是第三轮真机的教训原文）：

```css
/* 筛选：chips 组与排序组**各自独占一行、组内横滑**——
   滚动下沉到组自身（组 100% 宽不撑破文档），两组 wrap 换行。
   第三轮真机根因：单行 filter-row 整体横滑会把"最新/热门"排序挤出首屏；
   而整行 flex-shrink:0 长组又会撑破 375 视口（572 实测），两者都不行。 */
.filter-row { flex-wrap: wrap; gap: 8px; overflow: visible; }

.tab-bar { overflow-x: auto; -webkit-overflow-scrolling: touch; scrollbar-width: none; }
.tab-btn { white-space: nowrap; }   /* nowrap 只给单个按钮，不给整行组 */
```

**分析**：横滑设计有三个都试过的**错误答案**，值得在面试里当"排除法"讲：
1. 整行 `flex-shrink:0` + `nowrap` → 长组把 375 视口撑到 572，**整页横向滚动**；
2. 整行单行横滑 → 排序组被挤出首屏；
3. 正解 = **容器分组（wrap 换行）+ 滚动下沉到组内（overflow-x: auto）**——滚动容器 100% 宽，永不撑破文档。

## 4. iOS 聚焦放大坑

- **知识点**：输入字号 <16px 时 iOS Safari 聚焦会放大整页 → 全局给 `.el-dialog .el-input__inner / .el-textarea__inner` ≥16px，新控件自查。
- 🔗 根 [AGENTS.md](../../../AGENTS.md)（移动端适配 · 输入字号）

## 5. 双列/瀑布流在小屏的成立性验证

- **知识点**：CSS columns 瀑布流用 `left` 分两档判定列数（不能用 `top`——按列填充相邻卡 top 必不同）；移动端双列 `minmax(140px, 1fr)` 而非 150px。

## 6. 真机验证方法（⭐ 区分度）

- **标准套路**：CDP `Emulation.setDeviceMetricsOverride {375,812,2,mobile:true}` → 断言 `scrollWidth === 375`（无横溢）→ 断言布局关键值（列数/Tab 全见/弹窗宽）→ **最后必截图肉眼看**（只跑数字断言会漏"单列大卡=没适配"这类观感问题）。
- **面试话术**："我的规矩是数字断言 + 截图复核双保险——断言证明'没坏'，截图证明'好看'。"
