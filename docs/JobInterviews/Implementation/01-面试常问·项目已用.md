## Q1. 开发机 → 生产环境迁移，你怎么做？

**项目真实过程**（[Linux迁移指南](../../../docs/Linux迁移指南.md) 的骨架）：

```bash
# ① 环境基线（可重复执行的清单，而不是"我记得装过"）
apt install -y openjdk-17-jdk python3.11-venv nginx mysql-server redis-server
# ② 代码与依赖（版本锁定）
rsync -av --delete /media/usb/Dixiyang/ /opt/Dixiyang/
cd /opt/Dixiyang/DixyangFast && python -m venv .venv && .venv/bin/pip install -r requirements.txt
# ③ 配置注入（敏感项不随代码走）
cp .env.example .env && vi .env          # 数据库密码/密钥现场填写
# ④ 服务常驻（见运维 02 systemd）+ 反代（nginx）+ 开机自启
# ⑤ 向量库等重资源单独处理（2.3GB 模型不进 git，走离线拷贝/对象存储）
```

**答法（迁移五步法）**：
1. **环境清单化**——每条命令可重复执行（幂等），新人照跑也能成；
2. **代码与配置分离**——`.env` 现场填、绝不带开发机密钥过去（本项目 `.env.example` 占位符制度）；
3. **重资源单独通道**——向量库/模型这类 GB 级资产走离线拷贝，不塞 git；
4. **先并行后切换**——生产先跑起来做验证，前端切 target 一行（[Java 01 Q5](../JavaBackend/01-面试常问·项目已用.md) 的单出口设计）；
5. **回滚预案在切换前写好**，不是出事再想。
**追问**："迁移动没动数据？"——数据迁移单独立项（见 [02 Q2](./02-面试常问·通用高频.md) 的对账方法）。

## Q2. 现场多设备（手机/平板/别的电脑）怎么联调验收？

**项目真实做法**（[局域网访问与launch调试](../../../docs/局域网访问与launch调试.md)）：

```ts
// vite 插件：dev 启动自动建 adb reverse 隧道（5s 超时静默失败）
for (const port of [5173, 8084]) {
  execFile(adb, ['reverse', `tcp:${port}`, `tcp:${port}`], { timeout: 5000 }, (err) => {
    if (err) return;   // 手机未连：不阻塞启动
  });
}
```
```powershell
# 现场验收三步（有明确通过标准）
# 1) 本机通：curl http://127.0.0.1:8084/api/ping → JSON
# 2) 局域网通：手机浏览器 http://<电脑IP>:5173 → 页面渲染
# 3) 隧道通：手机浏览器 http://localhost:5173（走 adb reverse）→ 同上
```

**答法**：
1. **接入矩阵**：同 WiFi（`host: true`）、USB 隧道（AP 隔离时的保底）、网线直连——现场不挑环境；
2. **工具链自动化**：隧道做成 dev 启动自动执行，**现场少一条手工命令就少一个失败点**；失败静默降级（外设缺失不能拖垮服务）；
3. **验收有标准**：每步给出"期望返回什么"，不靠"看起来行"——这是实施与开发的核心区别：**可重复的验收清单**。
**追问**："客户现场没有你的电脑呢？"——交付物=部署脚本 + 探活 URL + 检查清单三件套（见 [02 Q7](./02-面试常问·通用高频.md) 现场体检脚本）。

## Q3. 怎么证明"交付的功能是好的"？（验收自动化）

**项目真实数据**（docs 各节验证记录）：

```text
API 自动化：  PS 脚本 14 项（登录/CRUD/钉住/坐标/投喂/图片/补全/越权/清理）→ 14/14 PASS
点子库三轮：  40/40 → 15/15 → 19/19 → 25/25 PASS（含越权、频控、失败不扣额度）
CDP UI 冒烟： 28/28 PASS（0 控制台错误）+ 375 移动端截图肉眼复核
```

```js
// UI 冒烟可自动化部分（headless Chrome + CDP，真实套路）
const checks = [
  ['未登录跳转', () => location.pathname === '/login'],
  ['卡片渲染',   () => document.querySelectorAll('.idea-card').length > 0],
  ['无横向溢出', () => document.documentElement.scrollWidth <= 375],
  ['控制台零错', () => errors.length === 0],
];
```

**答法（三级验收模型，可直接当方法论讲）**：
1. **接口级**：脚本批量打全端点（含**越权**——用 A 的 token 访问 B 的资源；**频控**——连续触发限流；**失败路径**——失败不扣额度），这是最便宜的回归；
2. **UI 级**：无头浏览器冒烟关键路径 + 控制台零错误断言；
3. **观感级**：**375 截图肉眼复核**——数字断言证明"没坏"，截图证明"好看"，缺一不可（本项目 AGENTS 铁律）；
4. **回归基线**：每轮改动后重跑全量，"X/X PASS"就是给客户/面试官的**质量证据**，比"我测过了"有说服力一个量级。

## Q4. 数据对账：怎么确认迁移/交付的数据是全的？

**项目真实脚本**（`Temp/opencode/check_sticky.py`，本轮排查便签问题时所写）：

```python
# 双向对账：DB → 文件、文件 → DB，缺一个方向都不能下结论
rows = engine.connect().execute(text("SELECT id, user_id, content_path FROM sticky_note"))
missing  = [r.id for r in rows
            if not os.path.exists(os.path.join(STORAGE_DIR, r.content_path.replace("__file__:", "")))]
ids = {r[0] for r in rows}
orphans = [f"{uid}/{f}" for uid in os.listdir(ROOT) for f in os.listdir(f"{ROOT}/{uid}")
           if f.endswith(".json") and int(f[:-5]) not in ids]
print(f"DB行={len(rows)} 文件缺失={len(missing)} 孤儿={len(orphans)}")
# 实跑结论：DB行=2 缺失=0 孤儿=0 → 数据完好 → 报障根因转向别处
```

**答法**：
1. **双向才完整**——只查"DB 有文件无"漏孤儿，只查"文件在不在"解释不了"看着没保存"；
2. **分级判据**：总数对齐 → 抽样字段比对（内容哈希/行数/关键字段 max-min）→ 异常清单导出给业务方确认；
3. **本项目数据双轨**（DB 路径 + 磁盘内容）天然需要这种对账——**存储分层的代价就是必须配对账**（[Python 01 Q4](../PythonBackend/01-面试常问·项目已用.md)）；
4. **迁移场景扩展**：迁移前后各跑一遍同款对账，输出"迁移前 N 条/迁移后 N 条/差异清单"作为验收附件。

## Q5. 交付文档怎么组织？（培训与交接物）

**项目真实结构**（`docs/README.md` 索引 + 60 余篇分册）：

```text
docs/
├── README.md                 # 总索引：按人群导航 + 版本变更记录（v1.5x 每次改动留痕）
├── 系统总览.md                # 架构与模块一页看懂（给决策者）
├── 前后端接口对照分析.md       # 接口契约清单（给联调方）
├── 功能完成状态.md            # 完成度矩阵 + 勘误（诚实标注过期内容）
├── 各专题实施记录.md           # 需求/方案/改动文件/已知问题/验证方式（五段式）
└── Linux迁移指南.md / 局域网访问与launch调试.md   # 操作手册（给运维/现场）
```

**答法**：
1. **分受众三层**：一页总览（决策者）→ 接口/架构契约（协作者）→ 操作手册（执行者）——一份文档服务三种人必然谁都服务不好；
2. **五段式模板**（需求/方案/改动/已知问题/验证）——**"已知问题"一节是诚实度的试金石**，交接方最怕"全绿"文档；
3. **变更留痕**：版本号 + 日期 + 变更记录，出问题能回答"这行为什么时候、因为什么变成这样"；
4. **文档即培训**——现场培训讲完，手册必须能让人**独立完成操作**，否则培训白做（[02 Q5](./02-面试常问·通用高频.md) 培训清单）。

## Q6. 实施中的"历史包袱"怎么处理？（存量数据/存量环境）

**项目真实案例**（三件同款模式）：

```python
# ① 旧表缺列（存量库 vs 新模型）→ 启动自愈 inspect + ALTER（幂等）
# ② 旧数据内联 JSON（存量内容 vs 新文件化）→ load_json 兼容两种格式平滑过渡
# ③ 旧 token 无 sid（存量凭证 vs 新顶号机制）→ 无 sid 放行至自然过期，不一刀切作废
```

**答法（存量兼容三原则，实施岗高频考点）**：
1. **双读**——新代码同时认新旧两种格式（`load_json` 判 `__file__:` 前缀）；
2. **渐进写**——新数据一律新格式，旧数据不动或批量脚本后台刷；
3. **凭证/连接不一刀切**——作废存量凭证必须给过渡期（否则上线当天全体用户被踢）；
4. **收口时机**——确认旧格式零读取后再删兼容分支（每个兼容分支都要能回答"何时删除"）。
**追问**："能直接改表吗？"——停机窗口内可以，**在线变更**就要 pt-osc/gh-ost（大表 DDL 锁表风险）——知道边界就是加分。
