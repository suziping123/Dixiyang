## 1. 概述与范围

### 1.1 一句话

「点子库」= **私有点子草稿 + 公开创意社区（帖子）**，帖子按**五个分区**组织，可附**只读结构化快照**（对话/角色/设定/时间线，从你现有数据导出），支持点赞/评论/收藏/标签/热门排序，角色附件可**一键导入**到自己的小说。

### 1.2 MVP 范围（第一期做）

| 能力 | 说明 |
|------|------|
| 五分区 | 点子灵感 / 角色 / 设定 / 时间线 / 技术分享（`category` 字段） |
| 私有草稿 | 标题、正文、标签、分区；增删改查、关键词搜索 |
| 发布 | 草稿 → 独立公开帖子（发布前**附件预览**强制确认） |
| 结构化附件 | 从现有数据导出只读快照：对话链 / 角色卡 / 设定集 / 时间线视图（`idea_attachment` 表） |
| 一键导入 | **角色附件**可导入到我指定的小说（复制角色行 + extra 文件，`vector_id` 置空） |
| 广场 | 分区 Tab + 排序（热门/最新/最多点赞）+ 标签筛选 + 关键词搜索 + 分页 |
| 互动 | 点赞（toggle）、平铺评论、收藏（灵感夹）、浏览计数 |
| 我的 | 我的帖子（编辑/下架）、我的收藏、我的点赞记录 |

### 1.3 非目标（第一期明确不做）

- 内容审核/敏感词过滤（先依赖登录态约束）
- 关注、私信、@、楼中楼回复、通知系统
- ~~帖子配图/封面（预留 `idea_attachment.type='cover'` 扩展位，一期不做）~~ **v1.2 移入一期**：独立表 `idea_post_image`（不占 attachment 扩展位、免 ALTER），每帖 ≤9 张、首张为封面，上传走 `/api/upload/idea-image`
- **Chroma 相似推荐**（二期，见 §8 路线图）
- 设定/时间线附件的**导入**（一期只读展示；角色导入是一期唯一导入能力）
- ES/向量搜索（LIKE + 标签关联表足够）
- Java 侧（dixiyang-engine）同步实现——**仅 Python FastAPI 单栈**

### 1.4 技术栈与依赖

- 后端：**Python FastAPI**（用户/会话/对话链/文件存储同栈）
- DB：MySQL（SQLAlchemy 模型，`Base.metadata.create_all` 自动建新表；`app_user` 走 `ALTER TABLE`）
- 缓存：**Redis**（计数、热门 ZSET、频控）
- 前端：Vue3 + Element Plus（沿用现栈）
- ⚠️ **实施前置**：
  1. `requirements.txt` 增加 `redis` 并 `pip install redis`（当前 venv 未装 redis-py）
  2. 探测 `REDIS_URL`（config.py 默认 `redis://localhost:6379/0`）可用性
  3. Redis 不可用降级策略见 §4.5

## 2. 产品方案

### 2.1 五分区模型

| category | 名称 | 默认附件类型 | 数据来源（现有表） |
|----------|------|--------------|--------------------|
| `idea` | 点子灵感 | `chat_snapshot` 可选 | 对话链 `storage/chat/...` |
| `character` | 角色 | `character_card` | `novel_character` 行 + `extra` 文件 |
| `setting` | 设定 | `setting_bundle` | `story_node` 选集（含 tags/character_names） |
| `timeline` | 时间线 | `timeline_view` | `timeline` 树 + `story_node` 节点 |
| `tech` | 技术分享 | 无（纯文字） | — |

- 帖子创建时**必须选分区**，附件类型须与分区匹配（服务端校验）
- 分区筛选 = 广场顶部 Tab（`category` 参数），与排序/搜索/标签正交叠加

### 2.2 双空间与发布流

```
我的点子库（私有）                       广场（公开）
┌─────────────────┐   发布(附件预览)   ┌─────────────────┐
│ 草稿 draft      │ ───────────────▶ │ 帖子 post       │
│ 分区/标题/正文/  │   一对一、独立     │ 分区/标题/正文   │
│ 标签/数据源引用  │  （发布即删草稿）  │ +结构化附件快照   │
│ 可关联AI对话/角色│                   │ +点赞/评论/收藏  │
└─────────────────┘                   └─────────────────┘
```

- **发布 = 生成独立帖子并删除草稿**（发布后要改去「我的帖子」改帖子）
- **关联数据源可选**（按分区）：`idea` 区选会话；`character` 区选角色（可多选）；`setting` 区选 story_node 集合；`timeline` 区选时间线
- **预览强制**：发布对话框展示附件快照全文，`previewed=true` 才允许提交

### 2.3 结构化附件（只读快照）

发布时把数据源**复制**为快照文件（不是引用），原数据删除/编辑不影响已发布帖子：

| attach_type | 导出内容 | 文件 |
|-------------|----------|------|
| `chat_snapshot` | 对话链全量 `{sourceSessionId, messages[]}` | `community/{uid}/{pid}/attach_chat.json` |
| `character_card` | 角色行字段 + `extra` JSON 展开 `{characterId, name, gender, age, appearance, background, personality, extra}` | `community/{uid}/{pid}/attach_character.json` |
| `setting_bundle` | story_node 选集 `[{title, content, eventDate, eventType, importance, tags, characterNames}]` | `community/{uid}/{pid}/attach_setting.json` |
| `timeline_view` | 时间线树 + 节点 `[{name, description, children[], nodes[{title, content, eventDate, tags}]}]` | `community/{uid}/{pid}/attach_timeline.json` |

- 快照仅发布时生成，发布后**不可更换**（要换重新发布）——避免"先过审再塞内容"漏洞
- 只读：其他用户仅可查看；无任何写入口
- 大小控制：对话 >200 轮截断并预览标注；角色/设定/时间线一期无条数上限（选集本身用户可控）

### 2.4 一键导入（角色附件）

- 帖子详情（角色附件）→ `📥 导入到我的小说` → 选择目标 novel → 服务端复制：
  1. `novel_character` 新行（`novel_id` 换目标、`vector_id` **置空**、`create_time` 取当前）
  2. `extra` 文件复制到 `storage/character/{新characterId}.json`
  3. 返回 `{characterId, name}`，前端跳角色管理页提示成功
- 幂等提示：同名角色导入前二次确认；**不导入**向量（目标小说 RAG 重建时自然纳入）
- 仅 `character_card` 类型附件可导入；`setting`/`timeline` 导入列二期（§8）

### 2.5 页面与入口

**新路由** `/ideas` → `IdeaLibraryView.vue`

```
/ideas
├── Tab 0 广场（默认）
│   ├── 分区条：[全部] [点子灵感] [角色] [设定] [时间线] [技术分享]
│   ├── 工具条：搜索框 | 排序[热门/最新/最多点赞] | 标签横向筛选(可多选)
│   ├── 帖子卡片流（分页）：分区角标/标题/摘要/作者(笔名+头像)/标签/
│   │     时间/❤N 💬N ⭐N / 附件类型角标（💬对话 / 🎭角色 / 📖设定 / 🕐时间线）
│   └── 点卡片 → 详情弹窗
├── Tab 1 我的点子（私有草稿）
│   ├── [新建点子] → 发布向导 DraftEditorDialog：
│   │     ① 选分区 → ② 标题/正文/标签 → ③ 选数据源（按分区，可跳过）→ ④ 预览发布
│   └── 草稿卡片：[编辑][发布][删除]
├── Tab 2 我的（子页签：我的帖子 / 收藏 / 点赞过）
│   └── 我的帖子：[编辑][下架][查看数据]
└── 右下悬浮 [✏️ 写点子]（任意 Tab 可见）
```

**帖子详情（弹窗）**：分区角标/标题/作者(笔名头像)/时间/标签/正文/附件快照卡片（展开）/互动条/评论列表；角色附件额外显示 `📥 导入到我的小说`

**入口**：首页导航卡片 + FloatingNav 加 `/ideas`；（P3 可选）RAG 助手会话头部「分享到点子库」→ `/ideas?share=<sessionId>&category=idea`

### 2.6 交互细节约定

- 所有写操作需登录；未登录点入口 → 跳 `/login`
- 点赞/收藏 toggle，前端乐观更新 + 失败回滚
- 浏览数：详情打开 +1（同用户同帖子 10 分钟 Redis SETNX 去重）
- 评论删除仅作者本人；下架 = `status=removed`（广场不可见、他人 404、作者可见可上架）
- 频控（Redis）：发帖 ≥1 条/10 秒、评论 ≥1 条/15 秒、导入 ≥1 次/10 秒
- 作者展示：`nickname ?? username`，有 `pen_name` 优先显示笔名；头像空则首字母占位

## 3. 数据模型（MySQL / SQLAlchemy）

> 位置：`DixyangFast/src/dixiyang/models/idea.py`（新文件）
> **字段惯例对齐全库主流**：主键 `id` Integer 自增、时间用 `create_time`（`server_default=func.now()`，更新表 `onupdate=func.now()`）、长度与 `chat_session`/`novel` 对齐；共库共表风格，避免双栈混乱。
> 长文本（帖子正文、草稿正文、附件快照）存文件，DB 只存路径/摘要/计数。

### 3.1 `idea_post` 帖子表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int PK | 自增 |
| user_id | int, index | 作者 |
| category | varchar(20), index | `idea`/`character`/`setting`/`timeline`/`tech` |
| title | varchar(200) | 标题（列表展示，DB 直存） |
| summary | varchar(300) | 正文截断摘要（列表/搜索用） |
| body_path | varchar(500) | `__file__:community/{uid}/{pid}.json`（{title, content, tags}） |
| status | varchar(16) default `published` | `published` / `removed` |
| view_count / like_count / comment_count / collect_count | int default 0 | 冗余计数（Redis 定时回写） |
| hot_score | bigint default 0 | 热门分（与 Redis ZSET 同步） |
| create_time / update_time | datetime | |

**索引**：
- `idx_post_browse (status, category, create_time)` — 广场分区+时间列表
- `idx_post_hot (status, hot_score)` — 热门排序
- `idx_post_user (user_id, status, create_time)` — 我的帖子
- `idx_post_title (title)` — 关键词 LIKE（一期够用）

### 3.2 `idea_draft` 私有草稿表

| 字段 | 类型 | 说明 |
|------|------|------|
| id / user_id | | PK / 作者 |
| category | varchar(20) | 分区（与 post 同枚举） |
| title | varchar(200) | |
| summary | varchar(300) | |
| body_path | varchar(500) | `__file__:community/{uid}/draft_{did}.json` |
| source_ref | varchar(64) NULL | 数据源引用（sessionId / characterId / novelId+nodeIds / timelineId；**仅存引用，发布时才复制**） |
| create_time / update_time | | |

> 草稿阶段只存引用不复制快照——用户可能继续聊/改数据，发布时刻才是想要的版本。

### 3.3 `idea_attachment` 附件表（替代 v1.0 单 `snapshot_path`）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int PK | |
| post_id | int, index | 所属帖子 |
| type | varchar(20) | `chat_snapshot`/`character_card`/`setting_bundle`/`timeline_view`（预留 `cover`） |
| attach_path | varchar(500) | `__file__:community/{uid}/{pid}/attach_{type}.json` |
| attach_meta | JSON | 角标展示元数据：轮数/角色名/节点数/时间线名等（列表不回源文件） |
| source_ref | varchar(64) | 数据源引用（审计/排障） |
| create_time | datetime | |

- 一期**一帖至多一条**附件（服务层约束），表结构天然支持多附件（`cover` 等二期直接加行）
- 草稿不建附件行，发布时才生成

### 3.4 `idea_post_tag` 标签关联表（替代 v1.0 逗号串）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int PK | |
| post_id | int, index | |
| tag | varchar(50), index | 单标签（规范化：去空格、限长 50、每帖 ≤5 个） |

- 筛选：`JOIN` 精确匹配（比逗号串 LIKE 更稳，支持 `GET /tags` 聚合计数）
- `GET /tags`：`SELECT tag, COUNT(*) FROM idea_post_tag JOIN idea_post(status=published) GROUP BY tag ORDER BY 2 DESC`

### 3.5 互动表

```sql
idea_like     (id, user_id, post_id, create_time, UNIQUE(user_id, post_id))
idea_collect  (id, user_id, post_id, create_time, UNIQUE(user_id, post_id))
idea_comment  (id, post_id, user_id, content Text, create_time)   -- 短文本入 DB，平铺无楼中楼
```

- 评论 `content`：**`Text`**（v1.0 `varchar(2000)` 修订），服务层限 1000 字

### 3.6 用户表扩展（`app_user` ALTER，零破坏）

```sql
ALTER TABLE app_user
  ADD COLUMN avatar_url varchar(500) NULL COMMENT '头像URL（帖子作者卡片）',
  ADD COLUMN pen_name   varchar(50)  NULL COMMENT '社区笔名（空则回退 nickname??username）';
```

- 两个可空列，Java 侧实体不同步也不受影响；`novel.pen_name` 已有先例
- 头像上传复用现有 `uploads/` + `__file__:` 或直接 HTTP URL（一期用 URL 字段即可，不建上传接口）

### 3.7 文件存储布局（遵守 AGENTS §7）

```
uploads/storage/community/{userId}/
├── draft_{draftId}.json          # 草稿正文 {title, content, tags}
├── {postId}.json                 # 帖子正文 {title, content, tags}
└── {postId}/
    ├── attach_chat.json          # 对话快照
    ├── attach_character.json     # 角色卡快照
    ├── attach_setting.json       # 设定集快照
    └── attach_timeline.json      # 时间线快照
```

删帖子/草稿 → 同步删对应文件（`StorageService` 先删文件后删行）。

## 4. Redis 设计

> 与 v1.0 一致，无修订。

### 4.1 Key 一览

| Key | 类型 | 用途 | 写入时机 |
|-----|------|------|---------|
| `idea:cnt:like:{postId}` | STRING | 点赞数缓存 | like toggle → INCR/DECR |
| `idea:cnt:collect:{postId}` | STRING | 收藏数 | collect toggle |
| `idea:cnt:comment:{postId}` | STRING | 评论数 | 评论增删 |
| `idea:view:{postId}` | STRING | 浏览数（未回写） | 详情浏览 INCR |
| `idea:view:dedup:{postId}:{userId}` | STRING(SETEX 600) | 浏览去重 10 分钟 | 详情浏览 |
| `idea:hot` | ZSET | 热门榜 member=postId score=hot | 事件 ZINCRBY |
| `idea:rate:post:{userId}` / `idea:rate:cmt:{userId}` / `idea:rate:imp:{userId}` | STRING(SETEX) | 发帖/评论/导入频控 | 写接口检查 |
| `idea:cnt:flush:ts` | STRING | 上次计数回写时间 | 定时任务 |

### 4.2 热门分算法

```
hot = 3*like + 2*collect + 2*comment + 1*view   （朴素线性，量大再迭代）
```
- 事件 → `ZINCRBY idea:hot {delta} {postId}`；「热门」列表 → `ZREVRANGE`（配合分区/标签过滤）
- 冷启动/Redis 空 → 回源 `ORDER BY hot_score DESC`
- 回写：每 60s pipeline 批量 `SET idea:cnt:*` ↔ DB 冗余计数与 `hot_score`

### 4.3 定时任务

FastAPI `asyncio` 后台任务（lifespan 启动）：
- **每 60s**：计数回写 DB（§4.2）
- **每 10min**：从 DB `hot_score` 全量重建 `idea:hot` ZSET（防漂移）

### 4.4 读路径

列表/详情计数：Redis 有则读 Redis，无则读 DB 并回填。`liked_by_me`/`collected_by_me` 查 DB 唯一键（量小）。

### 4.5 降级策略

连接 Redis 失败 → `logger.warning`，全部读写**回退 DB**（计数直读、排序用 `hot_score`、频控跳过），不阻断主流程。统一经 `services/idea_cache.py` 封装，业务层不直接摸客户端。

## 5. API 契约（FastAPI）

> Base：`/api`，JWT 必带（复用 `get_current_user_id`），统一 `Result{code,msg,data}`（code!=200 即失败，拦截器会 resolve，**调用方必须检查 `res.code`**）。
> 新文件：`routers/idea.py`（prefix `/idea`），服务 `services/idea_service.py`、`idea_cache.py`、`idea_export.py`（数据源导出/导入）。

### 5.1 草稿

| 方法 | 路径 | 请求 | 响应 data |
|------|------|------|-----------|
| GET | `/idea/drafts?category=&q=&page=&pageSize=` | | `{list:[{id,category,title,summary,tags,sourceRef,updateTime}], total}` |
| POST | `/idea/drafts` | `{category, title, content, tags[], sourceRef?}` | `{id}` |
| PUT | `/idea/drafts/{id}` | 同上可选字段 | null |
| DELETE | `/idea/drafts/{id}` | | null（连删文件） |
| GET | `/idea/drafts/{id}` | | `{category,title,content,tags,sourceRef}` |

### 5.2 发布

```
POST /idea/drafts/{id}/publish
body: { "previewed": true }
resp: { code:200, data:{ postId, attachId? } }
```
- 读草稿 → 写 `{postId}.json` + summary → 按 `category` 校验并生成附件（有 sourceRef 时导出快照，写 `idea_attachment`）→ 写 `idea_post_tag` → **删草稿与草稿文件**
- `previewed != true` → `code!=200 "请先预览附件"`
- category 与附件类型不匹配 → `code!=200 "附件类型与分区不符"`

### 5.3 帖子与附件

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/idea/posts?category=&sort=hot\|new\|like&q=&tags=a,b&page=` | 广场列表；`{list:[{id,category,title,summary,authorName,authorAvatar,tags,view/like/comment/collectCount,attach:{type,...meta}\|null,createTime,likedByMe?}],total}` |
| GET | `/idea/posts/{id}` | 详情（正文 content、附件元信息）；**浏览+1**（去重）；他人已下架 → `code!=200` |
| GET | `/idea/posts/{id}/attachment` | 附件快照全文（按 type 解析 attach_meta 外的完整内容）；无附件 404 语义 |
| POST | `/idea/posts/{id}/import` | **角色导入** body `{novelId}`，频控 10s → `{characterId, name}`（越权/非角色附件拒绝） |
| PUT | `/idea/posts/{id}` | 作者编辑 `{title?, content?, tags?}`（**分区与附件不可改**） |
| DELETE | `/idea/posts/{id}` | 作者下架（软删，附件/评论保留） |
| GET | `/idea/mine/posts?page=` | 我的帖子（含已下架 status） |

### 5.4 互动与评论

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/idea/posts/{id}/like` | toggle → `{liked, likeCount}` |
| POST | `/idea/posts/{id}/collect` | toggle → `{collected, collectCount}` |
| GET | `/idea/mine/collects?page=` | 我的收藏 |
| GET | `/idea/mine/likes?page=` | 我的点赞记录 |
| GET | `/idea/posts/{id}/comments?page=` | 平铺分页 `{list:[{id,authorName,authorAvatar,content,createTime,mine}],total}` |
| POST | `/idea/posts/{id}/comments` | `{content}`（≤1000 字，频控 15s） |
| DELETE | `/idea/comments/{id}` | 作者删自己评论（计数-1） |
| GET | `/idea/tags?top=30` | 标签聚合（关联表 GROUP BY，仅 published） |

### 5.5 错误约定

- 401：未登录/token 失效
- `code!=200 "无权限"` 越权；`"帖子不存在或已下架"`；`"操作过于频繁"`；`"附件类型与分区不符"`
- **测试断言一律 `code==200` / `code!=200`**（不断言具体数值）

## 9. 风险与已知问题

| 风险 | 缓解 |
|------|------|
| Redis 未安装/连不上 | §4.5 降级全 DB；P1 首日探测写入实施日志 |
| 快照复制大对话阻塞发布 | 文件 IO 毫秒级；>200 轮截断并预览标注 |
| 角色导入后源角色被删/改 | 快照已复制，导入是新行，无引用依赖 ✓ |
| 标签关联表写放大（发帖多次 INSERT） | 每帖 ≤5 标签，事务内批量插入 |
| LIKE 搜索性能（>10 万帖） | 一期不处理；预留全文索引位 |
| `app_user` ALTER 与 Java 实体不同步 | 两列可空、Java 不映射不受影响；后续 Java 需要时补实体字段 |
| 双端存储约定被破坏 | 本功能 Java 不实现；读写只走 `StorageService` |
